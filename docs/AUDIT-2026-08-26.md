# Talaria — quality & consistency audit

_2026-08-26 · against `88be534` · ~150k LOC: 214 API routes, 424 Svelte files, `mcp/`, `cli/`, `apps/`, `scripts/`_

Five parallel read-only audits (API consistency · UI primitives · DRY · security · dead code), every
headline claim verified against source. `bun run check` was green at the start (1187 files, 15 rules)
and its census carried one live debt item, which closes under P1-3 below.

**Execution order and delivery decisions live in the PR series `fix/security-p0` → `chore/audit-closeout`
(2026-08-26 remediation plan). Tick an item's box in the PR that closes it — this file is the work
order, not a second archive.** The July audit (`AUDIT-2026-07-30.md`) outlived four of its items;
don't let this one do the same.

---

## Verdict

The conventions are real and mostly enforced: 214/214 routes on one contract, zero missing auth,
SQL/SSRF/secrets/CI discipline that would pass an external review, and an invariant checker that
works. The recurring failure mode across all five dimensions is the same one — **the diverging
duplicate**: a copy made before a helper existed (or a surface superseded and never deleted) that
has since drifted. One structural gap (client mutation fetching) and one real vulnerability sit on
top of that.

## P0 — Security

- [x] **Inline-MIME XSS.** Both bytes routes served the uploader-declared MIME with `inline`
  disposition for any `image/*`/`text/*` — `text/html` and `image/svg+xml` execute same-origin with
  the viewer's session; the public-artifact variant served it unauthenticated. No CSP on the origin.
  Fixed: `serveUpload()` in `ui/src/server/uploads.ts` is now the single inline/download decision
  (raster + PDF inline; everything else `attachment` + `nosniff` + sandbox CSP); both
  `routes/api/uploads.$id.ts` and `artifacts.public.$slug.download.ts` serve through it.
  Tests: `ui/src/server/uploads.test.ts`. **(PR 1)**
- [x] **Credential sealing skipped image turns.** `llm-gateway.ts`/`gateway.ts` sealed only
  `string` content; array-content turns (channel replies with attachments) traveled whole, breaking
  the "CREDENTIALS DO NOT LEAVE THIS PROCESS" guarantee in the exact case the adversarial tier
  measures. Fixed: `sealContent()` in `secret-vault.ts` walks array parts; both chokepoints map
  through it. Tests: `secret-vault.test.ts` (unit + `buildUpstream` image-turn chokepoint). **(PR 1)**
- [x] **`fetchCitedPage` bypassed safe-fetch** (`fitness/probes.ts`) — the one raw `fetch` on a
  model-supplied URL. Now `safeFetch`; a refused URL reads as an inconclusive trial. **(PR 1)**
- [x] **Federation import skipped the slug/department alphabets** — imported strings reached an
  `.env` line (newline → line injection), path joins (`../`), and a RegExp. `SLUG_RE`/`DEPT_RE` moved
  to `agent-defs.ts`; `fleet-federate.ts` validates each entry into `result.errors`. **(PR 1)**
- [x] **Invite email HTML unescaped.** `escapeHtml` promoted from kb.ts's private const to
  `server/html.ts`; all four interpolations escaped. **(PR 1)**
- [x] **Quick hardening:** timing-safe OAuth `state` compare; MCP gateway relay validates non-builtin
  upstreams via `assertFetchableUrl` (raw pass-through kept — safeFetch would buffer endless SSE);
  `.gitignore` key-material rules; `/api/join` dual-counter rate limit (login-route shape). **(PR 1)**

Deferred as GitHub issues (see `chore/audit-closeout`): llm.v1 per-key spend caps; stream-based
upload size rejection; compose first-boot secret generation; upstream-error-text sanitizer pass;
Google `email_verified` enforcement.

## P2 — Structural DRY / API consistency

- [x] **The client mutation door.** `fetch-json.ts` exports GET helpers only → 134 hand-rolled
  `credentials:'same-origin'` stanzas across 67 files, ≥8 private helpers with divergent error
  contracts (boards throws, models returns `{error}`, inbox-focus drops the message). Add
  `postJson/putJson/patchJson/delJson`; migrate kb.ts first, then inbox-focus, then the helpers,
  then the sweep. Invariant rule: the stanza lives only in `fetch-json.ts`. **(PR 2)**
- [x] **28 files bypass `parseBody`** (27 discard the zod issue); **34 hand-roll the `requireUser`
  401** (boards family uses three spellings in one resource). Mechanical. **(PR 4)**
- [x] **SDK exports no validation helper** → `apps/contacts` hand-validates; also returns 404 where
  the host dispatcher returns 405+`allow`. **(PR 4)**
- [x] **Envelope/status polish:** `{ok:false}` second envelope (`auth/password.ts`); 422×2 vs 152×400;
  500s echoing `e.message` ×3; 403-where-401 on four task endpoints; `requireView` doc overstates
  coverage. **(PR 4)**
- [x] **Naming:** `plan`/`plans` prefix split in one family; singular `inbox/focus/conversation`
  beside plural `conversations`; `/api/profile` vs `/api/me`. **(PR 5)**
- [x] **Server consolidation:** Google OAuth built 3× (`requireToken` byte-identical ×3, two
  userinfo types for one endpoint, endpoints ×3, twin callbacks); work-session dispatch prompt
