# Talaria — full-app audit

_2026-07-30 · against `dc17712` / `4241664` · ~112k LOC in `ui/`, 466 TS/TSX files, 176 API routes, 78 tables_

Seven parallel audits (API authorization · fleet/sandbox/MCP · data layer · frontend · AI/LLM layer ·
architecture · engineering process), with every headline claim re-verified against source or by
execution. Findings below are marked **[verified]** where I reproduced them directly rather than
reading for them.

---

## Verdict

The design quality here is high and the conventions are real — four convention documents, a uniform
route shape (176/176), `strict` + `noUncheckedIndexedAccess` with a clean compile, envelope
encryption done properly, correct atomic counters where it matters, an ACL model that is genuinely
thought through. This is not a codebase that lacks care.

The problems are almost entirely **enforcement gaps, not design gaps**: conventions with a single
mechanical shape sit at 100%, conventions requiring judgment sit at 60–80% and are drifting, and
nothing automated has ever run on any commit. That is a much cheaper problem to fix than the reverse.

Three things need attention before anything else, because they are not "hardening" — they are broken:

1. **The app cannot install from a clean database.** [verified by execution]
2. **Agent identity is forgeable**, which makes every per-agent control in the product advisory.
3. **The README's human-in-the-loop guarantee does not hold.** [verified]

## P0 — Broken now

### 1. Fresh-install failure: migrations fail at statement 21 of 212 [verified by execution]

I extracted the real `MIGRATIONS` array from `ui/src/server/db/pg.ts` and replayed it against a
scratch Postgres. Statements were inserted mid-array rather than appended, so 11 of them reference
tables created hundreds of statements later. `alter table … add column if not exists` guards the
*column*, not the table — these are hard errors.

```
201/212 applied; 11 FAILED
[21] alter table research_runs add column if not exists title text
       → relation "research_runs" does not exist          (created at index ~190)
[22-24] alter/index channel_messages …                    → relation does not exist
[26] delete from user_agent_access … from agent_defs      → relation does not exist
[27-28] alter/update kb_docs …                            → relation does not exist
[34-35] create table kb_comments … references kb_docs      → relation does not exist
[47] insert … where can_mint_keys                         → column does not exist
[48] create table channel_message_reactions …             → relation does not exist
```

A fresh database therefore **permanently lacks** the `kb_comments` and `channel_message_reactions`
tables, `channel_messages.thread_root_id` / `edited_at`, `kb_docs.okf`, and `research_runs.title`.
Verified: the live dev DB has all of them (built incrementally as migrations were appended in order);
a clean DB creates 76 tables and is missing both of those.

`ensureMigrated()` (`pg.ts:1163`) caches the **rejected** promise, so once this fires every
subsequent `db()` call rejects for the life of the process. No retry, no recovery, no partial-state
record.

**Also:** `kb_spaces.okf_doc_id` is selected by `SPACE_COLS` (`kb.ts:77`) — backing `listSpaces`,
`getSpace`, `createSpace`, `getPublicSpace` — but is created by **no migration at all**. It exists
only in the live DB, added out-of-band. On any clean install the entire KB spaces feature throws.

**Fix:** move the 11 statements after their tables; add the missing `okf_doc_id` migration; then add
a `schema_migrations` table with checksums and a `pg_advisory_lock` around the run, so ordering is
enforced mechanically and a mid-list failure is recoverable.

### 2. Agent identity is a self-declared header behind one shared key

`agent-auth.ts:13-28` — `checkAgentKey` compares one org-wide `TALARIA_AGENT_KEY`; the *identity* is
whatever the caller puts in `x-agent-name`. Nothing binds the two. `fleet-render.ts:412` stamps that
same key into **every** agent container, and agents with a workbench profile have a shell.

Every per-agent control in the product resolves off that header: MCP tool allowlists
(`mcp.gw.$server.ts:19`), board agent policy (`tasks.$id.ts:69`), retrieval principals
(`rag.search.ts:23`), per-agent repo grants, per-user MCP OAuth connections, and — most seriously —
owner-identity proxying (`users.ts:85-110`), where naming a personal assistant resolves the request
to that assistant's **human owner**, with `elevated: true` if the owner is an admin.

One compromised or prompt-injected agent reads its own env and acts as any other agent, or as an
admin. This is the keystone: it is a precondition for the retrieval ACLs, the MCP allowlists, board
policy, and per-agent metering to mean anything at all.

**Fix:** mint a per-agent secret (the renderer already does this for `HERMES_KEY_<SLUG>`); resolve
identity **from the credential**, never from a header; keep `x-agent-name` only as a cross-check.

### 3. Human-in-the-loop guarantee does not hold [verified]

README:35 — *"Agents create and triage work but can't assign it to themselves or mark their own work
done. Sign-off is always a person's call, enforced at the protocol layer."*

The MCP toolkit half is true (no `assign` tool, no `complete` tool). The protocol-layer half is not.

`tasks.ts:210` makes `failed` and `cancelled` always-legal statuses. Because they are not board
status rows, they are never in `meta.doneKeys` — so the coercion at `tasks.$id.ts:103` that redirects
agents to the review column **never fires for them**. `PUT /api/tasks/:id {"status":"cancelled"}`
with the fleet key closes an agent's own ticket: no human, no QA judge, rendered as closed in the UI
(`field-pills.tsx:99`), dropped from overdue reporting, and `work-dispatch.ts:46` treats the session
as cleanly terminal.

Three related gaps, all verified:
- **`archived` is not stripped.** The agent branch nulls `assignees`, `estimatedHours`, `parentId`
  (`tasks.$id.ts:105-108`) but `archived: z.boolean().optional()` (`:31`) passes through. Agents can
  archive their own work.
- **Sign-off is not sticky.** The assign guard only refuses when the *current* status is
  open-category (`:99`), so an agent can pull a ticket back out of `done` — and `tasks.ts:231` nulls
  `completed_at`.
- **Implicit self-dispatch.** `tasks.ts:229` promotes a ticket into `meta.assignedKey` inside
  `updateTask` when assignees are present, with no `patch.status` for the route guard to inspect. Any
  agent write to a pre-assigned intake ticket — including `add_time` — flips it into the pickup queue.

Root cause is structural: `updateTask` has no concept of an agent actor (it takes a free-form
`actor: string`), so all enforcement lives in the route and every new caller inherits zero of it.
`judge.ts:182` already writes status through it outside those guards.

**Fix:** move the invariant into `updateTask` behind an `actor: {kind:'human'|'agent'}` parameter.
That closes all four gaps in one change.

## P1 — Cost and correctness (an agent-ops product's core)

- **The largest LLM spend in the product is metered nowhere.** The gateway skips metering for
  `fleet-gateway` on the assumption that usage is "already metered by those flows"
  (`llm.v1.chat.completions.ts:35`). It isn't, for the two biggest consumers: **workbench harness
  runs** (`workbench-harnesses.ts:26` gives them the fleet gateway credentials — a heavy coding run
  is routinely 0.5–2M tokens, the ledger records ~1,200) and **Hermes crons**, which fire inside the
  container and never touch a Talaria request path.
- **No spend cap, quota, rate limit, or circuit breaker exists anywhere in the LLM path.** The only
  bounds are `MAX_SESSION_TURNS = 12` (guarded by an in-process `Set`, so a restart re-enters) and a
  titler budget. `* * * * *` is an accepted cron.
- **Per-ticket cost attribution doesn't work.** README:135 claims spend is attributed to the ticket;
  `work-dispatch.ts:124` sets `refId`, not `taskId`, and `taskUsage` filters on `task_id`. The only
  writer of `task_id` is the agent's voluntary `log_usage` — which accepts 0 to 100,000,000 per field
  with no cross-check. [verified]
- **Usage is attributed to the wrong endpoint.** `classifyAgent` reads the endpoint from the agent's
  *stored config*, but `resolveRoute` picks the upstream by round-robin at request time. Cloud
  traffic can be stamped `local` and priced at **$0**.
- **Cache and reasoning tokens are unpriced.** Anthropic bills cache-write at 1.25× and cache-read at
  0.1× separately from `input_tokens`; OpenAI folds cached tokens into `prompt_tokens` at full price.
  The same code therefore *understates* on one provider and *overstates* on the other.
- **Silent model downgrade.** An unserved configured model falls back to the first local endpoint's
  first model (`fleet-brain.ts:132`) — surfaced as a render warning, never at request time. A
  deprecated `claude-opus-4` silently becomes a small local model.
- **Guardrails ship in `observe`** — detect and record, never act. They are a *confab* guard
  (fabrication), not an injection or safety guard, and they run on outputs only. Concrete false
  negatives include `github_pat_*` (the exact token shape the workbench uses in PAT mode),
  `sk_live_*`, `xapp-*`, URI credentials, and `TALARIA_AGENT_KEY` itself.
- **No prompt-injection trust boundary.** Untrusted content — channel messages, ticket descriptions,
  raw web pages in research, uploaded file contents, tool output — is concatenated into prompts with
  no provenance marking. The two markers that exist (`[Assigned work — no human sent this…]`) live in
  the same unescaped string space, so an attacker can simply write them.

## P1 — Frontend

The loading story is genuinely good (`Skeleton` used across 59 files, several shape-matched), every
`invalidateQueries` is scoped, and the primitives get a11y right where they try (`IconButton` makes
`title` required and mirrors it to `aria-label`). The failures cluster in three places:

- **A failed query is indistinguishable from empty data, app-wide.** 49 query functions in `lib/**`
  convert non-2xx into a successful empty value, so the query never enters an error state —
  `isError` appears 8 times against 114 `useQuery` sites. A server blip renders as *"No boards yet"*,
  *"Board not found — it may have been deleted"*, an empty sidebar, or the first-run hero shown to an
  existing user. Worst case: `session.ts:27` returns `{user:null}` on a 500, and `_app.tsx:24` then
  **bounces a logged-in user to `/login`** — a backend blip reads as a logout. The correct throwing
  helper already exists at `channels.ts:56`.
- **No error boundary anywhere.** No `defaultErrorComponent`, no `componentDidCatch`, no
  `QueryCache.onError`. [verified: none in `__root.tsx` / `router.tsx`] The app's one `<Suspense>`
  (`app-surface.tsx:51`) wraps a `React.lazy` chunk with **no boundary** — a stale asset hash after
  deploy white-screens the entire cockpit.
- **Zero `useMutation` call sites** [verified], and no toast system — the only feedback channel is
  `alert()`. ~35 writers never check `res.ok`. Consequences: kanban drag-and-drop silently reverts on
  the next refetch; `artifacts.tsx:489` autosave is `try/finally` with **no catch**, so the user keeps
  typing into a document that stopped saving; `plan-doc.tsx:114` swallows a failed flush so the agent
  rewrite **clobbers unsaved edits**.

**A concrete data-correctness bug:** the same due-date field stores a different instant depending on
which surface edits it — `field-pills.tsx:226` writes `new Date(\`${v}T17:00\`)` (5pm local),
`task-detail.tsx:403` writes `new Date(v)` (midnight UTC). [verified] This is the duplication in §
architecture producing a real defect.

Also:
- **`@tanstack/react-router-ssr-query` is a declared dependency that is never imported** [verified],
  and there are **zero route loaders** — so the SSR shell prefetches nothing and every route
  waterfalls after hydration. `boards/$boardId` gates five queries plus the SSE subscription behind
  `useBoards()`, so **events in that window are lost**.
- **Stream leak:** `sse-parse.ts:37` acquires `body.getReader()` with no `try/finally` [verified].
  `chat-view.tsx:252` `break`s on `queued`, so the reader is never released and the fetch stays open
  — one leaked connection per queued-while-streaming send. One-line fix.
- **`EventSource` has no `onerror`.** `boards.$id.events.ts:15` returns 403 on non-membership; a
  non-2xx moves EventSource to CLOSED and **the browser does not reconnect**. An expired session
  makes the board silently non-live forever. The server also emits no `id:`, so events during any
  reconnect gap are lost.
- **Nothing is virtualized** (no virtualization dep installed) and the chat transcript is unbounded —
  `chat-view.tsx:165` full-refetches every 800ms during a stream, re-rendering the whole transcript,
  with an O(n²) `messages.some()` inside the `messages.map()`. `markdown.tsx:139` passes fresh plugin
  arrays every render *and* sets `detect: true`, running highlight.js auto-language-detection over
  every unlabeled code block on every re-render.
- **All heavy deps are in the initial-load graph** — one `React.lazy` in the app, and `vite.config.ts`
  has no `build` key at all. The home route pulls in the full remark/rehype pipeline, all of TipTap +
  ProseMirror (via `assistant-wizard`), and framer-motion; `rich-editor.tsx:21` registers ~37
  highlight.js grammars at module scope.
- **Draft state is clobbered by refetch** in 8 editing surfaces — with `staleTime: 5s` +
  `refetchOnWindowFocus`, a tab refocus overwrites the name/title being typed. `knowledge.tsx:1042`
  is the worst: in multiplayer it invalidates every 10s, stomping the title field. The correct guard
  already exists at `task-detail.tsx:111`.
- **A11y: 89 `<label>` elements, zero `htmlFor`, zero `aria-labelledby`** — ~220 form controls with no
  programmatic name. The shared `Modal` (25 files) has no focus trap, no initial focus, no restore, no
  scroll lock and no accessible name. `Combobox` has no combobox semantics and no arrow keys. Two
  files (`input.tsx` + `modal.tsx`) fix most of it.

## P2 — Data layer

- **No migration tracking, locking, or rollback.** All 212 statements re-run every boot; 7 of them
  are unguarded DML (one re-populates `assignees` from the legacy `assigned_to` column on every
  start, undoing deliberate unassignments). Two instances booting concurrently can collide on
  `CREATE TABLE IF NOT EXISTS`, which is not atomic.
- **No GIN index on any jsonb column.** Every attachment fetch runs three unindexed sequential scans
  (`messages`, `channel_messages`, `tasks` via `@>`) plus a leading-wildcard `like` over every KB doc
  body. A page with 20 images does 60+ seq scans. The agent heartbeat (`assignedWork`) seq-scans
  `tasks` per agent per poll; the one index that exists (`tasks_assignee_idx`) is on the dead
  `assigned_to` column.
- **`messages.seq` uses read-modify-write.** `channels.msg_seq` and `boards.ticket_seq` both do the
  atomic `update … returning` inside a transaction, and `pg.ts:328` documents exactly why —
  `messages` never got the fix. Two collaborators posting simultaneously in a multiplayer plan lose
  one message to a `23505`.
- **~10 multi-statement writes that should be atomic aren't** — `saveDoc` (7 UPDATEs), `saveArtifact`
  (8), `updateProfile` (9), status delete + task reassign, `setArtifactOfficial`. Concrete failure:
  a doc flipped to `public` whose `public_slug` never gets assigned, which `getPublicDoc` can never
  resolve.
- **No pagination on the primary read paths** — `listBoardTasks`, `getConversation`, `priorMessages`
  (rebuilt on *every* turn, with a correlated `count(*)` per message row), `listArtifacts` (selects
  `body` for the whole table, then ACL-filters in JS).
- **Job claiming is in-process only.** `liveSessions` and `continuing` are plain `Set`s; a second
  instance duplicates every work session. `outreach.ts:174` claims a slot with a bare INSERT + an
  unlocked `order by created_at desc limit 1` UPDATE.
- **`redis.keys()` in a polled request path** (`kb.docs.$id.live.ts:35`) — O(N) over the whole
  keyspace, including every 7-day session key, on every doc-presence heartbeat.
- **Pool has no `statement_timeout`, no `connect_timeout`, no SSL option**, `max: 10`. Ten slow
  attachment fetches exhaust the pool and stall the app.
- **Losing Redis logs out every user** — sessions exist only there, with no `sessions` table. Worth
  stating as an operational property. Keys also have no global `talaria:` prefix.

## P2 — Architecture and maintainability

- **`server/` is one 33-module import cycle** caused by 29 specific edges — and 16 of the 32
  `await import()` cycle-breakers carry no comment explaining why, so converting one back to a static
  import is an import-time crash waiting to happen. A **bounded-context** split fails (161 cross-group
  edges, 16 bidirectional pairs); a **five-layer** split works (236 legal, 112 same-layer, only 29
  upward violations, of which 24 are plain static imports a lint rule catches today).
- **354 `as unknown as` casts** make the DB layer unverifiable — a column rename is a zero-compile-error
  change. Two consequences verified:
  - **Every `createdAt: string` is a lie.** With `pg.ts:15`'s exact options, postgres.js parses
    `timestamptz` into a **`Date`**. `typeof === 'object'`, `.slice` is `undefined`. It works only
    because these are `JSON.stringify`'d on the way out; the first server-side `.slice(0,10)` or
    string comparison typechecks and is wrong. **One-line fix** (a `types` override on `getSql()`).
  - **`AgentDef` has two runtime shapes.** It declares `ticketTemplateId` / `planTemplateId` as
    required; the `managedAgents` select (`fleet-render.ts:201`) doesn't fetch either but casts to
    `AgentDef` anyway. Three other selects do fetch them. `tsc` is clean.
- **152 of 297 route handlers are structural clones** — 22 clusters, the largest being 47 verbatim
  copies of `guard → json({ x: await listX() })`. ~90 copy-pasted ACL checks in 5 patterns; the
  agent-key dual-auth prologue is duplicated across 30 files (`'x-agent-name required'` appears 25
  times) and is *not documented in `api-guard.ts`* despite being the second-most-common auth
  mechanism. Three files have already independently extracted it locally — the strongest possible
  signal it belongs in the guard module. Estimated 1,200–1,500 lines removable.
- **One user is written into audit tables under five different names.** `actorOf` exists and is used
  in 50 files, but `user.email ?? user.name` is hand-written **64 times** with arbitrary fallbacks:
  `'user'`, `'admin'`, `'reviewer'`, `null`, or nothing. Ownership is then recomputed a *third* way on
  the client (`artifacts.tsx:487`). This is a correctness bug wearing a style-nit costume, and it gets
  harder to unwind with every row written.
- **280 raw `fetch` calls and zero `useMutation`.** Six modules independently reinvented the same POST
  helper (two byte-identical); `if (!r.ok)` forks three incompatible ways; `as { error?: string }` is
  re-declared 28 times. It has already produced a bug: two `useQuery` blocks share
  `queryKey: ['admin-settings']` with different declared return types over one cache entry. [verified]
- **Three full skill-editor implementations** with three different cache keys — a save in one surface
  does not refresh the other two. Four `/api/history` clients, three copies of the `Rev` interface.
  Three visually different tab strips in three modals, one of which is a byte-identical copy of
  `ui/tabs.tsx`.
- **~334 swallowed errors against 25 log lines**, densest exactly where failures are least visible
  (retrieval indexing, agent orchestration). Nothing distinguishes deliberate fire-and-forget from
  accidental.
- **Dead code:** `adapter/` (61 lines, imports two modules that don't exist, has never compiled),
  empty `stack/`, `@tanstack/react-router-ssr-query` (genuinely unreferenced), and a `sweep*` cluster
  of exported-but-unreferenced background jobs.
- The two repo paths are the **same worktree** (identical inode) — nothing to reconcile.

## P2 — Process and operations

Stated factually, because this section shouldn't be overstated:

- **Zero tests.** No runner, no config, no `*.test.*` (the one filename match,
  `routes/api/mcp.test.ts`, is a *route handler* for `POST /api/mcp/test`), no test imports, no
  `npm test`. [verified]
- **Zero CI.** No `.github/`, no other CI config, no active git hooks. The PR-numbered commits
  (#182–#199) are single-parent squashes by one committer; nothing automated has ever run on any of
  them. [verified]
- **No linter or formatter** of any kind. The one automated correctness signal is
  `tsc --noEmit` — which is strict, clean, and runs only when a human remembers.
- **7 dependency vulnerabilities** (2 high, 5 moderate). [verified] `postcss` path traversal and
  `linkify-it` DoS clear with a plain `npm audit fix`. The three `h3` advisories need a `--force`
  bump outside the pinned TanStack range — note **GHSA-4hxc-9384-m385 is SSE event injection, and SSE
  streaming is this app's primary workload.**
- **No observability.** 16 log statements survive a production build (9 of 22 are behind
  `import.meta.env.DEV`) against ~410 swallow sites. No structured logger, no request IDs, no error
  tracking, no metrics, **no health endpoint**, no `unhandledRejection` handler, no React error
  boundary. [verified: none in `__root.tsx` / `router.tsx`] An unhandled rejection kills the process
  and nothing external can tell. `server-entry.js:98`'s catch-all logs no method, path, user, or
  duration — and because it checks `headersSent`, a mid-stream SSE failure appends the literal bytes
  `Internal Server Error` into the stream.
- **No backups for anything** — Postgres, Redis, or uploads. No retention or restore procedure. The
  only `pg_dump` is a dev-worktree convenience. `docs/PRICING.md:33` sells "daily backups" that do
  not exist.
- **No boot-time config validation.** 38 env vars, no schema, and the process always starts. Three
  concrete traps: `realtime.ts:40`'s `process.env.REDIS_URL!` silently connects to localhost:6379;
  `storage.ts:54` falls back to `'talaria-dev-secret'`, a password published in git; and a prod
  deploy that forgets `NODE_ENV` **serves session cookies without `Secure`**. Unset
  `AUTH_ADMIN_EMAILS` yields an instance with zero admins and no warning.
- **The encryption root is missing from `.env.example`.** `TALARIA_SECRET_KEY` / `_FILE` — the one
  value `docs/ENCRYPTION.md` says must never change — is absent from the file operators are told to
  copy, while `AUTH_SECRET` is labelled *"Optional — no longer required"* despite silently serving as
  the fallback KEK. `secretbox.ts:100` deliberately soft-fails, so this presents as "my provider keys
  vanished," logged to a line nobody collects.
- **No container for the app itself** (deliberate and documented), but `build`/`start` is a working
  production path documented nowhere. `ui/.dockerignore` is an orphan.
- **Doc drift, three concrete errors:** ROADMAP claims "stateless HMAC sessions" (they're opaque
  Redis tokens); PLAN describes a "fleet multiplexer on 8642" that was removed — and the stale wording
  leaks into an operator-facing alert string at `alerts.ts:101`; `docs/PERMISSIONS.md` invents four
  permission groups and omits `Comms`. Aggravated by HANDOFF.md pointing newcomers at exactly the
  stale set as "authoritative."
