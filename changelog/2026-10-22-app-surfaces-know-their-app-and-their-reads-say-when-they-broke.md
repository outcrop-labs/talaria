- **Changed: an app surface now knows which app it is, `invalidate('things')` refreshes the filtered list the docs pair it with, and the SDK's fetch helpers are the host's own.** `AppSurface` hands each surface `{ slug, surface, manifest }` through a new `useApp()`, so client code no longer spells its slug: `useAppQuery(path, options?)`, `useAppInvalidate()` and the new `useAppApi()` default to the surface's installed slug, read once when the component initialises, so a handler still running after a navigation to another app keeps calling its own; the explicit-slug forms installed apps already use keep working. Query keys are built from the path's segments and then its search params, so `invalidate('things')` now reaches `things?q=…` and `things/123`; it used to match only a key equal to the raw string. `useAppQuery` takes svelte-query options (`enabled`, `select`, `staleTime`, `placeholderData`…), as an object or a getter. `api()` and `appApi()` are rebuilt on `ui/src/lib/fetch-json.ts`: a non-2xx rejects with an `HttpError` carrying its status and the server's sentence, a 2xx that is not JSON says so, reads stop at 30s, and a write through `api()`, `appApi()` or `useAppApi()` takes `timeout` or `signal`.
