- **Releases publish only promoted code, and the desktop updater key is reachable only from main.** `release.yml` refuses a stable `vX.Y.Z` whose commit is not on `main` and a `vX.Y.Z-rc.N` whose commit is not on `rc`, before CI starts. A tag cut on `testing` or a feature branch fails with `tag <t> points at <sha12>, which is not on <branch>`. The check fetches the two branches' commits and no files, so `resolve` still checks nothing out. The nightly and channel dispatches build the rc tip by name, as before.

  The updater signing key (`TAURI_SIGNING_PRIVATE_KEY` and its password) and `OMAPAK_SUBMIT_TOKEN` move to a `desktop-release` environment that admits `main` only. `desktop-v*` tags are left out on purpose: anyone with write access can point a new tag at unreviewed code, and a dispatch at it would hold the key and could publish a signed update. `desktop-package.yml`'s linux, macOS and Windows builds name that environment only on `main`. Once the repository-level copies are gone, a dispatch from any other ref builds every installer unsigned. It waits on no environment, and it is how to exercise the workflow. `resolve` refuses a publish or a `release_tag` from such a ref before an hour of builds, and `attach` and `omapak` run on `main` only. `omapak-submit.yml` is now two jobs: `gate` decides, and only `submit` holds the environment. So a hand-published server `v*` release still skips quietly. Any other ref is refused with the dispatch from `main` to make, and that includes a `desktop-v*` release published by hand, whose run is at its tag.

  An edit to `desktop-package.yml` or `.github/actions/` reaching main no longer mints `desktop-vX.Y.0` and makes it Latest, and an edit to `mobile-package.yml` no longer mints `mobile-vX.Y.0`. Pull requests still build the mobile workflow's edits. A new `.github/CODEOWNERS` names the three admins, so the code-owner review rule has someone to require. Before this reaches main, an admin creates `desktop-release` with the one `main` branch policy and copies the secrets into it. If the environment does not exist, GitHub creates an unprotected one the first time a job names it. The repository-level copies go once a main build has signed through it. Until then, a job outside the environment still reads them.

  Verified: `scripts/release-provenance.test.mjs` (16 checks, in `bun run check`) runs the resolve step's own shell from `release.yml` against a local repository shaped like the real history. Stable tags on main and rc tags on rc publish, pushed or dispatched at the tag the way `tag-release.yml` hands a stable release off. Tags on a scratch branch, a stable tag on an rc-only commit, and an rc tag on main's promotion merge are refused. A malformed tag fails before any fetch, the schedule and channel dispatch skip the check, and an unreachable repository refuses. Pointing the check at the wrong branch failed two of the checks, and dropping the stable check failed seven, both dispatch checks among them. The same step, run against GitHub itself, passed `v0.13.2`, `v0.13.0` and `v0.1.0-rc.1` at their real commits and refused `v0.13.2` claimed at an unmerged branch tip. actionlint on the four workflows reports nothing beyond the six info-level shellcheck notes their base already had. `bun run check` passes.
