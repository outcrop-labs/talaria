- **Fixed: desktop notifications work on Linux and macOS, closing the window keeps Talaria running so they still arrive, and the dock or launcher shows the unread count.** On Linux every banner now names its instance in the body, carries the desktop file the install actually has (detected: `Talaria.desktop` for deb/rpm, `app.talaria.desktop` for flatpak, AppImage and pacman, so no pinned launcher breaks), a category for messages and an urgency (approvals and other needs-you kinds are critical, status updates low), escapes markup so a DM saying `<b>&` shows exactly that, and replaces its own earlier banner by the id the notification server issued rather than an invented one. The whole app holds one session-bus connection: 30 banners left open used to cost 30 bus connections and 63 threads, now none. A click brings the window forward even when another app has focus on Wayland (the server's activation token is handed to the compositor), and reaches the instance as a `talaria:notification-open` event so the page can route without a reload; an older instance page reloads at the path as before. On macOS banners go through UNUserNotificationCenter with Talaria's own delegate: they show while Talaria is frontmost with its window closed, every click is routed back to its instance, permission is asked only when you click Allow notifications (on the launcher or in Settings → Desktop), and a post macOS refuses is reported instead of looking like a success. The macOS app is ad-hoc signed as `app.talaria.desktop`, the identity macOS ties notification permission to. Windows toasts are attributed to Talaria instead of Windows PowerShell. Closing the window now hides Talaria to the menu bar (macOS) or the tray (Linux with a tray host and libayatana-appindicator), or minimizes it where the desktop shows no tray icons (stock GNOME), with a one-time notice saying how to quit; Quit is in the instance switcher, the launcher and the tray, and Ctrl+Q (Cmd+Q on macOS) quits from any page; Settings → Desktop → Keep running in the background turns it off. Windows keeps quitting on close for now. A second launch on Linux brings the running window forward and exits. Settings → Desktop gains a Notifications panel that reads the real state from the OS ("On — shown by GNOME Shell", "Not allowed yet", "Blocked in System Settings", or the notification service's own error), the last error, and Send test notification. The badge is the sum of every instance's unread count (the macOS dock; Plasma, Ubuntu Dock and Dash-to-Dock on Linux). A suspended instance's watcher now starts from the page's own record of what it already showed, so a message the page missed (a dead stream, a sleep) is posted once instead of never, and the restored page does not post it again; it reconnects with backoff after a 502 instead of a fixed 5 s, and keeps its 30 s poll through the outage; clicking its banner marks the notification read. Instance pages still get no event permission, and every new command is rate limited per instance (20 banners, then one every 2 s).
