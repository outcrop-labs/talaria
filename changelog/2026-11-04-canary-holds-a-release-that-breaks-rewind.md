- **A Hermes release that would break rewind is held before it reaches an agent, and an agent whose Hermes cannot rewind says so.** The canary now carries out a rewind's fork and cut on a transcript in its own store, with the same scripts a rewind runs: it forks, retries the fork, cuts at a tool row, reads the rows back, reads the turn lease, empties a second fork and asks the stop routes about an unknown run. The first step that fails holds the release for an admin with what broke. It spends no tokens. A rewind on an agent whose Hermes lacks what it needs now fails with "this agent's Hermes does not support rewind" and what is missing, and a stopped container is no longer described that way. Verified: Hermes `stable` (v0.22.7) passed a real compose-rendered canary, and the same canary held an image whose cut does nothing though every symbol was still there; `cargo test -p talaria-hermes-channel --lib rewind_contract` and `cargo test -p talaria-fleet-docker rewind`.
