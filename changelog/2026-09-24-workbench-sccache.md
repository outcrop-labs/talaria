- **Workbench Rust builds share a compile cache.** Every workbench job starts from an empty `target/` (and teardown deletes it after), so each job compiled all ~650 dependencies of the api from scratch, which is most of what pinned the dogfood box. prepare_env now makes sccache cargo's compiler wrapper for any repo with a `Cargo.toml`, with one cache per department on the shared harness volume. A dependency any job already compiled is a cache hit for every later job. The wrapper is set through the repo's `mise.local.toml` `[env]` as sccache's absolute path, so it applies only inside that repo and still works when cargo compiles registry crates from outside it. Opt out with `sccache = false` in `.talaria/workbench.toml`.
  Verified: clippy `-D warnings` and tests on talaria-workbench-mcp (sccache for Rust repos with or without their own mise config, opt-out, non-Rust repos untouched); in the live dogfood agent container, two separate job dirs building the same crate: the first missed on its 2 dependencies, the second hit 100%.
