- **Fixed: an agent with the browser and the terminal on now really has a browser, and an agent without a terminal is told why it has none.** On the pinned Hermes v0.22.4 image, a hired agent was offered no browser tool at all, even though its `browser` box was ticked. There were two causes, both inside Hermes. First, the image ships Chromium but not the `agent-browser` CLI that drives it. The CLI is pinned in the image's own package lock, but Hermes only offers browser tools when the CLI is already installed. Second, Hermes's default browser is `browser_exec`, which it offers only to an agent that also has the `terminal` toolset, and in that default mode it withholds the built-in `browser_*` tools.
  - **The browser comes with the terminal.** Hermes's built-in browser tools would work without a terminal, but on this image they skip Hermes's own private-address check: Hermes reasons that the terminal reaches the host, other agents' containers and the LAN anyway. That holds for an agent with a terminal and not for one without. So only an agent with both `browser` and `terminal` on gets the browser, such as a Developer Agent, and it gets Hermes's default, `browser_exec`. An agent with `browser` ticked and the terminal closed, which is a new agent's default, gets no engine and no browser tool, as before. Its rendered config is exactly what it was before this change, so an upgrade changes nothing for it.
  - **Each start of such an agent installs the engine first.** Before an agent with both toolsets on starts (hire, start, roll or reconcile), Talaria runs `hermes pm install agent-browser` in a one-shot `compose run --rm` of the agent's own service, as the image's `hermes` user. The engine lands on the agent's state volume. It is the image's own pinned, sha256-checked package, installed by the image's own package manager, and it drives the image's own Chromium. Nothing is exec'd into a running agent and no browser is installed. On a roll the install runs before the drain, so the agent keeps serving while it runs. A failed install is logged with Hermes's own reason, and the agent starts anyway, without browser tools. The render lists which departments need the engine in `fleet/browser-engine.json`.
  - **A start waits at most 90 seconds for the install.** On a host whose network drops packets instead of refusing them, pm's own retries would otherwise hold every start for minutes. A one-shot that runs past 90 s is removed. Every start then skips the install for 5 minutes, so a reconcile of many agents pays the wait once. A fast failure, such as no DNS, is not remembered, so the first start after the fix installs.
  - **The toolset grid says which browser the agent has, or why it has none.** With the terminal closed it reads "Browser: none while the terminal is closed", and says why. With it open it names `browser_exec` and says the engine needs the npm registry. A backend a def authored is named too.
