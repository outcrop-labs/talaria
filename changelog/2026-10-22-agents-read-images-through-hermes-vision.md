- **Fixed:** **an agent whose model cannot see now reads images, through Hermes' own vision path, and Talaria's `describe_image` tool is gone.** Every fleet agent runs `provider: custom` with a gateway model id that Hermes' catalog does not know, so Hermes had to guess at every agent's sight. It described each attached image with the agent's own model. Once a model was known to be blind it had no describer at all, because its fallback chain (OpenRouter, Nous, DeepInfra) has no key in a Talaria container. The render now writes Hermes' own keys from Talaria's capability facts, which come from a fitness run's vision probe, the provider catalog, or a declaration. Each model the agent runs on whose sight is known gets `model_overrides.custom.<id>.supports_vision`. When any of the agent's models is not known to see, the org's `vision` role model becomes its describer as `auxiliary.vision`. That spec is routed through the gateway and key-scoped like any other. An endpoint-qualified role renders by its bare id only when that id cannot land on an endpoint not known to see, and a bare role is refused when one of its endpoints is known blind. Hermes keeps one image mode per agent, and the render picks it from the main model: `native` (pixels) for a main model known to see, `text` (the describer first) for one that is not. So under a seeing main model, a turn on a tier or fallback that cannot see gets pixels too and does not read an attached image, though that model still has `vision_analyze`. What a def authored about any of these keys stands. A blind agent with no reader, or a role that cannot be rendered, is named in the render's warnings. Assigning or clearing the `vision` role re-renders the fleet. A new capability fact reaches agents at the next render, and a re-render reaches a running agent only once #574 (hx-rolls) lands; until then it lands on the agent's next start. With the render in place, the per-upload-id copy of that mechanism goes: the `describe_image` MCP tool, `POST /api/vision/describe`, the `talaria-vision` crate, the capability-platform refusal branch, the capability-reach vision supply, and the fitness mirror and sandbox handler. The Apps SDK's in-process `ui/src/server/vision.ts` stays. The `vision` role is now marked wired, with a hint that says what it does, and Models → Roles files it under its own "Agents' eyes" category instead of Reserved. It stays out of the fitness matrix, because no Talaria harness reaches it. The toolkit skill and `fetch_attachment`'s description no longer promise "an image you can see": a tool's image arrives as a `MEDIA:` path, which a blind agent reads with `vision_analyze`. Known gap: talaria-vision metered each description against the ledger as `vision:describe`. A describer call Hermes makes while a chat turn is open now goes unmetered, through the relay's open-turn skip, until hx-metering lands. Verified: `bun run gate` was green.
