- **Fixed:** **`bun run check` no longer dies in a checkout where an app has run its database, and a worktree cut from a newer ref gets that ref's chassis and says when an older CLI set it up.** The doc-link walk in `scripts/check-docs.mjs` read every directory under the checkout. `app-data/<slug>/pg` belongs to the app database container's user, so once any app had started its database the walk threw `EACCES` and the whole check chain failed. The walk now lives in `scripts/markdown-walk.mjs`. It skips `app-data/` and `app-builds/`, the app platform's dev state, and it skips any other directory it cannot read and names it, where before it crashed. Both directories are now gitignored, and `.dockerignore` keeps them out of the image's build context (an app's `db.env` is a password file). `talaria worktree` runs the CLI of the checkout it is invoked from, usually the primary on `main`, not the base ref's CLI. It seeded `fleet/chassis.yml` from that checkout's template too, so a stack cut from `rc` got `main`'s chassis, with an older Hermes image line and env lines `rc`'s renderer had dropped. The chassis now comes from the worktree's own `scripts/chassis.template.yml`, and from the invoking checkout's only when the base ref has none. When the running `cli/src/cmd/worktree.ts` differs from the base ref's, the command now ends with a warning that names both. On 2026-10-22 a stack was cut this way with no `TALARIA_FLEET_PROJECT`, because the primary's CLI predated that line. `rc`'s CLI writes `TALARIA_FLEET_PROJECT`, `TALARIA_RUST_API_URL` and the chassis on every path: `ui/.env` is always written fresh, and a second run against an existing worktree dies before it writes anything. Verified: on `rc`, an unreadable `app-data/repro/pg` failed `bun run check` with `EACCES, scandir`, and with the fix the same tree passed the whole chain. An unreadable `docs/` subdirectory was skipped and named. New check-docs tests cover the exempt runtime directories, an unreadable directory (which fails the old walk with `EACCES`), and a missing root, which still throws. A new worktree test plants a base-ref checkout with its own template and `worktree.ts`: the chassis is the base ref's, and exactly one warning names the base ref. That test fails without the fix. `setupDiffers` is covered for the same file, a different one, and a base ref without one. Live: this branch's CLI cut `fx-dev-traps-probe` from `origin/rc`. Its `fleet/chassis.yml` was byte-identical to the probe's own `rc` template, its `ui/.env` carried `TALARIA_FLEET_PROJECT`, `TALARIA_RUST_API_URL` pointing at its own api port, and its other ports, and the run ended with the warning. The probe was then torn down. `scripts/cleanup-sweep.test.mjs` passes, and a dry-run sweep kept `talaria-wt-fx-dev-traps`. `bun run gate` is green.
