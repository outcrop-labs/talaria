- **Fixed:** Agent crons are driven through Hermes's own cron REST (`/api/jobs` on the agent's API server, the chat door and bearer) instead of `docker exec hermes cron` and a `jobs.json` read, so "Run now" stops reporting false failures and the admin frequency floor can no longer be slipped past. Since Hermes v0.22 the CLI's `run` executes the whole turn on the caller's thread, so any run longer than the exec's 30s bound came back as an error while the run carried on; REST `run` marks the job due for the next tick (≤60s) and answers at once. The floor used to read the schedule with a grammar of its own and allow anything it could not parse, which let `every minute` (Hermes's bare-unit interval), croniter's `0/1` and any 6-field cron through. Now a job is written paused, the floor judges the schedule Hermes parsed, and only then does the job start; any shape it cannot read is refused. A schedule edit pauses an armed job, patches it, judges it and resumes it, and a refused edit puts every changed field back. A create or schedule edit runs its calls on the agent to the end in its own task, so a client that hangs up partway cannot leave the job stranded paused. The edit form now sends only the fields that changed, so a rename never re-times a schedule and a job whose prompt was written longer than the cap below (the CLI had none) can still be renamed or rescheduled; an API client that sends the schedule back unchanged does not re-parse or re-time it either. The floor also reads the hour field now, so a floor above an hour stops refusing a daily cron. "Run now" on a paused job is refused, because Hermes's `run` would resume it for good (an archived thread's schedules are paused so they stop spending), and the Run button is disabled on paused rows. Prompts are capped at 5,000 characters, Hermes's own REST limit, at every cron door and in the forms. The list asks for `include_disabled=true`, so paused jobs still show. `talaria-gateway` gains `fleet_chat::agent_request`, one json call on an agent's own door, and `talaria-agent-crons` no longer depends on the docker socket.
