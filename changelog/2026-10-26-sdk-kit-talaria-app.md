- **Added: an app can be checked, built and evaluated outside the host — the instance serves an SDK kit and a `talaria-app` CLI, and a workbench job on a Talaria app gets them from `prepare_env`.** `@talaria/sdk` resolved only inside a Talaria checkout, so an app in a repo of its own — a Developer Agent's plugin repo above all — had its first compile on the host, after a merge and an install, where a failure turned it off. `GET /api/sdk/kit.tgz` now serves a kit built with the ui and versioned with the host build (`x-talaria-kit-version`: the host build stamp, then a digest of the kit's contents): declarations for `@talaria/sdk`, `/server` and `/testing`, the shared-module list, `talaria.json`'s schema, the host's own build recipe, load probe and harness replay bundled to run with no host and no database, and `talaria-app scaffold | check | build | eval`. `scaffold` writes the skeleton `talaria app new` writes (one source; `talaria app new` gains `--harness` too). `check` holds `talaria.json` to the host's rules, typechecks against the kit's declarations (only what an app may import resolves), and runs the app's own tests. `build` runs the host's recipe and probe and reports per surface, per MCP tool and per harness, skipped harnesses named as Manage → Apps names them. `eval` replays every harness fixture against replies recorded in `harnesses/recorded/`, or through the instance's gateway with `--gateway --model <id>` (`--record` keeps the replies). A signed-in member or an enabled agent on its own credential may fetch the kit. For a repo with a `talaria.json` at its root, `prepare_env` fetches the kit as the agent, installs it once per version on the department volume, puts `talaria-app` on the terminal's PATH, gives the repo a node for the checkers, and records an eval session the relay books to the job's ticket: a turn on the workbench key that carries it is now booked to that job and ticket. The host's build recipe now also refuses, by name, a bare import it does not share (`"zod" is not shared with apps: …`) — the same failure as before on the host, said the same way in the kit even where the package would resolve. Verified: vitest suites for the kit (arguments, scaffold, the declarations' rewrite, a reproducible tar, the checkers' configs, both eval transports, the eval run over recorded, failing and gateway replies), the kit route, the build guard and the proxy; the client-docs typecheck now compiles the starter harness; `cargo test` for the workbench MCP (the kit block run in a shell against a stub instance), the relay and the gateway; and the whole loop against a running stack — a kit fetched with a session and with an agent key, an app scaffolded in an empty directory outside any checkout, checked, built with a harness and evaluated against its recorded reply, the same app installed from a local git repository and loaded, and `prepare_env` run for a workbench job in a sandbox container, installing the kit and booking `talaria-app eval --gateway` to the job's ticket.
