- **Merge-to-testing is gone.** Talaria's job ends at the pull request. How a branch is then promoted, merged or sequenced belongs to the consuming repository's own branch protection, CI and written policy — every team does that differently, so a feature here that assumed one shape was wrong for most of them and drifting from all of them. Removed: the `merge_to_testing` agent verb from the workbench MCP surface, the `merge_testing` action on `PUT /api/workbench/jobs`, the "Merge to &lt;branch&gt;" button and its merged-state readout on the ticket's workbench strip, the **Testing branch** column and its explainer from Admin → the repository-flow panel, and the `merge_into` / `MergeOutcome` GitHub helpers that existed only to serve it. Per-repo flow keeps the one field that describes a pull request rather than an integration workflow: which branch PRs land on.

  `workbench_jobs.merged_testing_at` and `workbench_repo_flow.testing_branch` are retired but **not dropped** — add-first, the same call the developer-flag migration made for the columns it retired, because the previous image's job wire still selects `merged_testing_at` by name and dropping it now would leave a rollback unable to read its own table. A later release drops both. `futures-util` left `talaria-routes-workbench` with the per-row flow fan-out it was there for.

  Removing a tool also shifted the positional indices in `the_tools_spell_the_wire_key_order`, so its per-tool schema assertions were silently checking the wrong tools (request_repo's required set against finish_job's). Those assertions now address their tool BY NAME; the `names` assertion above them is what pins the wire order, and doing both positionally is what let a removal move the target without failing honestly.

  Verified: `cargo check -p talaria-github -p talaria-workbench-mcp -p talaria-routes-workbench` clean; `cargo test -p talaria-workbench-mcp` 24 pass; `bun run typecheck` 0 errors; 1304 ui tests pass; `bun run gate` green (it is what caught the index shift above); `docs/api/workbench.md` regenerated and `docs/WORKBENCH.md` rewritten to say where the boundary is.
