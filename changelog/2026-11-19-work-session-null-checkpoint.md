- **A queued work session no longer breaks a ticket's or a board's live status.** A work session's run has no checkpoint until it persists its first turn, so `runs.checkpoint` is NULL while it is queued and through its first turn. `GET /api/tasks/{id}/work-session` and `GET /api/boards/{id}/work-sessions` read that column as a plain JSON value. sqlx refuses to decode a NULL into one, `Row::get` panicked, and the router's catch-panic layer answered 500. The ticket's live strip showed an error for exactly the session it was meant to announce. The board read covers every card, so one queued card took the live state of all the board's cards with it. Both routes now read NULL as no turn and no tail. The plural `GET /api/tasks/{id}/work-sessions` has the same read; #689 fixes it there.
  Verified: the decode path was read in sqlx 0.9 (`Json<T>::decode` calls `PgValueRef::as_bytes`, which errors `UnexpectedNullError` on NULL, and `Row::get` unwraps it), and `runs.checkpoint` is a nullable jsonb that `PgRunStore::insert` never sets. A new live module, `work_session_null_checkpoint_live`, drives both routes through the real router with a queued session whose checkpoint is NULL: the ticket read answers 200 with `turn` and `lastTail` null, and the board read answers 200 with the queued card's turn null beside a working card's turn 3. Its only run is CI's live job, which is the proof. Locally: rustfmt and `bun run check`; no Rust was compiled.
