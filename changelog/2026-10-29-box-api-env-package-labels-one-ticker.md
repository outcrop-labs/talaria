- **Fixed: a devbox's api now runs with the box's own `ui/.env` block; `box new` from a worktree no longer fails at its install; a box no longer inherits the primary's app data and build directories (UB1, UB2).** The Rust api reads no `.env` file, and in a box nothing else handed it the block `box new` writes: the box compose's environment carries only `TALARIA_DEVBOX` and the app database network, `box enter` sources nothing, and the devbox branch of `talaria dev` skips the S3 lift. So a box's api read `TALARIA_AGENT_DIAL` as unset, took its fleet and apps dirs from its cwd (`/work/talaria/fleet`, a path only the box container has, so every agent bind it rendered named a host path that did not exist), handed agents the host's MCP gateway URL, and dialled qdrant, embeddings and object storage on its own loopback. `talaria dev` now lifts every line of the block the api reads, and a cli test reads the api's sources so a block key the api reads cannot be left out. `boxUiEnv` also drops `TALARIA_APP_DATA_DIR` and `TALARIA_APP_BUILDS_DIR`, which both readers then derive from the box's `TALARIA_APPS_DIR`. Found while proving it: a `talaria worktree` checkout links `ui/node_modules` to the primary's, `box new` copied the link itself, and in the box it dangled, so `bun install` failed and `box new` removed the partial box; it now copies what each tree resolves to. Verified: `bun test` for the cli (the new tests fail with the old list and the old strip); rc's and this branch's `apiEnv` over a real box's `ui/.env` and its container environment (rc hands the api none of the block's dial, dirs, gateway or service addresses; this branch hands it all of them); `box new` from this worktree, which failed at its install before the snapshot fix and completes with it; `talaria-postgres-dev` kept its id and start time across both `box new` runs.
