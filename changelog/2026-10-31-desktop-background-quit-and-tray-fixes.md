- **Fixed: on Linux the background notice no longer tells you the dock's Quit quits Talaria, a tray that disappears gives the window back, and the tray icon shows the unread count.** The dash's or a dock's Quit only closes the window, the same as ×, because Talaria exports no quit action for GNOME to call; the notice and the docs now say so and name the ways that do quit (Ctrl+Q, the switcher's Quit, the tray menu). If the tray host goes away while the window is hidden to it (the GNOME AppIndicator extension turned off, updated or crashed), the window comes back with a notice instead of leaving a process nobody can see; when the host returns, the icon registers again. On Linux the unread sum is the label beside the tray icon (appindicator has no tooltip), and it clears at 0. Ctrl+Q works as soon as the window comes back from the tray, a banner or a second launch, without a click into the page first. A re-alert (a refreshed DM, Send test notification) closes the old banner and posts a new one, because a replaced notification may update silently; an update without a re-alert still replaces in place. A notification link with a `.` or `..` path segment, in any spelling (`/..//evil.example`, `/%2e%2e/x`), is refused like any other link that is not a plain same-origin path — the instance's own rule, so a link the server, the page and its service worker refuse is one the shell refuses too, and an instance at a path prefix cannot be climbed out of. Only the notification server's own signals count as clicks: another program on the session bus can no longer open an instance by sending `ActionInvoked` for one of its banners. Settings → Desktop shows each instance its own last error and last post, never another instance's. The badge reports the count it settles on after a burst (2 → 3 → 2 no longer leaves 3), and a signed-out page reports 0 instead of its last signed-in count. A suspended instance's watcher no longer stops for good on a Cloudflare challenge (a 403 with `cf-mitigated` or an HTML body is retried like an outage; only the instance's own JSON 401/403 means signed out), the shell's requests name themselves (`User-Agent: Talaria-Desktop`), and an event split across network reads, mid-character or mid-line-ending, is no longer dropped. The single-instance name is released when Talaria exits, so the updater's relaunch never hands over to the process that is leaving. A dev build started while the installed Talaria runs says to quit it first.
