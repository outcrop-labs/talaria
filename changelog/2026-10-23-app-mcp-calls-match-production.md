- **Fixed: an app tool call now matches what production does in five places the #587 review found.** First, the gateway no longer starts an app tool's handler when the agent has already left: an agent that disconnected while its access resolved or its credentials were spent used to get the handler run anyway, with its side effects, on a call recorded as cancelled. Second, the call record no longer keeps a refused result's own keys. When a result failed its `outputSchema`, the -32603 sentence the record keeps quoted zod's report, keys and paths included (`✖ Unrecognized key: "secretKey"`). It now names only zod's issue codes and counts (`1 × invalid_type, 1 × unrecognized_keys`). Third, the app gateway's -32700 answer now agrees with the Rust gateway's serde_json. Nesting deeper than 127 arrays or objects, a lone surrogate escape (`"\ud800"`), and an overlong or encoded-surrogate UTF-8 sequence used to be accepted or reported at offset 0. They are now refused in serde's words, at serde's line, column and offset. In `@talaria/sdk/testing`, `callAppTool` with `caller: { proven: false }` now gives the null `id` the gateway sends, where it used to give `"test-agent"`. A call cut by `signal` now says the caller disconnected rather than claiming the time limit passed, and the result's new `cutBy` field says which cut happened (`"deadline"` or `"caller"`). `cut` is unchanged. Verified: new tests for each case, all failing on `rc` and passing here. The -32700 answers were compared with serde_json 1.0.151 (the api's `Cargo.lock` pin) through a standalone probe: the 34 review cases agree, and so do 30,000 mutated request bodies (679 of them disagreed on `rc`). The vitest suites for the app MCP call, gateway and SDK testing pass, and `bun run gate` is green.
