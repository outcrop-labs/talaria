- **Fixed: the MCP gateway no longer logs an upstream error for the probe Hermes sends before every connect. A terminal-less agent whose browser is a CDP endpoint supplied as a `BROWSER_CDP_URL` secret keeps its browser.** Before each `initialize`, Hermes v0.22.4 probes an HTTP server's URL (`_preflight_content_type` in tools/mcp_tool_transport.py) so that a URL pointing at a web page fails fast. The probe is a HEAD (a GET on 405 or 501) carrying the server's configured headers, httpx's default `Accept: */*`, and no session. A streamable-HTTP server answers it 406 (*Client must accept text/event-stream*) or 405, and Hermes goes on to connect. The gateway relayed that answer and logged `WARN [upstream] mcp-gw-get:<server> 406` (or `405`, twice for the toolkit) on every agent start and every reconnect. That one shape, answered 405 or 406, now logs at debug. Anything else still logs at warn: a request with a session or one that asks for `text/event-stream` (a real notification stream), a probe answered with any other status, and an upstream that cannot be reached. Separately, the render closes the `browser` toolset for an agent whose terminal is closed when the browser its config picks is one Hermes runs locally, without its private-address check (#621). It read a CDP endpoint only from `browser.cdp_url`, so a def with `backend: off` whose endpoint arrives as a `BROWSER_CDP_URL` secret had its browser closed. Hermes reads that env name first (`_get_cdp_override_raw`) and keeps its check for it. The render (`hermes_browser`) and the toolset grid's note (`authoredBrowser`, given the agent's secret names when the viewer may read them) now read that secret as the CDP endpoint, the same as `browser.cdp_url`. A hosted provider's credentials (`BROWSER_USE_API_KEY`, `BROWSERBASE_API_KEY` with `BROWSERBASE_PROJECT_ID`) are not read, because they cannot be an agent's secret: they are refused on write and skipped at materialize, so Hermes's auto-detect never finds them in an agent's env. A new test pins that, so the render has to start reading them if the rule ever changes. Camofox closing on a terminal-less agent (#621 decision 8) is unchanged.
