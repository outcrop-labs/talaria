- **Added: a Developer Agent's human-only approval request (Hermes' protected-instruction, untrusted-MCP-write and card-fill gates) becomes a card for the person whose chat it is. A reattached run's approval request now reaches the tap.** Allowing gets the step past Hermes' ask, not past its other limits: on the pinned image an allowed protected-instruction write is still refused by Hermes' write root (see below). Before this, the fleet chat door answered every Hermes `approval.request` `deny`. That left the gates Hermes never auto-approves (a write to a project's AGENTS.md / CLAUDE.md / SOUL.md, an untrusted MCP server's write tool, a saved card fill) unreachable on any streamed turn. Now, on an *attended* conversation turn (sent from `/api/chat`, or chained or resumed from one: the new `TurnAttribution::attended`), the door first offers the request to a card seam (`RAISE_CARD`, wired to the new `talaria-approval-cards` crate). A card is raised only for a Developer Agent, and only when the conversation's owner manages that agent (a named manager, its personal owner, or an admin). Every other request is refused at once, as before: an ordinary agent's, a non-manager's, or one on a channel, ticket, research, app, workbench or harness turn. The card is a `chat_approvals` row of kind `hermes_approval` and an `approval` chip on the turn's message. Only the owner sees **Allow once** / **Deny**, with a countdown; anyone else in the thread sees it read-only. The answer goes through `POST /api/chat/chips/approvals/{id}`, which re-checks the rule and sends exactly `{request_id, execution_generation, choice}` with `once` or `deny`, never `session` / `always`. A 409 or `already_resolved` from Hermes marks the card expired (the route answers 409). A Developer Agent now renders `approvals.timeout: 120`; everyone else stays at 60. The card closes itself at 115 s, answers `deny` and reads expired, and a boot sweep re-arms or closes the cards a restart left open. A person's answer is audited as `agent.approval_allowed` / `agent.approval_denied` with that person as the actor; an expired card is `agent.approval_denied` by `talaria`; an answer that reached an agent no longer waiting took nothing and is `agent.approval_expired` by the person, never an allow. Cards stay out of the approvals census. Separately, `reattach_session_run` now raises the parked run's `pending_controls` approvals as `approval.request` frames, once each, through the same tap. A run parked on an approval after its stream dropped is refused (or carded) within a poll instead of waiting out Hermes' timeout with the session's FIFO held. The projection does not say when a prompt was asked, so each rebuilt frame carries the earliest moment it can have been (the lost stream's last bytes, or the poll before), and a card raised from one counts its 115 s from then; one with under 10 s left is refused instead. While a person's answer is on its way to the agent, a reattach that raises the same request leaves it to that answer rather than racing it with a `deny`. Verified:
