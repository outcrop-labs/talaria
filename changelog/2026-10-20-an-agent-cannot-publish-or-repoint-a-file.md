- **Fixed:** An agent key can no longer put a document on the unauthenticated web or re-point a file at an upload it cannot read. `POST /api/artifacts` from a general agent always creates at `org` visibility — the `visibility` field is still validated and then ignored, as the PUT has always stripped it, because publishing is the human `artifacts.publish` power (the MCP `create_document`, `create_sheet` and `create_page` descriptions still advertise `public`; they are wrong and should say the field is ignored for every agent). An agent's `PUT /api/artifacts/{id}` with a `storageRef` is refused unless the agent can read that upload through its own access model (a ticket on a board it works, a channel it sits in), so a non-private artifact cannot be used to widen an upload's audience. Agent creates — the artifacts route and `agent-media/{model}/save` — now write an `artifact.create` audit row under `agent:<model>`, as a person's create always has. `edit_document` carries a version precondition: the save binds the `updated_at` the read carried and writes only if the row still has it; when a person saved in between, the edit is re-read and re-applied once (anchored edits make that safe), and a second move answers 409 "the document moved — read it again" instead of silently replacing the paragraph that landed in the window. `DELETE /api/artifacts/{id}` and `POST …/pull/google` answer 404, not 500, to an id that is not a uuid. Verified: `cargo clippy -p talaria-artifacts -p talaria-routes-knowledge -- -D warnings` clean; `cargo test -p talaria-artifacts -p talaria-routes-knowledge`; `bun run check`.
