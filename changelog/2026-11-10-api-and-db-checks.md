- **CI's api job runs the live-database suite itself and tests only the crates a pull request touches; migrations are a required check whose baseline is the branch the change targets.** `api-integration.yml` and `migrations.yml` are gone. The live suite now runs as steps of ci.yml's `fmt + clippy + test (api)` job: the ignored in-crate tests and the `api/tests/it` modules, against a scratch postgres and redis that start before clippy. The migration replay is ci.yml's `migrations (replay + upgrade)` job. It runs when the migration array or its scripts move and skips per job otherwise, so it can be required. The upgrade pass starts from the array of the branch the change lands on: a pull request's base, `rc` for a push to `testing`, and `main` for a push to `rc` or `main`. A `hotfix/*` pull request whose array applies anything on top of that baseline is red. In a light run (a pull request into `testing`, an offload), `scripts/surfaces.mjs` scopes the tests. It runs the packages the diff touches, the packages that read a touched file by its path (a shared fixture, another crate's source), and only the live modules whose files name those crates or reach them through `talaria_api` re-exports. A lockfile edit that touches only workspace members stays package-scoped. So does a root-manifest edit that only wires members. A registry or toolchain change tests the whole workspace. Postgres and redis start only when a live test is in scope. Clippy still checks every crate's library in every mode. Integration and full runs test everything.
