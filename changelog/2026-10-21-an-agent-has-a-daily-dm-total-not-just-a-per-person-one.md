- **Fixed:** `message_user`'s daily cap was per agent↔person pair, so a general agent could DM every person in the org three times a day, and the count-then-insert let concurrent calls overshoot the cap they did see. There is now a per-agent daily total as well (`dailyDmTotalCap`, default 20, beside `dailyDmCap` in Admin → Outreach and `GET/PUT /api/admin/outreach`; a PUT without it keeps the stored value), and the slot is claimed before the message exists: both counts and the claiming insert run in one transaction under an advisory lock keyed on the agent, so concurrent calls serialize at the cap instead of all landing. A call that fails after claiming hands its slot back. Verified: `cargo clippy -p talaria-outreach -p talaria-routes-admin --tests -- -D warnings` clean; `cargo test -p talaria-outreach` (the pure cap decision is tested under, at and over both caps); `bun run check`.
