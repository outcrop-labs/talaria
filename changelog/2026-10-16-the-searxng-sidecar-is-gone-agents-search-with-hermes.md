- **The bundled SearXNG sidecar is gone from every stack; fleet agents search with Hermes's own web tools, and the Talaria-side `web_search` MCP tool that duplicated them is removed.** Hermes Agent ships a web-search provider registry of its own (searxng, brave, ddgs, exa, firecrawl, parallel, tavily, perplexity, keenable, xai, with keyless public tiers as the floor), so every agent was getting two `web_search` tools and Talaria was running a metasearch container, an init service to render its settings, DNS pins and a canary query to notice when its engines were CAPTCHA-walled — which on a fresh instance was most of them. Now: `docker/sidecars.compose.yml` is the five sidecars; `docker/compose.yml`'s init is a stock alpine `state-init` that only hands the state bind to the app's uid (the previous init was the app image in a second role and, because it carried `build:`, every `up --build` built the whole app image twice — the double build an update took to notice); registry mode pulls `talaria` alone; the dev loop, worktrees and devboxes stop rendering or starting a search container; `SEARXNG_SECRET` is no longer generated. The SearXNG **client** stays as one operator-pointed provider shape with no default: `SEARXNG_URL` or Admin → Search names a SearXNG-compatible JSON endpoint you already run, otherwise `platform_supply` withholds `search` and every caller is told plainly that the workspace cannot search. The fleet renderer passes a configured endpoint through to each agent's Hermes as `SEARXNG_URL` (a loopback address on a host-run dev app is rewritten to `host.docker.internal`; in a containerized stack a loopback address reaches nothing from an agent and is withheld). Two deploy bugs found on the way: the first-boot postgres-password guard looked for `talaria_pg-data` even on a renamed compose project, so an initialized cluster under `<project>_pg-data` could be handed a fresh random password — it now derives the volume from `COMPOSE_PROJECT_NAME` (shell, then `docker/.env`); and `docker volume inspect` ran with the terminal inherited, printing a "no such volume" error on every fresh host's successful first `up`.
  Verified: `bun run gate` green (check, cli typecheck and tests — 223 cases including the renamed-project volume guard — and the touched crates' `cargo test`/clippy). `docker compose config` on all four layerings (prod, dev, devbox, registry), `sh -n` on the entrypoint. The image boots the way CI proves it: `docker build -t talaria-rc:local .` then `node scripts/deploy-smoke.mjs --image talaria-rc:local` — a fresh stack whose `state-init` ran as root, chowned the bind, exited 0, and whose app came up healthy and answered the claim screen. Hermes's own search surface was read from the running `nousresearch/hermes-agent:latest` container's `agent/web_search_registry.py` and `plugins/web/`, not from memory.
