- **`bun run gate:remote` compiles and tests a branch on GitHub before it has a pull request, and is red at the first failing job, with that job's log.** It pushes HEAD to `ci/<branch>` and watches the `CI offload` run, so an agent stops building on its own machine. `--full` pushes to `ci/full/<branch>` instead, and a `hotfix/`, `release/`, `sync/`, `promote/` or `backflow/` branch always goes there. Exit 0 prints one proof line naming the run, then deletes the ref. Exit 2 opens its verdict with a token line:
  - `dirty`: a tracked change is uncommitted. An untracked file only warns.
  - `base`: the branch is `main`, `rc` or `testing`.
  - `has-pr`: the branch already has an open pull request. That PR's checks are the proof, and `pr-watch` reads them.
  - `check` and `fmt`: before anything is pushed, it runs `bun run check`, then `cargo fmt --check` on the touched crates. That is rustfmt only, with no compile.
  - `no-run`: no `CI offload` run started for the commit.
  - `red`, `cancelled` and `timeout`: the run's verdict. `red` comes as soon as any job fails, with up to three log tails, while the other jobs still run.
  - `pending`: `--detach` was given.

  Only a run the ref did not already have counts. On a commit the ref already carries, the gate attaches to that commit's run instead of pushing again. `--watch <run-id>` resumes a run after a killed harness. `--rerun` re-runs a finished run's failed jobs and watches the new attempt, or with `--detach` starts it and exits `pending`. It refuses once the ref holds another commit, because a re-run would cancel that commit's run. A red ref is kept for both. The gate reads GitHub over REST with `GH_TOKEN`, `GITHUB_TOKEN` or `gh auth token`, so a devbox needs no `gh`. The cleanup sweep now deletes a merged worktree's `ci/wt/<name>` and `ci/full/wt/<name>` when it stops the stack or removes the checkout. `.talaria-keep` is git-ignored, so a held worktree no longer reads as dirty.
