- **Fixed:** An npm or pypi package server answered the Workbench's catalog instead of its own. The package spec parser required an `image`, which only an oci package carries — nothing ever recorded the stock runtime image for the other two kinds — so every npm/pypi row failed to parse, fell through the registry's in-process branch, and had the Workbench's tools stored as its catalog (and the gateway could not dispatch to it at all). The runtime image is now one table (`runtime_image(kind)`) read by the parser and by the install's pull; a package row that still does not parse (the install's pull has not pinned it yet) answers "ask again shortly" instead of falling through; and the in-process branch serves the Workbench's catalog only to the Workbench row. Verified: against a worktree stack, installing `@modelcontextprotocol/server-memory` as an npm package and refreshing its tools answered the Workbench's seven tools before the fix; `cargo clippy -p talaria-mcp -p talaria-routes-fleet --tests -- -D warnings` and `cargo test -p talaria-mcp` after.
