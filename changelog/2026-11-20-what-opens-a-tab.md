- **Agents are told one rule for what opens a tab in the pane: creating, changing or `open_in_pane` opens a file, and reading never does.** The Work prompt's first sentence said every file the agent "creates or opens" appears as a tab, so an agent that had only read a document with `get_document` told the person it was in their pane. The Work prompt now says a file appears as a tab when the agent creates it, changes it or opens it with `open_in_pane`; that `get_document`, `read_google_doc`, `read_google_sheet`, `read_google_slides`, `read_drive_file` and every search bring a file to the agent, not to the person; that when the person asks to see, open, show, pull up or go through a file the agent calls `open_in_pane`, even for a file it already read; and that a question about what a file says is answered, not opened. "Reading is free" now says reading does not put the file in their pane, and the line a turn carries when no file is open tells a new file (create it) from an existing one (`open_in_pane`). The Plan prompt and both Research prompts name every read too, Google reads included, where they named `get_document` alone. In the toolkit, `get_document` and the four Google reads end "Reading does not open it in the person's pane — if they asked to see or open it, call open_in_pane"; `create_document`, `create_sheet` and `create_page` say the file opens in a Work, Plan or Research session's pane by itself; `open_in_pane` lists show and pull up among its asks and names the Google reads among the reads that do not open; `export_to_google_doc` says its Google Doc does not open in the pane by itself, and that `open_in_pane` with the returned link puts it there. The model-fitness catalogue mirrors each description, and the fitness sandbox's `open_in_pane` now answers in the door's shape (`file`, `alreadyOpen`, `theyCanEdit`, `youCanEdit`, `message`, with the door's sentences; a listing carries each file's type and the door's sentence), and keys a Google file by its Drive id at its canonical URL, as the door does, so two spellings of one link are one file and a Google link that names no file is refused. The Work-session fitness def gains four fixtures in the owner's words: "Show me …" and "Pull up …" must open the document in the pane without pasting it, "What do … say about retries?" must read it and leave the pane alone, and "Open this Google Doc here: <link>" must open the link with `open_in_pane`'s `url`. Two parts of the rule rest on #779 (agent files land in their own session), which merged first: that a Google read opens no tab, and that a long `update_document` rewrite, or a create or edit made while the agent is answering in two places at once, opens one. If #779's Google-read rule is ever reverted, the Google-read clauses here (the Work, Plan and Research prompts, the four Google read descriptions, `open_in_pane`, the toolkit README and skill rows) must be cut back to Talaria reads.
