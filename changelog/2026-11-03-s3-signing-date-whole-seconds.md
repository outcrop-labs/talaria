- **A Backblaze B2 (or AWS S3) bucket now works as the storage target or the replica — every request was refused.** The S3 signature's `x-amz-date` carried milliseconds (`20261103T173649.020Z`). The built-in bucket let that through, but strict S3 services answer 400 `InvalidRequest`: "Timestamp … is invalid, must be in ISO 8601 format yyyyMMddThhmmssZ". So a replica sync, or a test of the connection, failed on its first PUT. The timestamp is now whole seconds (`20261103T173649Z`), the same instant the signature's scope names. Creating the bucket, reading an object back and deleting one signed with the same timestamp, and are fixed with it.
  Verified: `cargo test -p talaria-storage --lib` — the date vectors (the epoch, a leap day, and the reported instant, with its milliseconds dropped rather than rounded) and AWS's own SigV4 GET example signature. Not verified: a live request against Backblaze B2, since no account was available here.
