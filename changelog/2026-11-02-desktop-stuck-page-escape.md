- **Fixed: Talaria Desktop always has a way back when an instance's page does not come up.** While an instance restarts behind Cloudflare, its page could hang for 100 seconds and end on Cloudflare's 524, show a 502 or a challenge, or, on Windows, WebView2's network error page — in a window with no close, minimize or drag, because the styled titlebar is drawn by the page. Now a page on the instance's own address that is not Talaria puts you back on the launcher with a card saying what answered. A page that answered (an error page, a Cloudflare challenge, a sign-in gate) stays alive behind the card: **Show the page** shows it as it is, with **← Instances** at the bottom left as the way back, which also works from a sign-in provider the gate sent you on to; opening the instance any other way (its row, the tray, a notification, another instance's switcher) loads it fresh instead. Retry and Back to instances close it. A page the desktop app cannot reach into (a load that got no answer, a page where its script never answers, such as WebView2's own error page) is closed and offers no Show the page. A page that has not loaded in 25 seconds gets "<instance> is not answering", with Keep waiting. If Talaria comes up while a card is up, it opens by itself. A page with Talaria up is never interrupted, older Talaria versions included (their titlebar's call counts, and a page still starting is looked at again about 8 and 20 seconds after it loads); pages on other addresses are never judged; after a page that was not Talaria, Retry opens the instance's home, while a dropped connection or a stall keeps the page you were on; and an instance loaded in the background at launch that does not come up is tried again later.
  Verified: on Linux, on a private headless rig (WebDriver on the launcher, fake instances whose beacon answers so the open reaches the webview), against this change's earlier rounds. Main's real UI build with its lazy Tauri chunk 10 s late: opened, no card (the first round closed it at 3.9 s); 30 s late: the card at 21.5 s with the page kept, then opened by itself at 31.0 s. Held, then a 524: the not-answering card at 25.2 s, then the 524 card with the page kept; the instance's row then loaded it fresh, and so did another instance's switcher for a page carded while the person was elsewhere (round 2 would have shown the kept page as it was). A Cloudflare-style challenge that passes by itself: opened by itself at 7.4 s. A challenge that wants a click, under a strict CSP: Show the page, ← Instances back to the card, then the click and Talaria. A same-origin sign-in gate: Show the page, sign in, Talaria; on to another origin from the gate, where the shell refuses the page's calls, ← Instances and Ctrl+Shift+H both came back to the launcher. A page whose script never answers: the card at 29.8 s, the page closed, no Show the page. A share page as the last page: Retry opened the root; a dropped connection kept the last page, and Retry went back to it. Unit tests cover each rule and every row of the decision after a page finishes. `bun run gate` passes its check; its desktop cargo cannot build on this host (no GTK headers), so fmt, clippy and the 152 tests ran in the Fedora 44 rig image. Not verified: Windows and macOS at run time (WebView2's own error pages among them), the tray's entry (this rig has no tray; it takes the same `activate` as the switcher), a real instance behind Cloudflare.
