- **`talaria setup` on a checkout that is already set up regenerates nothing — it refreshes the `talaria` PATH shim and the git wiring, and adds only what is missing.** Re-running setup used to re-pull all six infra images and rebuild the toolkit and the auth bridge on every run, so nobody re-ran it, and installs ended up with no `talaria` on PATH at all (the shim was also the LAST step, behind every pull and build that could fail). Now the shim and the `git wt` / pre-push hook wiring come first, before anything slow; images are pulled only when the daemon lacks them (compose is asked what the stack resolves to, the daemon which of those it holds); `mcp/dist` and `omp-auth/dist` are rebuilt only when missing or older than their sources — the same predicate `talaria dev` runs on every boot, now shared rather than re-spelled; and `ui/.env`, `fleet/chassis.yml` and `fleet/.env` are left exactly as they were (the one write that stays is the existing pin of `TALARIA_SECRET_KEY` on a pre-key install, which never generates a value). From a linked worktree the shim keeps pointing at the primary checkout, because a `talaria worktree` is gone the day its pull request merges. A fresh clone gets the full bootstrap as before.
