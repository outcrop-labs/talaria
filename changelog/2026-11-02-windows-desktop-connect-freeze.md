- **Fixed: Talaria Desktop on Windows no longer freezes for good the first time you connect an instance. Windows users on desktop v0.11.0 must download and run the new installer by hand: the frozen launcher cannot reach Check for updates. The installer (NSIS, `Talaria_<version>_x64-setup.exe`) installs over the old copy and keeps your instances, sign-ins and settings; if the frozen copy is still running, end it in Task Manager first.** Opening an instance created its WebView2 inside the launcher's own WebView2 IPC callback (`activate_instance` was a sync command), and WebView2 cannot finish creating a webview while one of its handlers is on the stack: the window kept repainting, but the Add dialog stayed at "Checking…" and no button, titlebar control or close answered again. The instance was already saved, so every relaunch reopened it and froze at once; the in-app switcher and a suspended instance coming back did the same. Now every path that makes an instance webview runs as a main-thread task of its own (the launcher, the switcher, a restore when the window comes back, a notification click, a tray row, the launch-time preload), and a second open of an instance still being created changes nothing. Also: the shell writes a log file — `%LOCALAPPDATA%\app.talaria.desktop\logs\talaria-desktop.log` on Windows, `~/Library/Logs/app.talaria.desktop/` on macOS, `~/.local/share/app.talaria.desktop/logs/` on Linux — rotated at about 1 MB, so a problem report can carry evidence; and HTML5 drag and drop works inside instances on Windows (boards, the Gantt, dropping a file on a composer), because the instance webviews no longer install Tauri's file-drop handler. CI now runs clippy and the tests on Windows and a Windows connect smoke on every desktop pull request, and `bun run check` fails any shell command that could create a webview inline.
  Verified: the new Windows connect smoke (CI, `windows-latest`, a debug build with the launcher embedded, a fake instance on localhost registered as the last view) failed on rc's code — the launcher probed the beacon at +11.9 s, the instance page was never requested in 30 s, the shell was still running, and the data dir showed the freeze's signature (`instances\<id>\webview` made, `lastOpenedAt` null) — and passes with the fix: page and script 1.4 s after the probe, `lastOpenedAt` set, and the log file written at `%LOCALAPPDATA%\app.talaria.desktop\logs\talaria-desktop.log`. The new `bun run check` rule fails on rc's tree with exactly one finding (`activate_instance → activate → create_instance_webview → .add_child(`) and is clean here; its fixture and three mutations (an async command creating from its worker, a sync command through a helper, a sync command wrapping the preload in `run_on_main_thread`) are caught. Clippy `-D warnings` and the tests pass on Linux, macOS and now Windows in CI; the Windows job's first runs found one dead-code error and one test whose 600 ms bound is shorter than Windows' ~2 s refusal of a closed port, both fixed. On Linux, on a private headless rig (its own mutter and session bus, two fake instances, WebDriver on the launcher), with the shell built in the Fedora 44 rig image: a refused address answers in 0.3 s; Cancel on a black-holed probe closes the dialog and nothing lands 15 s later; Add opens the new instance (page loaded 1.0 s after Connect, twice); the same instance by another origin reads "already added"; switching from an instance page to a live instance and back, two activations at once, back to the launcher from a page, and a row click all work; at relaunch the last instance is probed and reopened (+1.3 s, +2.0 s), the other is preloaded hidden and suspended, a switch from a page into the suspended one recreates it in 0.6 s, and after it was suspended with the window minimized a second launch brought the window back and restored it 1 ms later (the queued restore); the connect smoke passes on Linux too (page 0.7 s after the probe); and the log file carries every line with its timestamp. Not verified on a real Windows desktop, with an installed release build, or against an instance behind Cloudflare; the switcher and suspend paths ran on Linux only; drag and drop was not exercised on any OS; macOS through CI's clippy and tests only.
