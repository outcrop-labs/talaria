- **Fixed: an app's server-side code can import `zod` again — `import { z } from 'zod'` in `server.ts`, `mcp.ts`, `harnesses/` or a `lib/schema.ts` they share builds, loads and updates, as the SDK promised before this release; it had been refused by name, so the first boot after the upgrade would have turned such an app off.** `zod` is now a shared server package, like `@talaria/sdk/server`, and it is the same module the SDK re-exports as `z`: a built `server.js` imports it from the host's runtime file `rt-zod.js` beside `rt-talaria-sdk-server.js`, both re-exporting the host's one zod (named, whole and default imports alike), never a copy bundled into the app. The SDK kit carries the same runtime file, so `talaria-app build` and the host link an app the same way, and `talaria-app check` typechecks a bare `zod` and maps it for the app's own tests. In dev, where an app's server-side code loads from source, `zod` resolves from the host as svelte does; an update that added a zod import used to roll back with "Cannot find module 'zod'". Only the bare entry is shared: `zod/mini` fails the build by name, and so does zod in a surface, with a sentence saying a surface takes its types by `import type`. The refusal of every other unshared package is unchanged.
