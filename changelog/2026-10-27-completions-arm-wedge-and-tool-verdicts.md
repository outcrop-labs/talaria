- **A chat whose agent died mid-turn keeps working, a tool call Hermes refused is saved as failed, and pinned agents say why they have no tiers.** Five follow-ups from the Hermes-overlap rollout (C1, B9, C2, C5, C9) and one recorded decision (C7).
  - **The completions arm no longer wedges after a crash (C1).** Hermes files a header-less `/v1/chat/completions` turn under a session it derives from the turn's opening, so a conversation keeps one derived session for life. After a non-graceful restart (OOM, `docker kill`), v0.22 fenced that session's head as `unknown` and refused every later turn of the conversation with `unknown_execution`, keeping each refusal queued. That arm is every chat of an agent without pinned sessions, so the conversation was dead for good. The gateway now watches each completions turn's opening (`heal_lost_completion` in `fleet_lost_turns.rs`). On that refusal, or `queue_full`, it sends the turn again once, with one more system row in its opening (`SESSION THREAD: n`). That lands it on a fresh derived session. Nothing is discarded, so the lost turn and every refusal queued behind it stay parked, never run. A chat keeps its thread on the new `conversations.hermes_epoch` column, so later turns open on the fresh session. A one-shot (harness, app or channel turn) takes a random thread. The log names the abandoned `api-…` session at warn.
  - **A refused tool call lands as `error` (B9).** v0.22.4's completions stream ends every finished tool `completed`, an approval-denied `rm -rf` included. The agent's talaria-events plugin already reported the real verdict to `/api/agents/tool-events`. That door now keeps it in Redis (6 h), keyed by the conversation the plugin's session names and the tool-call id, with the time the call finished. It marks the call on the reply that was running at that moment. A call id is not unique across turns (Hermes mints `deterministic_call_id(name, arguments, index)` when a provider sends none, and some providers number their calls), so a verdict reaches only its own conversation, and a turn takes only the verdicts from after it was sent. A session that names no conversation of the agent's (a work session, a one-shot) keeps nothing, and the wire's word stands. The chat turn folds its verdicts into its tools when it lands, and reads them again after the write, so the plugin's post and the turn's own writes can arrive in either order.
  - **Session-arm usage reads Hermes' spelling (C2).** `session_usage` takes `input_tokens`/`output_tokens` (what `run.completed` carries) as well as the chat-completions spelling. The tests now use a captured v0.22.4 session turn.
  - **Persona payloads stop sending `tools: []` / `tool_choice: "none"` (C5)**, Rust and TS. Hermes reads neither off a chat-completions body. The `ToolPolicy` docs now say what stands behind `none` on a persona: the guard pass over the tool names the stream reports.
  - **Pinned agents show the tier chip off, with the reason (C9).** A pinned session runs the agent's main model whatever a message picks. `/api/agents` now carries `pinnedSessions`. The DM composer and the Plan/Work header dim and disable the tier chip for such an agent, with "This agent keeps pinned sessions, which always run its main model…" on hover, and hold no tier for the send.
  - **Hermes' `todo_list` stays closed until the session arm is the chat default (C7).** Its list lives only in the session transcript, which a completions-arm turn does not carry, so it would reset every turn. The decision, the unblock condition and the migration plan are in `MANDATORY_DISABLED` (talaria-agent-defs), talaria-agent-todo's header, `docs/ARCHITECTURE.md` and the toolset row's tooltip.
