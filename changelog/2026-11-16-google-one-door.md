- **One door for agent Google tokens, and Check with Google.** Every agent Google token now comes through `talaria_google_agent::vend_principal_token`. The agent routes (`resolve_agent_google`), the approval executor, the queue-time write refusal and the agent record all read through it. The principal names one stored grant: the owner's own connection, the org account, or the agent's own identity. An owner with no connection gets nothing, never the org account's, and an unproven caller gets nothing. The grant refreshes with the client that minted it, and the purpose decides whether that client qualifies. A REST call takes any grant, which is unchanged for every agent tool today. A call bound for Google's Workspace MCP servers is refused, and the token never reaches them, when the grant's minting client is declared *Unticked* for "Use this client for an AI-powered agent" and Google's last answer to a check did not accept it. The answer says nothing was sent to Google's Workspace MCP servers (the vend may already have refreshed the grant at Google's token endpoint) and names the client and the fix: a reconnect when the connections slot holds a client not declared unticked, else an admin's. A client nobody has declared, or a grant that has not recorded its client, goes to Google. Eligibility follows the minting client, not the table a grant sits in, so under a flipped connections client every stored grant qualifies with no reconnect. Nothing calls Google's MCP servers for an agent yet; the Workspace MCP pack is a later change. `GET /api/fleet/defs/{id}/google` adds `agentic` (`verified`, `declared_agentic`, `declared_not_agentic`, `unknown`, or null) and `mcpRefusal`. For an `org` agent, `connected`, `email` and `clientId` now describe the org account's grant, as they already did for the other kinds, and the agent card shows the client's mark. The org account's address and its `reconnectReason` stay admin-only, as on the org connection's own routes: an agent manager who is not an admin reads them as null. On the agent card, Disconnect shows only when the saved principal is the agent's own account. Admin → Google Workspace adds **Check with Google** (`POST /api/admin/google-client/check?role=connections|signin`, admin only, audited as `google.client_check`). It makes one `tools/call list_labels` to `https://gmailmcp.googleapis.com/mcp/v1` with the admin's own connection, which must have been made with the client being checked. No connection, or one recorded as made with another client, is refused with a 409 before the token is vended, so nothing reaches Google, not even a refresh. The button sits on that client's card alone (`personalClientId` on `GET /api/admin/google-client`). Google's answer is stored under the client's id as `lastCheck` (`{ok, status, text, at}`) and shown on the card. `ok` means Google accepted the call, and that outranks the declaration. A refusal is shown in Google's words and is never read as "not marked", because the same call fails for a project outside the Developer Preview or without the Gmail MCP service. Only the last answer is kept, so a refusal after an acceptance ends it, and the client's standing falls back to its declaration. A new crate, `talaria-google-mcp`, holds the Workspace MCP product catalog and the check.
