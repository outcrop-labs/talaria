  - **F21.** Inside a devbox the app dialled an app database at `127.0.0.1:<published port>`, the box container's own loopback, so no app's store could open. The box compose sets `TALARIA_APP_DB_NETWORK` to the box's own network: the app DB joins it with no published port, and the app dials it by container name. `TALARIA_DEVBOX` carries the box's name instead of `1`, so two boxes running one app get two databases. A host-run app dials the loopback port as before.
  - **An app DB is no longer a second `postgres`.** Its compose service was named `postgres`, and compose aliases a service by its name on every network it joins. On the image's `internal` (and a box's network) that is the platform's own database, so a lookup of `postgres` answered with both, and the platform's connections could reach an app's database and fail its password. On rc that is live for every image install with an app. The service is now named for its container. One made before this keeps the alias while it runs (`restart: unless-stopped` keeps it running), so host boot recreates each one under its own name, by docker alone and from the password in its `db.env`, before anything reads the platform's database; `appSql` checks first too. The data is a bind mount and stays.
  - **No two databases on one cluster.** A box's app now asks for `talaria-appdb-<box>-<slug>` while its database from before, `talaria-appdb-1-<slug>`, still runs on the same data directory, and starting the new one put two postmasters on one cluster. Before it starts an app DB, the host looks for other app DB containers with that app's `pg` directory mounted. In a box it stops and removes the box's own `talaria-appdb-1-<slug>`. Any other running one is refused with its name, rather than joined.
  - **`talaria box rm`** removes the box's app databases: those on its network, and those with a mount in its state (a box's databases from before the network). It empties the box's state from a root container on the box's image (`--pull never`: the image is built here and named on no registry), since an app database owns its files and the removal used to die on them with EACCES. If the directory still outlives that, it says so and exits 1 instead of printing `gone`.
