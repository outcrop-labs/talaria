- **Added:** **Agents search the web with the provider the operator picks, through their own Hermes: one setting, Admin → Search → Agent web search, renders Hermes's `web:` backend and the vendor key into every agent, and once anything is chosen, Hermes's keyless public tiers stop catching agents' queries.** Hermes v0.22.4 picks its web backend from `web.search_backend` / `web.extract_backend` and reads each vendor's key from the environment. Talaria now writes both from one org setting (`agent_web_search`, new crate `talaria-agent-web-search`). The setting offers Tavily, Exa, Parallel, Firecrawl, Keenable, the Perplexity Search API, Brave Search, or SearXNG at the workspace search URL, each checked against `plugins/web/<vendor>/provider.py` (NAME, KEY_ENV, EXTRACT, KEYLESS), plus an optional separate provider for reading pages. Three registered v0.22.4 backends are left out: `ddgs` (the image does not ship the package), `xai` (a model call to x.ai outside the gateway), and `openai-native` (it needs the Codex Responses transport). The key is sealed into the setting row. Each render unseals it into `fleet/.env` as `TALARIA_WEB_<VAR>`, and the agent service interpolates it under the exact name the provider reads, so the value never appears in the compose file or config.yaml. Hermes's own provider env blocklist keeps it out of terminal and execute_code children. When a provider is picked, or a search URL reaches the agents, the render also sets `web.keyless_fallback: false` and `web.keyless_rescue: false`, unless the operator ticks **Allow Hermes's keyless public tiers**. Without that, a failing provider no longer falls through to the anonymous Exa, Parallel, Firecrawl or Keenable tiers. Left unset, nothing is rendered and Talaria recommends no vendor. Research does not read the setting: it keeps its own search stage on the search URL or a registered search MCP server, and the panel says so. `PUT /api/admin/search/agents` refuses a backend it does not offer, a search-only backend for page reading, a key for a vendor that is not picked, a key `.env` could not hold, a keyed vendor with no key (unless its anonymous tier is allowed), Perplexity or Brave with no key at all, and SearXNG with no search URL. Switching vendors drops the old key. The write audits as `search.agents_configure`, recording vendor names only, and rolls nothing: the choice reaches each agent at its next roll. The key appears in the secrets inventory and is re-sealed by key rotation. Admin → Search is a new tab, and it also gives the existing search URL (`/api/admin/search`) the editor it never had. Verified on the worktree stack, with an agent on the pinned `nousresearch/hermes-agent:v0.22.4@sha256:7a6920…` image. Nothing set: `/opt/data/config.yaml` had no `web:` block, the container env had no vendor key, and Hermes's own `_get_search_backend()` landed on its keyless ring. With Tavily and a test key saved: the container's config read `search_backend: tavily`, `keyless_fallback: false`, `keyless_rescue: false`, and its `TAVILY_API_KEY` equalled the saved key. Hermes resolved `tavily` with its keyless tier and rescue both off, and `web_search` reached `api.tavily.com` and returned Tavily's own `Unauthorized: missing or invalid API key.` with no rescue. A real chat turn on the agent's API server (LLM through the gateway) called `web_search`, Hermes logged `Web search via tavily`, and the agent quoted that error. With public tiers allowed, the same failed call was rescued through the keyless ring (`rescued_from: tavily`, three results), which is the fallthrough the default now prevents. A search URL alone rendered `SEARXNG_URL` plus the two keyless switches, and Hermes resolved `searxng` with no rescue. SearXNG search with Firecrawl page reading rendered both keys, and Hermes resolved search to `searxng` and extract to `firecrawl`. Clearing the setting removed the `web:` block, the compose variable and the `.env` line. Every PUT refusal above was exercised. A key rotation re-sealed the key from v1 to v2, and the next render delivered the same value. A headless browser drove the panel: picking Tavily held it as a draft until its key was saved, then both landed together. `bun run gate` passed (check, ui typecheck and 1,886 tests, and fmt, clippy and tests for the six touched api packages, including 15 new `talaria-agent-web-search` tests). `bun run docs:api` regenerated `docs/api/admin.md`. CI is the proof line for the full workspace, because `Cargo.lock` moved with the new crate. Running agents pick the setting up only on a recreate. A config-only change reaches a running container once hx-rolls (#574) lands, but the vendor key rides the container environment, so it always needs the roll.
