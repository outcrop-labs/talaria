- **Fixed: a config save whose apply did not land says so, instead of closing as if it had worked.** `POST /api/fleet/defs/{id}/edit` answers `applied: false` with a `warning` when the roll it was asked for fails, finds the department mid-roll, finds no agent to roll, or the agent has no container of its own. A roll step that throws (the render, the image pull, the recreate) is answered the same way, *the roll failed — <reason>*, where it used to be a bare 400 that said nothing of the version it had already saved. The version is saved either way. The Config form read only `notes`, so it closed the manage modal with no word at all. Now **Save & apply** keeps the form open and says *Saved as version N, not applied:* with the reason. A soul saved from the workspace raises a notice with the reason and leaves the same line in the form. An apply that lands still closes the modal. Pressing **Save & apply** again with nothing changed creates no version, so the route has nothing new to apply and answers no warning; the form, which saw that version not apply, now says *Version N is still not applied* with the reason and points to **Roll**, rather than closing on the silence. A left-out agent's refusal is no longer repeated in `notes`, so it is said once. The form's two saves are the only callers of the edit route. The MCP tab's apply already shows its route's `warning`. Verified in Playwright on a worktree stack with the pinned Hermes image and a mock model endpoint. Each of these saved a new version, kept the form open and said why: a **Save & apply** on Ava while a roll of Ava was in flight (*department "research" is already mid-roll*), one on a retired agent (*no managed agent in department "desk"*), and one on an agent seeded into Ava's department (*Zed has no container of its own to roll: …*, said once). That agent's soul saved from the workspace raised *Zed · soul saved, not applied*, and Ava's container kept its `Id` through both of Zed's saves. A **Save & apply** that rolled Ava in 22 seconds closed the modal with no warning, and the container read back the new threshold. With a docker shim failing the roll's `compose up --force-recreate`, a **Save & apply** on Ava said *Saved as version 5, not applied: the roll failed — docker compose failed: …* with the form open, the roll registry said `failed`, and Ava's container kept its `Id` and stayed healthy. A second **Save & apply** with nothing changed kept the form open and said *Version 5 is still not applied …*; **Roll** from the roster then recreated Ava in 24 seconds on threshold 0.82. New unit tests cover `editNotApplied`, the remembered version included.
