- **Fixed:** A secret's `allowed_hosts` is now checked against the server that actually receives the credential, not only against hosts mentioned in the arguments. The gateway hands the spend boundary the destination — the upstream URL's host for a remote server, or a token for a server Talaria answers itself (`talaria-builtin://`, `talaria-workbench://`, `talaria-pkg://<name>`, `talaria-app://<slug>`), which an allowlist names verbatim to admit — and a restricted secret refuses when the list does not cover it, whatever the arguments say. Before, a secret restricted to `github.com` could be sent to any server the agent could call by mentioning `github.com` somewhere in the arguments, and the audit row recorded the mentioned host as where it went. The `secrets.spend` audit row now carries the destination beside the mentioned hosts. Handles are substituted by walking the parsed arguments tree and replacing inside each string, instead of splicing the value into serialized JSON, so a value carrying a quote, a backslash or a newline (a service-account blob, say) lands intact; before, such a value broke the JSON round trip, the literal handle went upstream, and a one-shot relay had already been burned and destroyed on the attempt. A handle written twice into one call now spends once. A legacy shared-key caller (identified by the org-wide key, not proven to be the agent it names) spends nothing: each handle it wrote is reported to the operator as `unproven-caller`. The same rules apply on the app-server gateway in the TS runtime, which passes `talaria-app://<slug>` and the caller's proof. Verified: `cargo test -p talaria-workspace-secrets` (a quote-and-backslash value round-trips the tree exactly, keys are never substituted, each spelling is listed once); `cargo test -p talaria-routes-fleet --lib mcp_gw_server` (the destination is the host or the first-party token, lowercased, and a token admits only when named verbatim); `bunx vitest run src/server/workspace-secrets.test.ts` (51 passed) (a restricted secret refuses `mcp.notion.com` while the arguments mention github.com, admits the host, a subdomain and a named token, the audit row names the destination; nested quote/backslash values substitute intact and a one-shot written twice spends once; an unproven caller gets nothing); `bun run typecheck`; clippy `-D warnings`; `bun run check` (its invariant pass reports three failures, all in files this change does not touch: a hand-unwrapped secretbox in `fleet_defs_id_rotate_key.rs`, an off-board status literal in `mcp/src/index.ts`, and duplicate `too_many_requests`/`agent_brake` bodies in the knowledge and comms route crates).
