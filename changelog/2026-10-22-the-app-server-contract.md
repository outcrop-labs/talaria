- **Changed:** An app's server owns every path under `/api/apps/<slug>/` and gets a fuller request context: the sub-path decoded once as `ctx.segments`, `ctx.api()` to call the platform API as the caller, `ctx.secret(name)` for the workspace secrets an admin gave the app, `ctx.origin`, and `ctx.signal`, which aborts when the caller disconnects. App documents with a malformed id now return "not found" instead of crashing the app, and an app needs `app.ts` only when its manifest declares a surface. The store's `get` and `update` return `null` and `remove` returns `false` for an id that is not a UUID, where Postgres used to refuse the cast and the request came back as a 500 "app crashed". The request path is no longer decoded twice. `%25` used to 500 before the app ran, and it now reaches the handler as a literal `%`. An encoded slash (`%2F`) used to split one segment into two. It is now refused with a 400, so a segment never holds a `/`, and a malformed escape is a 400 rather than a 500. In production a malformed escape on a GET used to get no answer at all, because the static-file check threw on it. The grants example in `docs/sdk/server.md` now checks `ctx.segments[0]`, because a `ctx.path` prefix check missed the bare `admin` path. The host's rebuild route moved from `/api/apps/<slug>/rebuild`, where it took that path from every app, to `/api/app-host/<slug>/rebuild`, a TS resident listed in the generated API reference. Manage → Apps calls the new path, and no caller of the old one remains. `ctx.api(path, init)` sends only the caller's session cookie to the Rust api, so the caller's permissions apply. It returns parsed JSON and throws an `HttpError` carrying the status and the server's sentence. It refuses `/api/apps/`, `/api/app-host/`, the app MCP gateway and `/api/internal`. Reads time out after 30 seconds and writes have no deadline. `ctx.secret` resolves only a workspace vault secret, not expired, whose allowed hosts list `talaria-app://<slug>` exactly, the same entry that lets agent handles reach the app's MCP tools. An unrestricted secret is not readable by app code. Each read spends any use limit and writes a `secrets.spend` audit row (actor `app:<slug>`, plus the reading person's id), and the reason for a refusal goes to the host log. `server-entry.ts` and the vite dev middleware abort the request's signal when the response closes unfinished. The proxy now cancels a read once its caller has gone, and still lets a write run to completion. A read cut because its caller left answers 499 and is not logged: it is not reported as `[rust-proxy] … unreachable` or answered 502, so that log line still means the api is down. A real upstream failure, or a read the 30-second deadline cut, is still a logged 502 even when the caller leaves at the same moment. `ctx.api` follows the same rule: the caller leaving cuts a read and never a write, so a write an app started finishes after the tab closes. A `signal` the app passes still cuts any call. A server-only or MCP-only app with no surfaces builds without a client and enables. Verified: `bun run check`; svelte-check 0 errors; new vitest suites for the route matcher, the store, `ctx.api`/origin/segments (including its read/write split on a caller leaving), the secret rule, the gateway context, the proxy's read/write split and its quiet 499 for a caller who left (with a logged 502 kept for a refused connection or a deadline that fires as the caller leaves), and clientless builds and probes, which `build.test.ts` builds and probes for real. Live on a worktree stack, under `talaria dev`, two scaffolded apps were enabled through Manage → Apps, whose Enable click called `POST /api/app-host/<slug>/rebuild`. Each check below ran as the admin and as a member granted the work view. `GET`, `PATCH` and `DELETE items/123` answered the app's own 404, and a real id worked. `echo/files/100%25` reached the app as `["echo","files","100%"]`, `%2F` and a lone `%` answered 400, and `GET`, `POST`, `PUT`, `PATCH` and `DELETE rebuild` all reached the app's own handler. `ctx.api('/api/auth/session')` returned the caller's own id and role. `/api/boards` listed only the caller's own boards. `/api/admin/users` returned the admin's list and threw `HttpError(403)` for the member. The allowed secret resolved for both callers and wrote audit rows naming each person. Secrets locked to another host, unrestricted or unknown returned null, with the reason logged. With forwarded headers `ctx.origin` was `https://talaria.example.com`. A 15-second handler cut by curl at 2 seconds logged `aborted` at about 2,000 ms with no crash, and the uncut control finished at 15,002 ms. The server-only app (no `app.ts`, no surfaces) built and enabled, answered its admin and refused the member (no surface to grant). Then `bun run build` and `bun server-entry.ts` on the same stack. The server-only app built `server.js` and `mcp.js` and no `app.js`. Its boot probe first refused it, because it reused the dev build made without them (the shared build key, noted on #583), and Enable in Manage → Apps rebuilt it. The same probe gave the same answers for both callers. `HttpError` from the built SDK passed `instanceof` for the member's 403. A malformed `GET /api/healthz%` answered 400, where it used to hang. The slow handler cut at 2 seconds logged `aborted` at about 2,000 ms under Bun, and the member's work surface loaded the built `app.js` and added an item with no page errors.
