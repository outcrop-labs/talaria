- **Fixed:** Federation seals the credentials written inline in an imported agent's config instead of storing them as written. `federate_one` used to store the source `config.yaml` whole as `raw` in `agent_versions`. A platform token, a named provider's key or an `Authorization` header sat in Postgres in plaintext, came back from the versions and history reads, and was re-emitted into the 0644 `config.yaml` the render writes. Now `talaria_agent_secrets::plan_config_seal` walks the raw config the way the render does, before anything is written. Each literal under a credential key that the render would emit becomes a per-agent secret named for its path (`CONFIG_PROVIDERS_LAN_PROXY_API_KEY`), sealed with the secretbox. Credential keys are read on the key's last word: `api_key`, `*_token`, `*_secret`, `password`, `private_key`, `encrypt_key`, `*_aes_key`, `Authorization`, `X-Api-Key` and the like. The config keeps a `${CONFIG_…}` handle in its place, which the render delivers through the agent's `secrets.env` and Hermes expands when it loads the file. Three kinds are dropped instead, because Talaria supplies that credential itself: a model spec's `api_key` becomes the gateway's `${LLM_API_KEY}`, an authored MCP server's inline credentials go, and so does the API server's own `key`, which Hermes replaces with the render's `API_SERVER_KEY` anyway. References (by Hermes's own `${…}` pattern), empty strings, non-strings and the top-level `secrets:` block stay as written; Hermes reads that block unexpanded, and it holds secret-manager references. A literal no env line can carry (multi-line, or over 8 KB) refuses that agent before any endpoint, key or def exists, and the error says plainly that Talaria cannot deliver it. A hire from a template copies the template's sealed secrets, as ciphertext, only when the hirer manages the template or is an admin. Otherwise the clone is hired without those settings, and its first version's note names each one. The federate result lists what was sealed and what was dropped per agent, and the modal shows it. `secrets.env` lines are now quoted where compose would otherwise rewrite the value: a `$`, a `#`, leading or trailing space, or an opening quote. Single quotes are used only for a value with no `'` and no `\`. Anything else is double-quoted with `\`, `"` and `$` escaped, because compose reads a final `\'` as an escaped quote and would refuse the whole file. Before this, a per-agent secret `pa$word` reached the container as `pa`. Plain values are written byte for byte as before. `docs/ENCRYPTION.md` and `docs/user/admin-agents.md` describe it. Verified: `bun run gate` (check, ui typecheck and tests, and fmt, clippy `-D warnings` and tests for the touched crates). Unit tests cover the credential-key rules, sealing, the dropped spec key, MCP credentials and API server key, the left-alone `secrets:` block, stray `${`, nested specs, a spec at the root, names for long and clashing paths, refusals, handle discovery, withholding, and the env-line quoting. All 27 quoting cases, trailing backslashes included, read back exactly from `docker compose config` and from a real container's `env` (compose v5.5.1). Exercised on this branch's own stack, with agents on the pinned `nousresearch/hermes-agent:v0.22.4@sha256:7a69…a4cf`. A roster with a feishu `encrypt_key`, a wecom `encoding_aes_key`, a webhook `secret` holding a stray `${`, an API server `key` in both spellings, a 1Password `secrets:` block and the dashboard password `pa$wo\rd #\` federated to four sealed secrets and two dropped paths. A `pg_dump` grep for the six literals found none. After reconcile the container came up healthy (`/health` 0.22.4), and Hermes's own `load_config()` resolved all four handles to exactly the original literals. The `secrets:` block reached Hermes unchanged, and the API server took the render's key (200) and refused the dropped literal (401). A hire from that agent as template copied identical ciphertext for an admin and for a member who manages it. A member who does not manage it got none: no rows, no handles, a note naming the four paths, and a healthy container with no `CONFIG_` in its env. A multi-line `private_key` was refused by path, leaving no def. An earlier run on this branch proved a named provider's key and a dashboard password with `$$`, ` #` and `'` end to end the same way. Not exercised: the modal's new lines in a browser (svelte-check only), a hire nobody can be traced to (the create route always names the hirer), and an LLM call (none was needed to prove delivery). Rows written before this change keep their literals; sealing them needs a pass that also rolls each agent it touches, which is left as a follow-up.
