- **Fixed:** Federation seals the credentials written inline in an imported agent's config instead of storing them as written. `federate_one` used to store the source `config.yaml` whole as `raw` in `agent_versions`. A platform token, a named provider's key or an `Authorization` header sat in Postgres in plaintext, came back from the versions and history reads, and was re-emitted into the 0644 `config.yaml` the render writes. Now `talaria_agent_secrets::plan_config_seal` walks the raw config the way the render does, before anything is written. Each literal under a credential key (`api_key`, `*_token`, `*_secret`, `password`, `private_key`, `Authorization`, `X-Api-Key` …) that the render would emit becomes a per-agent secret named for its path (`CONFIG_PROVIDERS_LAN_PROXY_API_KEY`), sealed with the secretbox. The config keeps a `${CONFIG_…}` handle in its place, which the render delivers through the agent's `secrets.env` and Hermes expands when it loads the file. Two kinds are dropped instead, because the render never emits them and sealing would hand the agent a credential it does not get today: a model spec's `api_key` becomes the gateway's `${LLM_API_KEY}`, and an authored MCP server's inline credentials go. References (`${VAR}`), empty strings and non-strings stay as written. A literal no env line can carry (multi-line, or over 8 KB) refuses that agent before any endpoint, key or def exists. A hire from a template copies the sealed secrets its handles name, as ciphertext. The federate result lists what was sealed and what was dropped per agent, and the modal shows it. `secrets.env` lines are now quoted where compose would otherwise rewrite the value: a `$`, a `#`, leading or trailing space, or an opening quote. Before this, a per-agent secret `pa$word` reached the container as `pa`. Plain values are written byte for byte as before. `docs/ENCRYPTION.md` and `docs/user/admin-agents.md` describe it. Verified: `bun run gate` (check, ui typecheck and tests, and fmt, clippy `-D warnings` and tests for talaria-agent-secrets, talaria-fleet-brain, talaria-fleet-create, talaria-fleet-federate and talaria-routes-fleet). New unit tests cover the credential-key rules, sealing, the dropped spec key and MCP credentials, nested specs, a spec at the root, names for long and clashing paths, refusals, handle discovery and the env-line quoting. The quoting forms were checked against `docker compose run … env` (v5.5.1).
