- **Added:** The MCP surface has an end-to-end suite (`ui/e2e/`, Playwright; [docs/E2E.md](docs/E2E.md)). It drives a real app, api and browser against a stub world in one stdlib process (`scripts/e2e/mcp-stubs.mjs`, HTTPS with a throwaway CA, since the catalog keeps only https remotes). The stubs are a paging registry (cursor, `version=latest`, `updated_since`, `search`), an open server, a key server that answers 401 until it is sent `X-Api-Key`, an OAuth 2.1 server (client registration, an `/authorize` that 302s straight back, PKCE-checked `/token`), a dead entry and a package entry. Seven chapters: the catalog syncs and the marketplace finds the entries; an open install lands ready with its 3 tools; the key server opens the credentials editor and connects once the key is set, and the key never comes back from the api; the OAuth server is detected and connects through the popup; an agent's MCP tab assigns the server, narrows it to one tool, shows on the registry card's count and comes off again; the gateway, called with the agent's own key, echoes the allowed tool, refuses the other with -32602 before it reaches the upstream, and answers 401 with no credential; the custom form registers a raw URL. A failed chapter does not skip the rest: each one rebuilds what it needs. The suite never starts a container (the agent tab's edits go out with `apply: false`) and removes everything it made. `bun run test:e2e` runs it, and the new `e2e` CI job runs it when the ui, the stubs or the MCP crates move. That job seeds the fleet chassis a hire needs, keeps its logs beside Playwright's output (which Playwright wipes), and uploads results, report and logs on failure. Verified: against the worktree stack (the rc api, started with the stub env), `E2E_MARKETPLACE=0` (registration by URL, chapter 1 skipped) gave 6 passed, 1 skipped. With the five stub entries written into that stack's mirror by hand (an rc binary cannot follow `TALARIA_MCP_REGISTRY_URL`), all 7 passed, twice in a row. Each run left no server, agent, endpoint, fleet key or container behind. Chapters 2–4 also passed through the marketplace UI. The sync half of chapter 1 runs at integration. actionlint 1.7.7 on ci.yml: clean. `tsc -p ui/e2e`: clean. ui svelte-check: 0 errors. ui vitest: 1614 passed. check-docs and check-invariants: pass.
