- **New: `GET /api/working` answers which views an agent is working in right now, `{ comms, work, boards }`, each `{ count, label, href }` for its freshest item or null, and `useWorking()` reads it in the app.** The tab bar's waiting glyphs will draw only from this read. Comms counts your chats whose reply is streaming and the rooms you're in with an agent reply streaming. Work counts streaming work sessions, plans and research threads, plus research runs that are queued or running (a run parked on a question is waiting on you, not working). Boards counts tickets on boards you can see with a work session queued or running. Every arm reuses its engine's own predicate rather than a copy: the sidebar's `working` flag and its audience, the room page's 15-minute dead-stream silence, the research status projection, and board visibility. The conversation list, the unread badges and this read now share one spelling of each audience. One failed arm fails the whole read with a 500, and the client reads a failed read, or a failed refetch, as no reading at all, so no glyph outlives its signal. Room replies and ticket sessions send no event when they end, so the read polls every 5s while anything is lit and every 30s when idle.
  Verified: `bun run gate`. Live-DB tests against a seeded worktree database: a streaming chat reply lights Comms with the thread's title and link and stops counting once silent past five minutes, a streaming room reply lights Comms and stops once silent past fifteen, and another person's streaming chat never counts. The client test reads a 500 as null, never as "nothing working", and drops an earlier good reading when a refetch fails. On a running worktree stack with real agents, polling the route every second:
  - A chat turn read Comms 0, then 1, then 0, and stopping a reply mid-stream cleared Comms within a second.
  - A work session and a research run each lit Work while they ran.
  - Putting an agent on a ticket lit Boards for the 22 seconds the session ran.
  - A chat and a ticket session at once lit both arms.
  - A member outside a plan read nothing while the plan streamed, and read it once they were added.
  - Killing the agent container mid-reply cleared Comms within a second, because the reply closes as an error.
  - Renaming a table under one arm made the route answer 500, and the app's query read null.
  - With no session the route answers 401, and rc answers 404 for it.
  - Over five rounds of 200 interleaved requests, `/api/working` p95 was 1.9 to 2.3 ms against `/api/unreads` at 2.0 to 3.1 ms. On a synthetic 40k-message, 20k-run volume it was 2.9 to 3.3 ms against 42.9 to 44.5 ms.
