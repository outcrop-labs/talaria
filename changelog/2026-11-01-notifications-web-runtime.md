The tab that holds the notification leader lock now owns the browser's only `/api/me/events` and passes every event to the other tabs; when it closes, the next tab takes the stream over at once (five tabs were five streams and five server subscribers). A board, channel or work-session stream closes once its tab has been hidden for 30 seconds (5 on a plain-http dev stack, where a browser allows six connections to a host) and catches up when the tab is shown, so eight tabs on a dev stack no longer starve each other, and a work session that finished while its tab was hidden shows that it ended. Against a server that serves it, each tab catches up by sequence number (`?since`) — every notification filed while the stream was down arrives exactly once, as one summary past three — and the arrival record keeps its key and gains `v: 2` and `seq`. Each arrival is decided in order: a muted ("feed") row and a row held by Do Not Disturb are counted in the bell but never toasted or bannered (Needs-you rows still break through); a Direct or Following row whose page you are looking at is marked read instead of toasted (a hidden tab never reads it); the tab you are looking at toasts; and when the server says you are looking at, or using, another device, this browser stays quiet. Each tab now reports itself — looking, active, idle or hidden, with the desktop shell's OS idle time — on the presence heartbeat it already sent, a tab that closes says so on its way out, and a toast shown to you or a banner posted is acknowledged so a delayed push can skip it. When a notification is read anywhere, the banners for it close (in the desktop shell through `desktop_notify_close`) and its toast is dismissed; mark-all clears them all. The tab title counts your For-you unread, the favicon gets a dot, and an installed app's badge shows the count; a web app manifest is served. Visiting a page reads the Direct and Following notifications that point at it. A stream ended because its session ended re-checks the session at once.
