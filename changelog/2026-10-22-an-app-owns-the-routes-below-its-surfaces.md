- **Added: an app can have routes below its surfaces — `/x/<slug>/<anything>` renders the work surface and `/x/<slug>/manage/<anything>` the manage surface.** An app's list, record pages and tabs now have addresses that can be linked, bookmarked, reloaded and stepped through with Back and Forward. Before this, `/x/<slug>/items/42` rendered Not Found. sv-router lets a top-level `*` beat a catch-all nested in the `/` layout group, so Not Found moves into that group as `(*)`, a catch-all that breaks out of the shell: the app routes stay under `/` and win, and an unknown path still renders Not Found bare. The route table moves to `ui/src/route-table.ts` so a test can run sv-router's own matcher over it. No `layout`, `hooks` or `meta` key sits at or below `/x`: sv-router matches those config keys as path segments that outrank `/:app`, so beside the slug they would shadow an app named `hooks` or `layout` and its matcher would throw. Install and `talaria app new` now refuse those three words as new slugs, and an app that already has one still opens. The SDK gains `useAppRoute()`, which gives the path below the surface, its decoded segments, the query, and `match('items/:id')` with params typed from the pattern. It also gains `appHref(path, { surface? })` and `appNavigate(path, { surface?, replace? })`, which resolve relative to the surface the page shows; `useApp()` gains `rest` and `query`. A settings tab stays one page with no routes below it, and links elsewhere with `{ surface }`. The route gate, the dock, the manage sidebar and Rust's `ViewGrants::denies` give every route below `/x/<slug>` to the work grant and every route below `/x/<slug>/manage` to the manage grant. They compare paths case-insensitively, as the router does: a work grant used to pass `/x/<slug>/MANAGE`, which the router mounts as the manage surface, and `/X/<slug>` passed as a core view nobody denies. `navigateHref` now passes a query and hash in the router's options instead of in the path, so notification and activity links such as `/artifacts?a=<id>` open their view instead of Not Found. It also resolves the href as the browser will before the router matches it (`..`, `%2e%2e`, `./`, backslashes, tabs, newlines and control characters), so the router mounts the surface for the same path the route gate checks, and it refuses an href to another origin. Unresolved, `/x/<slug>/manage/../items` mounted the manage surface at the address `/x/<slug>/items`, which the gate judged as the work view. `appHref` and `appNavigate` resolve a path the same way and throw when it would leave its surface, such as `'../items'` from the manage surface; `{ surface }` is how to cross. The shell's route gate now withholds a denied view instead of only bouncing from it: as an effect alone, following a link into a surface the person does not hold rendered that surface for a moment before Home replaced it. The scaffold's work surface links each item to its own page at `items/<id>`, and its server answers `GET items/<id>`.
