- **A new worktree starts with its Rust build cache seeded, not empty, and a finished worktree's cache is the first thing `talaria cleanup` reclaims.** `bun talaria worktree` reflink-copies the registry crates' build units into the new `api/target` from the idle checkout whose `Cargo.lock` matches best (`--desktop` seeds the desktop target too, `--no-seed` starts empty, `--seed-from` names the source; `bun talaria seed-target` does it for the checkout you stand in). Nothing of a workspace crate is copied, so every workspace crate builds from the new tree's own sources. Copying a whole target passed another worktree's crates off as this one's, because a path crate's unit hash is relative to the workspace and its freshness is an mtime test. A target a cargo is building in is never read: its locks are checked in `/proc/locks` and the copy runs under shared flocks. A filesystem without reflink gets a cold build, never a byte copy or a hard link. `bun talaria cleanup` now lists the build dirs of every linked checkout, including agent worktrees whose branch was renamed (known by `TALARIA_WORKTREE` in `ui/.env`), which it could not see before. `--apply` drops a cache whose pull request merged or closed at the checkout's HEAD. With the disk over the 85% line, it also drops idle caches of clean, pushed trees, least recently used first, until `statfs` says the disk is back under. It never takes one with a cargo lock held, one built in within the hour, or one with a running stack, and a dirty or unpushed tree is flagged for a human. The stop gate removes no cache and makes no extra `gh` call.
  Verified: on the dev host (XFS, reflink=1), `cargo test -p talaria-boards --no-run` in a fresh rc worktree compiled 245 units in 15 min cold (sccache warm), and in a seeded one compiled 21 units, all workspace crates and no registry crate, in 43 s. Seeding took 0.3 s and moved `df` by nothing measurable, while `du` read 987 MiB. Correctness: in the seeded worktree a constant was changed (`role_rank("owner")` 3 → 7) with a test asserting 7, and its source mtime was set back to before the source tree's build, which is the condition the trap needs. The test ran and passed. The same change in a tree given a whole `cp -a --reflink` copy did not compile it (see the PR). A shared `CARGO_TARGET_DIR` between two copies of a scratch workspace ran the other copy's binary (`ANSWER=1` from sources saying 2), and a second cargo on it blocked for the first one's whole build. `bun run check`, cli `bun test` (481 pass, the reflink path run for real on XFS and the fallback on tmpfs), `tsc --noEmit`, and `scripts/cleanup-sweep.test.mjs` (72 checks).
