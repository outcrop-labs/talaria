- **Changed:** Every agent container now reaches the LLM gateway on **its own** key instead of one fleet-wide `LLM_API_KEY` shared by every sandbox. The fleet render mints a `tlk_` key per enabled agent (`agent:<slug>`), stamps it into `fleet/.env` as `LLM_API_KEY_<SLUG>` beside the agent's `tak_` credential, and interpolates it into that agent's compose service as `LLM_API_KEY` — so Hermes and the rendered `config.yaml` keep reading the same variable, but no container holds the fleet's key; a retired agent keeps its line, a slug that no longer exists loses both the line and the key. At the relay an agent key is the agent: its budget subject is the agent's model id (so `llm_budgets.perAgent` and `agents{…}` finally bind an agent, on the same `agent_model` window its chat turns are ledgered in), its calls are unmetered and never annotated by prefix rather than by a list, and a request for any model outside the set its rendered config routes to (`gateway_agent_models`, written by the render) is a 403 before any upstream is touched; `GET /v1/models` on that key lists the same set. Cron-driven turns inside a container remain unmetered at the relay — Hermes makes that call, not Talaria, so nothing the chat proxy sends can mark it; closing that needs the chat proxy to register its in-flight turns. Verified: `cargo fmt`, `cargo clippy --tests -- -D warnings` and `cargo test` for `talaria-gateway`, `talaria-fleet-brain`, `talaria-fleet-render`, `talaria-routes-fleet` (new unit tests pin the key-name round trip, the scope row the render writes and the relay reads, the model gate's exact match, the `LLM_API_KEY_<SLUG>` sweep and the relay's subject rule); `bun run check`.
