- **Removed: five pieces of agent plumbing that Hermes v0.22.4 already covers.**
  - **`POST /api/search` and its resolver are gone** (`search_the_web`, `WebSearch` and the `CALL_MCP_TOOL` twin in `talaria-web-search`, plus their `talaria-jobs` wiring). They were left behind when the agent `web_search` MCP tool was removed on 2026-10-16, and nothing called them. Kept: `/api/admin/search`, which sets the `SEARXNG_URL` Hermes's own search reads, and `results_from_payload`, which research uses.
  - **The `log_usage` MCP tool and `POST /api/tasks/{id}/usage` are gone.** Every Hermes agent's model traffic is already metered at the gateway, so each self-report counted spend a second time, on token counts the agent guessed: once in the ticket rollup, again in the fleet totals and again in the agent's budget window. The GET rollup stays, and rows written before this change still count in it. No other caller of the POST exists: we checked ui, mcp, desktop, mobile, cli, the skills, plugin, the apps subrepos and the Oh My Pi / coding-account paths.
  - **Nothing execs into an agent after it comes up any more.** The post-health browser install was a no-op on v0.22.4: in Docker, `hermes tools post-setup agent_browser` only checks, and the image ships pinned Chromium. It is gone, along with its marker and the `TALARIA_BROWSER_INSTALL` brake. The per-up/per-roll `docker exec rm -rf` of replaced bundled skill packs is gone too. Instead, Hermes's own `skills_sync` defers any bundled skill whose name a skill in `/opt/skills` provides. New `himalaya` and `email-inbox-triage` signposts cover the two names that were missing. Before this change, those two IMAP skills loaded on a fresh volume until the prune ran. The signpost test and the `bun run check` invariant now require a signpost for every name in a replaced pack, where before one name was enough.
  - **The tool-offer pruning measurement is gone** (`talaria-decide` `tools.rs`, the `tool-prune` census site, the admin `toolShadow` switch and its checkbox). Its premise was that every turn carries the full toolkit. That is false on v0.22.4: Hermes's tool search keeps MCP schemas behind `tool_search` / `tool_describe` / `tool_call`. Every agent config now pins `tools.tool_search.enabled: on`, unless the def authored its own value.
  - **Agents are pointed at their own `web_search` for quick facts.** The toolkit skill and the MCP `research` description now keep `research` for cited work someone will rely on. A recon run refuses on an install with no workspace search provider, while the agent's own search still works.
