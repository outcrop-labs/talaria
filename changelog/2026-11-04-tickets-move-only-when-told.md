- **Fixed: a ticket changes column only when a person moves it, and an agent picks it up only once a person put it there.** Assigning a ticket used to move it: an intake ticket jumped to the agent's pickup column ("promoted by assignment", 43 times on the owner's instance), a ticket created with an assignee was born there, and either started the agent at once. The work session then moved its own ticket, to in_progress when it began and to quality review when its PR opened (81 times), because the dispatch brief and `report_outcome` told it to. A plugin PR with failing checks or requested changes sent its ticket from review back to work and reassigned the maintainer, and the minute sweep restarted sessions on tickets nobody had released. Now a ticket's column is written in one place, `talaria-tasks` `placement.rs`, for a signed-in person, whose user id the route reads from the session. An agent never writes a status itself: its move is refused, and in a chat the refusal becomes an approval card whose click makes the move as that person. A work session starts only on a ticket a person placed in a pickup column, or on an approved, running workchain's next step, and moving it between pickup columns starts it at once. A session ends on the agent's `report_outcome`, which records the result without moving the ticket, tells the ticket's people, and spends that placement. **The board stays where you put it, and reviews arrive from outcomes:** the approvals inbox, the daily brief, the inbox cards, Home's Review list and the digest show an agent's reported outcome as work to review, and a reported error as blocked work with its reason. Each stays until a person approves it, sends it back (Request changes puts the agent back on it, even in the same column) or moves the ticket; an agent writing again never clears it. A session that stopped without a report (the turn cap, an error) spends nothing, and the sweep continues it up to the 25-session limit; at the limit the ticket says so once and its people are told. Assignment never moves a ticket or starts work, tickets are born in intake, and the sweep no longer offers finished tickets every minute or repeats the same log line. A person's Stop now lifts when that person moves the ticket again: it waited for a status line whose actor was a user id, and the board writes a person's moves under their email, so it never lifted. A new `bun run check` rule (`ticket-status-one-writer`) fails any other write of a ticket's column, in any SQL spelling, dynamic query or migration trigger, and any person actor built outside the routes. Tickets already in a pickup column keep their release only if a signed-in person's own move put them there; the rest wait for a person to place them.
