- **pr-watch takes the CI workflow's name from the PR's own repository, and the PR template asks for a `changelog/` file instead of a hand edit of `CHANGELOG.md`.** Before green, the watcher requires a finished run of the CI workflow for the PR's head. It used to read that workflow's name from the `ci.yml` in its working directory. So `--repo owner/name`, or a `--pr` URL from another repository, waited on a workflow that repository never runs, or silently guessed `CI` when the working directory had no `ci.yml`. The target repository is now the one the PR's URL names (gh returns that URL for the PR it found), or `--repo` when there is no URL to read. The name comes from that repository's `ci.yml` at the PR's head, read from GitHub. A `pull_request` run reads the merge commit's copy, which has the head's name unless the base renamed the workflow after the branch point. `gh run list` and the failed-job logs now query that repository too. If GitHub cannot answer, this checkout's `ci.yml` is used only when one of its remotes is the target; otherwise the watcher assumes `CI`. Either fallback is stated in the pending reason, the proof line and `--json` (`ciWorkflow.source`, `ciWorkflow.note`). A failed read is not cached, so the next poll tries again. `.github/PULL_REQUEST_TEMPLATE.md` now asks for `changelog/YYYY-MM-DD-<slug>.md` and says `CHANGELOG.md` is written only by the release roll. The `## CHANGELOG entry` heading that judge-pr reads is unchanged. Every `gh` read now names the PR's host. Each `gh api` call (the `ci.yml`, the branch's head and the compare) gets `--hostname`, and `gh run list` and `gh run view` get `--repo HOST/OWNER/REPO`. Before, the branch-head and compare reads named no host, so gh sent a GitHub Enterprise PR's reads to github.com, and a `GH_HOST` naming another host moved a github.com PR's reads (its runs included) there.
