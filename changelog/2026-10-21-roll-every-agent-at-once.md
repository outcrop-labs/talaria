- **Added:** Admins can roll every agent container at once from the roster. **Roll all** confirms in the page (how many running agents, an opt-in for the stopped ones), then `POST /api/fleet/roll` queues each managed agent through the same blue/green roll one agent gets, `TALARIA_FLEET_ROLL_CONCURRENCY` (default 2) departments at a time so a fleet of twenty never doubles the host's load in one breath; departments already mid-roll are skipped and named, and the request answers at once with what was queued, what was skipped and the batch id (audited as `fleet.roll_all`). `GET /api/fleet/roll` is the live picture, one row per agent: rolling, idle, failed or done, since when, and the failure sentence, read from a roll registry `roll_agent` itself writes at start and verdict (so a manager's single roll and an MCP apply's roll land on the same page) and mirrored into the Redis hash `talaria:fleet-roll:v1` so a second api instance answers the same, outcomes kept an hour. The roster polls it every five seconds while anything rolls, each tile and row carries its rolling / rolled / roll-failed chip with the sentence, the strip above the roster keeps the batch's tally and every failure, and an agent's own Roll control is disabled while its department rolls.
