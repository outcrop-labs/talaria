- **A credential sealed out of an agent's own config (`CONFIG_*`) no longer reaches any command the agent runs, a per-agent secret under a now-refused name is no longer loaded, configs stored before federation sealed their credentials can be sealed after the fact, and a sealed credential the config still uses can no longer be deleted out from under it.** The render now declares each agent's `CONFIG_*` names in a platform plugin manifest Hermes never loads (`/opt/data/plugins/platforms/talaria-sealed/plugin.yaml`, its directory mounted read-only, rewritten by rename), which is how Hermes v0.22.4 keeps its own platform tokens out of every child it spawns: the foreground terminal, `terminal(background=true)` and `execute_code` start without them, while Hermes's own process keeps them to expand `${CONFIG_…}` in `config.yaml`. The Workbench auth probe unsets the same names, so it still sees what the agent's terminal sees. A per-agent secret saved under a name the rules now refuse (`TAVILY_API_KEY`, `TERMINAL_ENV`, …) is left out of `secrets.env` and logged on each render; the Secrets tab marks it **Not loaded**. `POST /api/fleet/seal-configs` (the federation dialog's last line opens it) reports first and writes nothing; applied, it seals each agent's current literals as its secrets, rolls a running agent that gains secrets, rewrites every stored version in place, renders, and audits `agent.config_sealed` with names and paths only. Deleting a `CONFIG_*` secret the current config names is now a 409 that lists where, unless the caller asks to remove the setting too, which writes a new version without it; the Secrets tab shows where each one is used and its confirm says what goes. A revert to a version that names a sealed secret the agent no longer holds leaves that setting out. The TS `addVersionIfChanged`, which nothing called, is gone.
