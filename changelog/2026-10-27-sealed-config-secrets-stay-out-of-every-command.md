- **A credential sealed out of an agent's own config (`CONFIG_*`) no longer reaches any command the agent runs, a per-agent secret under a now-refused name is no longer loaded, configs stored before federation sealed their credentials can be sealed after the fact, and a sealed credential the config still uses can no longer be deleted out from under it.** The render now declares each agent's `CONFIG_*` names in a platform plugin manifest Hermes never loads (`/opt/data/plugins/platforms/talaria-sealed/plugin.yaml`, its directory mounted read-only, rewritten by rename), which is how Hermes v0.22.4 keeps its own platform tokens out of every child it spawns: the foreground terminal, `terminal(background=true)` and `execute_code` start without them, while Hermes's own process keeps them to expand `${CONFIG_…}` in `config.yaml`. The Workbench auth probe unsets the same names, so it still sees what the agent's terminal sees. A per-agent secret saved under a name the rules now refuse (`TAVILY_API_KEY`, `TERMINAL_ENV`, …) is left out of `secrets.env` and logged on each render; the Secrets tab marks it **Not loaded**. One such key did work before: Hermes's own web search read a per-agent `TAVILY_API_KEY`, and that stops on the agent's next restart. Admin → Search → Agent web search sets the key for every agent instead, and earlier releases already mark these rows **Would be refused today**, so they can be found before upgrading. `POST /api/fleet/seal-configs` (the federation dialog's last line opens it) reports first and writes nothing; applied to the agents the dry run listed, it seals each agent's current literals as its secrets, rolls a running agent that gains secrets (a stopped one's container is removed, so a restart cannot bring back a container without them), rewrites every stored version in place, renders, and audits each agent as it goes, `agent.config_sealed` or `agent.config_seal_incomplete`, with names and paths only. It runs to the end even if the caller hangs up. Deleting a `CONFIG_*` secret the current config names is now a 409 that lists where, unless the caller asks to remove the setting too, which writes a new version without it; the Secrets tab shows where each one is used and its confirm says what goes. A revert to a version that names a sealed secret the agent no longer holds leaves that setting out, and so does every render: a `${CONFIG_…}` with no secret behind it (removed by a secret-health clear or by hand) is withheld from `config.yaml` with a render warning until the secret is set again under that name. The TS `addVersionIfChanged`, which nothing called, is gone.
