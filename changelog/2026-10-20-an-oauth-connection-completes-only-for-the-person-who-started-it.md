- **Fixed:** The MCP OAuth callback now requires a Talaria session, and the signed-in person must be the subject the flow was started for — or hold `agents.manage` for an `org` flow. Before, the callback had no session check: a user could start a flow for their own row, hand the provider's authorize link to somebody else, and when that person consented the provider's redirect stored their tokens under the first user's connection. A state older than ten minutes is refused at the callback (states were only swept at the next start, so one could sit for days); a state the wrong person or a stale one arrives with is consumed, not left for a retry. The callback page still explains each refusal in the same window. Starting a personal (`scope=me`) connection is refused on a server that does not take one — disabled, not per-user, the builtin toolkit, an app's in-process server — before any discovery or registration runs against the server's URL. Storing a personal connection's headers (`PUT /api/me/mcp`) now requires an existing, enabled, per-user server, refuses the framing and hop-by-hop names (`host`, `content-length`, `transfer-encoding`, `connection`, `mcp-session-id`, `cookie` and the like) outright, and when the server declares its `requiredHeaders` takes only those names (`Authorization` stands in when nothing is declared, as the connect form offers); a disconnect still works on any existing server. A legacy shared-key caller is now refused the Workbench and gets no org OAuth bearer, as `subject_proven`'s contract always said. Verified: `cargo test -p talaria-mcp-oauth --lib` (a state started for one user is refused to another, an org state needs the permission, a user named "org" cannot pass as the org); `cargo test -p talaria-routes-integrations --lib me_mcp` (the never-set names, the declared-set rule, `Authorization` without a declaration); `cargo clippy -p talaria-routes-fleet -p talaria-mcp -p talaria-mcp-oauth -p talaria-routes-integrations --tests -- -D warnings`; `bun run check` (its invariant pass reports three failures, all in files this change does not touch: a hand-unwrapped secretbox in `fleet_defs_id_rotate_key.rs`, an off-board status literal in `mcp/src/index.ts`, and duplicate `too_many_requests`/`agent_brake` bodies in the knowledge and comms route crates).
