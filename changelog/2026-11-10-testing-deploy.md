- **New: every push to `testing` becomes an image the testing instance runs, and an agent can tell when its merge is live.** `testing-deploy.yml` builds the commit's dev-profile api package (`talaria-api:sha-<sha12>-dev`), then builds and smoke-tests the app image in a job that can only read packages. A separate job, which checks out nothing and runs no repository script, pushes `talaria:testing-<sha12>` and moves `:testing` to it while the commit is still testing's tip. Once the `TESTING_URL` variable is set, a last job waits for the instance to report the commit. On the VM, `docker/follow/talaria-follow.sh` (with its systemd timer) pins the checkout and the image to the revision `:testing` was built from, applies at most once every 10 minutes, and pauses while a hold file exists. `node scripts/hooks/testing-watch.mjs <pr|sha>` exits 0 once the instance runs a commit containing the merge, or 2 with `unmerged`, `red-deploy`, `down` or `timeout`. `promote-testing.yml` keeps the lane: a sticky `testing-red` issue, `sync: rc → testing` back-flow pull requests, a frozen `promote/testing-<sha12>` snapshot into rc on dispatch, a weekday readiness summary, and a daily full battery (macOS, Windows, iOS, e2e) on testing. It stays dormant until testing is brought up to rc. The api package now has one build cache per profile, so a dev nightly no longer evicts the release build's dependencies, and a dev build no longer overwrites a release `sha-<sha12>`. rc-deploy and testing-deploy queue instead of cancelling a run mid-build. A new invariant, `lane-write-jobs`, fails any job that a testing, `ci/**` or pull-request event can start, holds `packages: write` or `contents: write`, and runs a repository script or a local action. The VM's runbook is [docs/TESTING-INSTANCE.md](docs/TESTING-INSTANCE.md).
