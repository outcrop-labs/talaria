- **Changed: the app docs now say what actually runs an app harness — only the app's own `server.ts`, through `runHarness` — and the SDK's `defineHarness` is now the platform's, so an app's JSON harness refuses a model measured unable to produce JSON.** That is a behavior change for app authors. The SDK used to hand a definition back untouched, so an app's JSON harness ran on a model that a probe or an admin had recorded as `json: false`. It now gets the floor every platform harness derives (`json` added to `floor.capabilities`, `refuseBelow: true`), so on such a model it makes no call and returns `refused: true` with the harness's floor note. An untested model, or one whose JSON failure the gateway only learned from a 400, still runs. The docs: `docs/sdk/harnesses.md`, `docs/APPS.md`, `docs/HARNESSES.md`, `docs/RUST-MIGRATION.md` and the `@talaria/sdk/server` header now say that nothing compiles, registers or scores `apps/<slug>/harnesses/*.ts` today. HARNESSES.md points its 18 deleted `api/src` paths at the crates that hold them, counts 40 harnesses, documents the derived JSON floor, and drops the JSON-row workbench harness and the Claude Code/Codex/Aider row. APPS.md's uninstall says what uninstall does: the `wipeData` flag changes nothing. `docs/sdk/mcp.md` says a secret with a host list resolves for an app's tools only if the list names `talaria-app://<slug>`, and that otherwise the handler receives the handle text. `apps/README.md`'s client example reads `things.data?.things`. With the app grants, server contract, client, routes and MCP changes it merges in, `apps/README.md`, `docs/APPS.md` and `docs/sdk/getting-started.md` now agree with them: each surface is its own grant (per person or per team), the settings tab follows the manage grant, the gateway admits a holder of any surface and a manage-only route checks `ctx.access.manage`, the server context is `user`, `access`, `perms`, `can`, `segments`, `path`, `url`, `origin`, `store`, `api`, `secret` and `signal`, surfaces read their slug from the host and never spell it, each surface owns the routes below it, an app with no UI ships no `app.ts`, and an app that is turned off keeps its MCP server row and grants until uninstall removes them. `reference.md` and `getting-started.md` stop describing `harnesses/*.ts` as loaded, and `mcp.md` says an unresolved handle can sit anywhere in a string. The API reference generator now lists a required body field that a handler reads by hand, so `docs/api/admin.md` shows `installUrl` (six other route bodies gain required fields, and PUT `/api/admin/apps` renders as its two variants). `PlatformAgentId` gains `ticket-relevance`. Stale source comments in `ui/src/server/apps.ts`, `app-build/paths.ts`, the Dockerfile and `.dockerignore` now point at what exists. Verified: `bun run gate` passed (check, docs drift, svelte-check with 0 errors, 121 test files and 1888 tests). `ui/src/sdk/client-docs.test.ts` now also compiles and svelte-checks every example in `apps/README.md`, its server and MCP modules included: it caught the README's MCP search tool ignoring its `query` (now fixed), and it fails when the client example loops over `things.data` again. New tests in `ui/src/sdk/server.test.ts` cover the doc's harness carrying the floor, a probed or declared `json: false` model being refused with zero transport calls, and a learned fact still running. Four of them fail against the old SDK. The new `ui/src/server/platform-agents.test.ts` holds the TS catalog to the Rust one and fails on the old list. Its run on a model with a probe `json: false` fact came back refused without touching the endpoint, while an untested model on the same endpoint tried it, and so did the old SDK on the same model. Playwright showed the README surface rendering both stored names, and the old snippet rendered none. Five secret-handle cases resolved or passed through verbatim exactly as mcp.md says: unrestricted, locked without the token, locked with it, a shared-key caller, and an ungranted agent.
