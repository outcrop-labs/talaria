- **`talaria dev --api-from-ci` runs the api binary CI built instead of compiling it, and a new worktree no longer seeds a Rust build cache unless `--seed` asks.** The flag downloads the `talaria-api-linux-x64-<sha>` artifact that ci.yml's api job uploads, keeps it in the git-ignored `api/.ci-bin/<sha12>/`, smoke-runs it, and starts it where `cargo run` used to start, with the same directory, environment and signal handling. It takes HEAD's own binary, or else the binary of the newest commit before HEAD, on its first-parent line, whose api is still HEAD's. That reaches an offload run made before a docs-only commit, and the base branch's last binary when the branch has not changed the api (a `testing` push builds the binary only when it moved the api). It stops at the first commit with another api, so a branch that changed the api never runs the code from before the change. "The api" is `api/` plus the files the binary compiles in from outside it, which is the planner's list in `scripts/surfaces.mjs`. Uncommitted api changes are refused, because no CI binary contains them. With no binary anywhere, the command says to run `bun run gate:remote --full` or open the pull request. Only an artifact from a run of this repository counts: a fork's pull request runs its own ci.yml here and could upload any file under that name, so a fork's artifact is never run. The artifact must also be for exactly that commit, and the download must match GitHub's sha256 digest and the zip's CRC. GitHub is read over REST with `gate:remote`'s token rules (`GH_TOKEN`, `GITHUB_TOKEN`, or gh's login), so a devbox needs no `gh`. A devbox whose glibc is older than CI's is told to use `cargo run` or the host. `--api-bin <path>` runs a binary you already have. `talaria worktree` now leaves `api/target` empty: `--seed` (or `--seed-from`, or `--desktop`) reflinks one for reproducing a CI failure with cargo, and `--no-seed` is accepted and does nothing. The worktree command's flags are now parsed at all. Before this, `talaria worktree demo --no-seed` cut a worktree from a ref named `--no-seed`.

  Verified: `bun run check` (the CLI reference regenerated by `bun run docs:api`), the cli typecheck, and `cd cli && bun test` (523 tests). `src/ci-artifact.test.ts` covers the zip reader on stored, deflated and upload-artifact-shaped archives, plus multi-entry, method and CRC refusals. It covers which artifact is trusted (a fork's run, another commit, an expired one), the download following its redirect without the token and checking the digest, the token order, the walk back to the last api change, the smoke verdicts, and the whole fetch against planted git and a fake GitHub. Each new flag is tested through the router.
