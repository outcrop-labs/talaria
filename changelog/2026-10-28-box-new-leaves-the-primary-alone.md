- **Fixed: `talaria box new` no longer recreates the owner's primary Postgres, a box made from a worktree's CLI no longer runs on that worktree's fleet, and `talaria cleanup` finds the app databases a gone worktree or box left running.** `box new` and `box start` bring the primary's services up with `--no-recreate`: rc changed Postgres's healthcheck, so the config hash of a checkout on rc no longer matched the running `talaria-postgres-dev` (started from main's files), and the plain `up -d` dry-ran as `Recreate`. The box's `ui/.env` now drops every line the box block writes, read from the block itself, and everything that names a worktree's stack. Before, the worktree's `TALARIA_FLEET_PROJECT` and `TALARIA_GATEWAY_SELF_URL` came first and won: the box's api rendered its agents into `talaria-wt-<name>-fleet` and pointed them at the worktree's app. `TALARIA_EMBED_URL` names the embeddings container `box new` started (the shell's `TALARIA_EMBED_CONTAINER`, when set). `talaria worktree` refuses an inherited `TALARIA_PG_CONTAINER` with the one predicate `box new`, `box seed` and `talaria dev` use, so it now also catches a name of a worktree's or a box's shape whose container is gone. The sweep lists a `talaria-appdb-*` container whose cluster is mounted from a sibling `talaria-<name>` directory that is gone (one still on disk keeps its databases, checkout or not), or from a box whose `box.env` is gone, and `--apply` removes the container (never the stop gate, never the data directory). The sweep also no longer cuts its own output at 64 KiB: it called `process.exit()` straight after writing, so on a host with many stacks a piped `talaria cleanup`, the stop gate's stderr and `--json` all ended at byte 65536. Verified: `bun run gate`. The 8 new cli tests fail on rc's code and pass here. A throwaway "primary" (its own project, container and port), started from main's compose files, was recreated by rc's `up -d` (new container id) and left running by this branch's (same id and start time); a stopped one was started in place and a missing one created. `docker compose --dry-run` against the owner's real stack reads `Recreate` with rc's argv and `Running` with this branch's, for postgres and embeddings. rc's `boxUiEnv` over this worktree's real `ui/.env` wrote `TALARIA_FLEET_PROJECT` and `TALARIA_GATEWAY_SELF_URL` twice and kept six worktree-only keys; this branch's writes each key once. The sweep found, by report and by its own executor, five app databases made with rc's `composeYaml`: the two whose owner was gone (a running one under a deleted worktree directory, a stopped one under a box without `box.env`) were listed and removed, and the three under a live box, a live checkout and an outside path stayed. rc's sweep listed none of them, and a unit test with a real temporary directory pins that a sibling still on disk with no `.git` keeps its database. On this host the report is 95,053 bytes: rc's sweep delivered 65,536 of them through a pipe, this one delivers all of them, and its 3.9 MB `--json` parses.
