- **Fixed: Stop now halts a completions-arm chat turn in the agent itself, not just the stream. A malformed id in a route path now answers 404 instead of a 500 or the database's own error text. Two smaller fixes: agent transport errors share one wording that never names the agent's address, and the abandoned-turn guard's log says whether a turn was interrupted mid-run or cancelled while still queued.** Before, `POST /api/conversations/{id}/stop` answered `hermes: false` for a turn on the completions arm (the chat default). The client hung up its copy of the stream, the server's drain kept reading, and the agent worked and spent until the end of a reply nobody wanted. While the drain holds the turn's request open, the completion id its stream names (`chatcmpl-…`) is also the turn's Hermes run id. So the drain now records it (talaria-chat-persist `open_completion`), and the stop posts `POST /v1/runs/{id}/stop` for it. That interrupts a running turn, or withdraws one still queued in its Hermes session. A stop Hermes cannot place yet is sent again within the control window. Hermes ends the stream with a `cancelled` finish, which the parser now reads the same way as a session's `run.cancelled`: the row lands `complete` with `stopped: true` and keeps the words streamed so far. Thirty-nine route methods that cast a path id with `$N::uuid` used to answer 500 for a malformed id (an admin passed every gate in front of the cast). Eight more passed the database's error text through as a 400: an agent's cron list, cron create and cron-job actions, its secret write, and its memory. Two answered 200 for an agent that cannot exist (its secrets list and delete), and the agent's Google connect would have answered 500 once Google is configured. All 50 now answer 404, the same as a well-formed id that names nothing. They are listed in the PR. The uuid shape check now lives in one place, `talaria_params::uuid_shaped`. It is Postgres' own uuid input rule, so the old `Uuid::parse_str` gates stop passing the `urn:uuid:` form the cast refuses. The two private copies (talaria-conversations' `uuid_shaped`, talaria-routes-comms' `could_be_uuid`) are gone. Six of them (`GET` and `POST /api/fleet/defs/{id}/mcp`, `PATCH /api/fleet/defs/{id}`, its `edit` and `rotate-key`, and `POST /api/fleet/agents/{id}/control`) were held back while their files belonged to #614. That PR has now landed, and they are gated too. The approval door and the abandoned-turn guard used to build their own agent transport errors. They now use `fleet_chat::transport_error`, so an `agent.approval_*` audit row or a stop refusal never names the container's dial URL. The Rust harness's `LedgerAttribution.tier` had no reader anywhere in api, ui, mcp, desktop, cli, mobile, scripts or the client apps, so it is gone. The guard logged a turn cancelled while queued as `(chatcmpl-…: stopped)`, because Hermes answers that stop with `null`. It now says *cancelled in the agent while still queued: it never ran*, or *interrupted in the agent while it ran* for a running turn.
