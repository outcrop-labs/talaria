- **Fixed: an app's grants belong to the repository installed under its slug, so a different repository installed under the same slug starts with no grants, and the harness docs' free probe now sees the harness's own model setting.** Uninstall used to leave every person's and team's grants on the app (`/x/<slug>`, `/x/<slug>/manage`) on their rows. A different repository installed later under the same slug, even after `keptData: "wipe"`, then inherited every one of them: its members reached the work and manage surfaces nobody had granted it, against "enabling one gives members nothing". Grants are named by slug alone, so they are now tied to the record of the repository that the slug's data directory already keeps (`source.json`, repository identity = host plus the owner/name path, compared without case). An uninstall that keeps the data keeps the grants with it. One that keeps no data (wiped, or the app never stored anything) removes them and their denials from users and teams. An install keeps them only when that record names its own repository, even when it wipes its own data. Another repository starts with none whether it adopts the data or wipes it, and so does any install of a slug whose grants no record vouches for. That covers grants an uninstall left behind before this release, so no migration is needed. Other apps' views, a slug that begins with this one's included, and core views are never touched.
