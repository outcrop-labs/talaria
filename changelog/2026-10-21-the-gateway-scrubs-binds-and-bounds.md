- **Fixed:** Four low-severity gateway findings from the 2026-10-20 audit. The one place an upstream body reaches a log line (`talaria-error`'s `log_upstream_error`, which the MCP gateway's relay, its notification stream and the LLM relay all go through) now scrubs it before the 500-char cap: `Bearer <token>`, `tlk_`/`tak_`/`sk-`-shaped keys, `"access_token": "…"`-style JSON fields (and `refresh_token`, `client_secret`, `api_key`, `authorization`, `password`, …) and `x-api-key: …`-style header echoes each become a `[redacted]` marker that keeps the prefix or the key name, so a 4xx that quotes the credential it refused no longer puts that credential in the log. The gateway binds an upstream session to the agent it was minted for: the `mcp-session-id` an `initialize` answer carries is recorded against the caller (Redis, `talaria:mcp-session:v1:<server>:<sid>`, 24 h, refreshed on use) and a later request presenting a session recorded for another agent is refused with JSON-RPC `-32602` ("this session belongs to another agent"; 403 on the GET stream) instead of relayed — before, the caller's session header was forwarded as-is, so two agents sharing an org credential could present each other's sessions; a session the gateway never saw passes through, and Redis out of reach fails open with a log line like every Redis-backed gate here. Every tool catalog an upstream answers is bounded before it is cached, on every path (hosted, package, Workbench): a tool name is capped at 200 UTF-16 units and an entry whose name is empty, missing or over the cap is dropped, a description is clipped to 300, and an `inputSchema` over 32 KiB is replaced by the permissive object schema plus `inputSchemaTruncated: true` — before, the package path stored names, descriptions and schemas at whatever size the upstream chose. The health pass's drift sentence names at most the first twenty tools a side and says "and N more". OAuth discovery refuses an endpoint that is not `https://` (token, registration, authorization, and the metadata documents on the way to them) with a sentence naming it, even on the server's own domain, except a loopback host admitted by name through `TALARIA_FETCH_ALLOW_HOSTS` (the e2e stub's `127.0.0.1`; the suite's stub serves https regardless). Verified: `cargo fmt`, `cargo clippy --tests -- -D warnings` and `cargo test` for `talaria-error` (the scrubber on a JWT bearer, an OAuth token document, a Talaria key in prose, an OpenAI key in a provider's sentence, a header echo, an escaped quote, a body cut mid-token, and a set of plain bodies — a `WWW-Authenticate` challenge, a provider's prose, multi-byte text — that must pass untouched), `talaria-routes-fleet` (`mcp_gw_server`: the pure binding rule and the refusal's framing), `talaria-mcp` (the catalog bound's drop/clip/mark set and the twenty-name drift line), `talaria-mcp-oauth` (plain http refused on-domain, every loopback spelling admitted, a LAN host admitted by the guard still refused); `bun run check`.
