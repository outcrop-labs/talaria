- **The ticket modal reads like a ticket again.** It was 896px wide — narrower than any page surface in the app — and spent 240px of that on a properties rail, leaving ~656px for a title, a description, a discussion and five tabs. It is now the app's own page measure (`--page-width`, 1152px) with a 280px rail, so the content column goes from ~656px to ~880px without inventing a new width. The header is real chrome now: ticket ref, a status dot and label, the sign-off chip, who opened it, then the watch eye, copy link and close — and **the close button lives in the header**, where it used to be the first child of the rail's own scroll box, so scrolling the properties carried the way out of the dialog off the top of the screen. The rail is grouped instead of a flat run of fifteen labelled fields: identity at the top with no heading, then Planning, Relationships, Classification, Spend, People and the timestamps, each behind a hairline (new `PropGroup`), so a field has a neighbourhood rather than a position in a list.

  **The work log stopped squeezing the view.** Every run a ticket had ever seen lived in a 144px-capped scroll box stacked above the description, sharing that budget with the review gate, the workbench plan gate and the live ticker. So the moment an agent started working, the pane a reader actually came for got compressed — worst on a short window, where the description's own 9rem minimum meant the discussion was what gave way. The split is now by urgency, not topic: only things wanting a decision *now* sit above the description (review gate, plan approval, live session — never more than a couple), and the record moved to a new **Work** tab (`TicketWorkTab`) with the run log, the review history and a zero state of its own. The description's clamp came down to `6rem–16vh–12rem` for the same reason — every band above the tab pane is `shrink-0`, so each floor is taken straight out of the pane's budget, and long prose has Expand anyway.

  **And it works on a small window.** The rail was `w-60 shrink-0`, so a narrow viewport had it eating the content it was describing. Below `lg` the properties are now a slide-over drawer opened from a header control; at `lg` and up they are the side column as before. Both render the *same* snippet, so the two cannot drift, and `lg:hidden` on the overlay means widening the window just reveals the column — no resize listener, no state to reconcile. Escape is layered to match: with the drawer open it closes the drawer, and only closes the ticket once the drawer is shut (a capture-phase listener ahead of Modal's own), because losing the whole ticket to the key that should dismiss the panel you just opened is the wrong answer. Tabs renamed Attachments → Files, and Work sits second.

  The attention zone keeps a ceiling of its own (`min(38vh,17rem)`, scrolling past it) for one reason: `WorkbenchJobsStrip` lists every live job, and a ticket carrying several would push the description and the pane down — the same squeeze in different clothes. Unlike the 144px cap it replaces, this one is generous and usually unspent, because the run log no longer lives in it.
