- **Fixed:** A workchain step whose predecessor is still open is no longer dispatched to its agent, and the dead mission-control heartbeat contract is gone. The only code that kept an agent off a blocked step was the heartbeat's `assigned_work`, and nothing called the heartbeat: the `plugin/talaria` plugin that would have was mounted nowhere. So a blocked step sitting in a pickup column with an agent assigned got a work session while the step before it was still live. Now `maybe_dispatch_ticket` asks the chain order (`talaria_tasks::workchain_blocked`, over `talaria_workchains::chain_readiness`) once per ticket before any per-agent side effect. The sixty-second sweep asks it once per pass and logs held steps as `waiting on an earlier workchain step` instead of counting them as re-offered. The work-session loop asks the new `agent_work_refusal` on every turn, so a session whose predecessor a person reopens stops with "agents cannot work this ticket yet: an earlier step of its workchain is still open". A sign-off that makes successors ready offers each one to dispatch straight away, rather than waiting up to a minute for the sweep. Writes are not gated: agents still triage, comment on and report against a waiting step.
