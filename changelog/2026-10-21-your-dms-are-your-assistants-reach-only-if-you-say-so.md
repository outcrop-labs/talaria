- **Changed:** A personal assistant used to read and post in its owner's human↔human direct messages as part of the owner's view, with no way to say otherwise. Settings → Assistant now has **Your DMs** — **None**, **Read**, or **Read & post** — stored per owner (it outlives the assistant's handle, model and container) and honoured at both doors: the assistant's channel listing leaves DMs out at None, and the access predicate (`agent_may_access_channel`, which now takes the intent) refuses a read below Read and a post or reaction below Read & post. Channels and relays follow the owner's membership as before. The default is **Read & post**, so nothing changes for an existing owner until they choose. `GET/PATCH /api/me/assistant` carry it as `dmAccess` (`none` | `read` | `read-write`); a patch that carries only it lands without a new agent version or a restart. Verified: `cargo clippy -p talaria-users -p talaria-channels -p talaria-routes-comms -p talaria-routes-integrations --tests -- -D warnings` clean; `cargo test -p talaria-users -p talaria-channels` (the three-way predicate is unit-tested at every kind × intent); `cd ui && bun run typecheck`; `bun run check`.
