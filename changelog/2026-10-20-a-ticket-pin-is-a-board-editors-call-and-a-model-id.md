- **Fixed:** Any signed-in user could re-point another team's ticket onto a particular person's coding subscription, list which accounts (emails) sit behind agents on boards they could not see, and — because the pinned `model` went onto the harness's invocation line verbatim — put a shell command into a Developer Agent's sandbox. The ticket coding-pin routes (`GET`/`PUT`/`DELETE /api/workbench/coding/pin/{taskId}`) now require `can_edit` on the ticket's board, the same gate the human job route puts on approving a plan, and answer 404 for a ticket that is not there. A pinned model, and every per-role pick on an agent's coding plans, must fit the model-id grammar `^[A-Za-z0-9][A-Za-z0-9._:/-]{0,199}$` (400 otherwise). Independently of that, every value slotted into an invocation line — the `--model` argument, the session dir, the inline `PI_SMOL_MODEL`/`PI_SLOW_MODEL`/`PI_PLAN_MODEL` assignments — is now shell-quoted (`sh_quote`: the model vocabulary passes through bare, anything else is single-quoted), so a value that gets in some other way is one word, not a command. The sandbox's `OPENAI_API_KEY` is `${LLM_WORKBENCH_API_KEY}` alone; the `:-${LLM_API_KEY}` fallback that let model-authored code read the personas' fleet-wide, unmetered key out of its own environment is gone (an operator on a raw upstream sets `LLM_WORKBENCH_API_KEY` explicitly). Verified: `talaria-coding-accounts`, `talaria-workbench-harnesses` and `talaria-routes-workbench` unit tests — the grammar's accept/reject table, the hostile `x; curl … | sh; #` model arg landing as one quoted word on both the `--model` line and the role env prefix, and the env carrying no `LLM_API_KEY` — fmt and clippy `-D warnings` clean on all three.
