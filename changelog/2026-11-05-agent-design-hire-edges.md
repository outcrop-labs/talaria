- **Fixed: an agent design being hired can no longer come back twice, nag from the bell, or turn into a manual copy in another tab.** Each write to a design held for a hire is now a compare-and-set on the hold as it was read. That covers marking it returned, using it up, following the hiring strip's Retry, dismissing it, and handing it back into New agent. When two reads settle one failed hire at the same moment, or a read races Retry, the design ends up in exactly one place: never both back in New agent and still waiting, and never handed back over a retry that is making the agent. The "The hire of <name> did not finish" row is filed once per hold, so reading it no longer files it again with another toast or push. When a design leaves New agent for a hire from another tab, the modal open on it resets to an empty describe step and says "<name> is being hired from another tab" instead of keeping its fields, where the next keystroke would have saved them as a manual copy. A conflict that finds no design resets the same way. Smaller edges:
  - A bell row about a design that is gone, expired or ended elsewhere, is marked read.
  - **Discard it** finds a waiting design even if it moved into New agent in the same moment, and a failure to discard is shown.
  - A hire stopped between creating the agent and checkpointing it counts as having created it, because the agent is under the hirer's management.
  - Editing a handed-back design ends its link to the failed hire, so a later Retry of that hire does not use up the edited design.

  Verified: against this worktree's Postgres and Redis, `cargo test -p talaria-agent-design --lib -- --include-ignored` passes 40 tests. Four live tests are new. `design_live_two_reads_settle_one_failure_once` runs two reads at once, over five rounds, and the design lands in New agent and nowhere else, with no "waits" row about it. `design_live_a_read_racing_the_retry_follow_cannot_undo_it` runs a read and the Retry follow at once, over five rounds, and the design ends on the retry and is used up when it finishes. `design_live_the_waiting_bell_row_is_filed_once` checks that the row is filed once, unread, and that after it is read three more reads file nothing. `design_live_a_bell_row_about_a_design_gone_is_read` covers the expired design's row. The ui tests pin the reset helper and the modal's reset wiring.
