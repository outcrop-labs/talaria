- **A run now knows which attempt it is, and each attempt has its own workspace.** Runs gain `lineage_id`, `attempt_no`, `rewound_from_run_id` and `rewound_from_seq`, and a run nobody rewound reads as attempt 1 of its own lineage. `GET /api/tasks/{id}/work-sessions` returns those fields on each session, groups sessions in a new `lineages` list, and adds `outside` with what a run did beyond its workspace: tokens, pushes and pull requests. `workbench_jobs.run_id` names the run that owns a job. `start_job` gives a rewind attempt the job its rewind allocated, ahead of the one-live-job refusal, and moves the job it replaced to a new `superseded` status. `finish_job` and `prepare_env` refuse a superseded job with the current job's id, and the pre-push check declines a push to its branch. The sweep keeps a superseded job's workdir while a `run_checkpoints` row names it. Ordinary re-dispatch and revise rounds behave as before. A work session's spend now carries its run in `usage_events.ref_id`, where it used to repeat the ticket id. An agent that spends all 25 sessions on a ticket now says so on the ticket, once, as well as in the log. Rewinding itself ships later; nothing in the app starts a rewind yet.
