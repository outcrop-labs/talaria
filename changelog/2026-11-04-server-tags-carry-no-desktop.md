- **Server tags no longer build or attach Desktop installers.** A `vX.Y.Z` or `vX.Y.Z-rc.N` tag used to call `desktop-package.yml` and attach installers stamped with the server version. A Desktop numbered 0.13.0 beside `desktop-v0.12.0` would never have been offered an update until Desktop passed 0.13. Talaria Desktop now ships only as `desktop-vX.Y.Z` releases, which `desktop-package.yml` mints on a main push or a `publish=true` dispatch. `release.yml` drops its `desktop-package` job and nothing else changes: the image, api package and GitHub Release are untouched, and every `v*` release stays `--latest=false`. `omapak-submit.yml` now submits only `desktop-v*` tags. RELEASING.md, the cut-release skill, docs/DESKTOP.md, docs/BRANCHES.md, docs/MOBILE.md and DEVELOPERS.md say the same. Verified by reading: nothing in `release.yml` needed the removed job, its SHA256SUMS and `latest.json` were produced only inside `desktop-package.yml`, and that workflow's main-push and dispatch triggers never depended on the `workflow_call`. `bun run check` passes, including `release-latest-is-the-desktop-feed`. The release workflow itself was not run.
