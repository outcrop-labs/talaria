- **New: the workbench works repositories on the git hosts an operator chooses — GitHub (github.com or an Enterprise Server) or Forgejo / Gitea — instead of one GitHub connection.** Admin → **Git hosts** (a new tab; the GitHub panel left Admin → Organization) lists each host as a card: its live status, **Test connection** (who the connection acts as, which repos it reaches), the orgs agents may request repos in, and its connection — a GitHub App or access token for GitHub, sealed on the host's row as before; a **workspace secret** (Spendable at the host, no use limit) holding a token for Forgejo. Behind it: a `GitHost` interface every caller now talks to (`talaria-git-host-types`), GitHub as its first adapter (`talaria-github`, now connection-scoped, so an Enterprise Server is a second row) and Forgejo as its second (`talaria-forgejo`), and the registry (`talaria-git-hosts`: the `git_hosts` table, grants, branch rules, PR bases, the sandbox's credential) with `/api/workbench/git-hosts`, `/{id}` and `/{id}/test` (admin, audited as `workbench.git_host_*`) replacing `/api/workbench/github`. Every workbench row that names a repo names its host (`host_id` on `workbench_repos`, `workbench_repo_flow`, `workbench_jobs`, `workbench_repo_requests`, `app_install_requests`), and `plugins.git_host_id` references a real host. **Existing installs need no action:** the migration moves the one GitHub connection into a `github` host row (and deletes `app_settings.github_config`, so the credential lives in one place) and backfills every row to it; a fresh install gets that row unconfigured. The agents' tools gain an optional `host` (`start_job`, `request_repo`, `request_app_install`) needed only when a repo or org is on two hosts; `list_repos` adds `grants: [{host, repo}]`, `doctor` checks every host the agent's repos live on and answers `repoCreation.hosts`, and `pr_status`, `plugin_status` and the upkeep sweep read each PR from its own host in one shape. The sandbox's credential helper and pre-push hook resolve the host by the origin git names (the hook now sends it). App install and update fetch a repo on any registered host with that host's read login.
