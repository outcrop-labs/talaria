- **Fixed:** A browsing agent could not browse. The toolset switch, the uploads door and the screenshot chip from "an agent can show you the page it saw" were right, but the premise under the roll-time install was not: the hermes-agent image already ships Chromium under its own `PLAYWRIGHT_BROWSERS_PATH` (in the image layer, which a roll keeps because a roll is the image), and `hermes tools post-setup agent_browser` inside Docker does not download a browser at all — it installs the browser-use CLI onto the state volume and prints a pull hint when it cannot see Chromium. The renderer's override of `PLAYWRIGHT_BROWSERS_PATH` to an empty directory on the volume therefore hid the bundled browser, and every browser turn failed with "Chromium is missing". The override is gone; the post-health setup keeps running once per volume behind a marker (`/opt/data/.talaria-browser-setup`), for the CLI it does install, and `TALARIA_BROWSER_INSTALL=off` still skips it. The Developer Agent overlay's own Playwright path (its Oh My Pi harness dir) is untouched. Verified: `talaria-fleet-render` 23 and `talaria-fleet-docker` 5 unit tests, clippy clean on the four fleet crates; live on the worktree stack, the first run reproduced the failure (marker written, `/opt/data/.playwright` empty, the agent reporting Chromium missing while `/opt/hermes/.playwright/chromium_headless_shell-1243` sat in the image), and after the fix the rerun's result is recorded in the pull request.
