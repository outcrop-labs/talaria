- **Fixed:** Four knowledge-base doors stopped answering with rows or placements their caller should not have. `create_kb_space`'s find-or-create matches only a space the agent could have listed — the same read gate as `GET /api/kb/spaces` — and a name collision with a space it cannot read is a 409 with no row, where it used to hand back a private space's landing page and owner. A `parentId` on doc create and on `PUT /api/kb/docs/{id}` passes the two checks the move route has always run — the parent is a doc of the same space, and not the doc itself or one of its descendants — so a doc can no longer be filed under itself (a loop for every tree builder) or into another space's tree. `GET /api/kb/public/{slug}` serves on the doc's EFFECTIVE visibility, inherited from its folder like every other read, so a doc inside a space made private is no longer public by its old slug. `GET /api/kb/search` runs its ACL over a 300-row ranked page instead of 60 before truncating to 20, so a member whose readable hits rank below a wall of private ones still gets them. A draft in a space bound to a custom brain no longer grounds that brain until a human marks it official — the gate the org brain always had; an owner's explicit per-doc routing still indexes as written. `DELETE /api/kb/docs/{id}` answers 404, not 500, to a non-uuid id. Verified: `cargo clippy -p talaria-kb -p talaria-retrieval-sources -p talaria-routes-knowledge -- -D warnings` clean; `cargo test` on the same crates; `bun run check`.
