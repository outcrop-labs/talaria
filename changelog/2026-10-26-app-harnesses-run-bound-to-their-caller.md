- **Changed: an app runs its harnesses through `ctx.harness`, a runner the host binds to the caller it authenticated, and the free `runHarness` no longer takes `deps`.** `ctx.harness.run(def, input, options)` and `ctx.harness.stream(def, input, { onDelta })` are on the request context and the MCP tool context, built by one factory (`appHarnessRunner`, `ui/src/server/app-harness-runner.ts`) that the trigger context will call too. The host now decides what the app used to: every run is recorded as `app:<slug>:<harnessId>` and booked to ledger source `app` (new in TS and as `LedgerSource::App` in Rust; gateway rows carry it, and now the run's `refId`/`taskId` too when they are UUIDs), the definition is held to the platform's harness rules (the JSON floor included, even for one built without `defineHarness`), and nothing an app passes reaches the guard, the transport or the recorders. **Pinning is gated:** from a request, an agent only if the signed-in member may use it (the api's `usable_agent_gate`, asked through `GET /api/agents` with their session) and a gateway model only if the member model allowlist opens it to them; from an MCP tool, only the calling agent, and only when it called on its own key; from a trigger, no agent. A refused run makes no model call and follows the harness's `onFailure`. **Breaking for app tests:** `deps` is gone from the SDK's `RunContext` and is dropped, with a warning, if passed anyway; the free `runHarness` also warns when it pins an agent, since it checks nothing. Test a harness offline with the new `runHarnessOffline` in `@talaria/sdk/testing` (scripted replies, capabilities on record, every request returned). Verified: `bun run gate`, the new `app-harness-runner.test.ts` (stamping, ledger, slot, deps ignored, JSON floor, rule refusal, `onFailure: 'throw'`, every pin case for request, MCP and trigger, streaming, signals, the free runner's warnings), the SDK doc tests moved onto `runHarnessOffline`, and `cargo test`/clippy on the touched crates. Live on a worktree stack with a scratch app and a mock OpenAI-compatible endpoint registered through the gateway: runs and streams came back booked `app:w4probe:w4probe:triage`, source `app`, with the ticket id on the row and a non-UUID `refId` dropped with a warning; a member pinning an agent they cannot see, or a model outside the allowlist, was refused with the sentence above and no call; their usable agent and an allowed model passed; an admin's pin passed; an agent calling the app's MCP tool on its own key ran the harness, and its pin of another agent was refused; the free runner logged both warnings.
