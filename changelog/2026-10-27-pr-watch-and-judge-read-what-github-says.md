- **The PR tools read what GitHub says: judge-pr sees a filled PR body as filled, and pr-watch counts only the latest run of each check, on the commit you pushed, once CI has run for it.** Before this, the judge asked "no Verified section filled in" (and "names no changelog entry") on every pull request whose body came from the template, filled or not. Its section reader used `\s*$` under the `m` flag, which matched the end of the heading line, so every section read as empty. The watcher had two faults. It reported `red` whenever a body edit right after `gh pr create` had cancelled a `judge` run and re-run it. It could also report `green` straight after a push, either on a rollup that held only `judge` or on the previous head's finished checks.
  - **judge-pr.** The reader is now `scripts/pr-body.mjs`, a line walk that respects code fences and HTML comments and handles CRLF bodies. A section counts as filled only by what it holds beyond the template's own lines for that section (the `- **Gate:**` labels, the two paragraphs and the code block). Template-only answers stay unfilled. The no-entry hint now points at `changelog/` files instead of CHANGELOG.md.
  - **pr-watch.** It now keeps the latest check per workflow and name, chosen by job id and then by start time; a queued re-run counts as newer than the run it replaces. A cancelled run that is itself the latest is still red. Green also needs three things. First, the PR's head must be the pushed commit: this checkout's HEAD, pushed, when it is on the PR's branch, or the branch's head on GitHub from anywhere else. A mismatch is pending, and it is checked before red and conflict. Second, there must be a `CI` workflow run (ci.yml's `name:`) for that head. Third, every workflow run on the head must be finished. A run that failed with no job in the rollup, such as a startup failure, is red. The exit contract and its tokens are unchanged.
