- **Changed:** `create_google_doc` and `create_google_folder` stay immediate in the account's own Drive or inside a folder the agent created, and now queue for approval (`doc_create` / `drive_folder_create`, executed at approve time and recorded as the agent's) when the caller names any other parent folder — a file placed in a shared folder inherits that folder's sharing, which is a disclosure a person decides. An agent's standing to replace the whole body of a doc it created without a card ends when someone else edits it: the route asks Drive for the last modifier before an immediate full-body replace, and a doc last changed by anyone other than the token holder queues like a human-owned doc from then on (an append stays immediate). The agent arm of `export_to_google_doc` writes the same `artifact.export_google` audit row the human arm does, with the identity it acted as and the file it made. `create_google_meeting` and `update_google_event` validate like `draft_calendar_event`: attendees are checked addresses capped at 50, the agenda is bounded, and `start` / `end` must be a date or an RFC 3339 timestamp. `read_drive_file` and `import_drive_file` stop at the upload limit (25 MiB), on `Content-Length` and again on the streamed bytes. Google token refresh, revoke, exchange and userinfo calls carry a 60-second request timeout. Verified: `talaria-google-docs`, `talaria-google-drive`, `talaria-google-pending`, `talaria-routes-integrations`, `talaria-routes-knowledge`, `talaria-google-connections`, `talaria-google-org` and `talaria-google-oauth` unit tests, `cargo fmt` and `cargo clippy -D warnings` on each, and `bun run check`. The Drive round-trips themselves need a consented Google account and were not exercised live in this change.
