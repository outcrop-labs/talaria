- **Fixed: an agent that hits its LLM budget now fails the turn in seconds and says when the budget reopens. Before, it waited ten minutes and then said "resets in ~5 min" about a 24-hour window. Agent transport errors no longer show the agent's internal address, and the gateway's dead agent-reported spend writer is gone.** A budget refusal now carries the real resume time: the moment enough of the rolling window's oldest spend ages out to bring the rest under the cap, if nothing more is spent. It goes out as `error.resets_at` (epoch seconds) and as the same minute, in UTC, in the message. An agent's own key gets no `Retry-After` with it. Hermes honours that header with waits of up to 600 s, so the old `Retry-After: 300` held the turn for two 300-second waits. Operator and app keys keep `Retry-After: 300` and also get `resets_at`. A failed call to an agent's API server (the Crons tab of a stopped agent, a steer, a stop, a turn whose reply broke after it was sent, a refused-turn withdrawal) now reads like "error sending request: Connection refused (os error 111)". reqwest's own text was "error sending request for url (http://…:<port>/…)": it showed the container's dial address and left out the cause. The full error, address included, still goes to the server log. `record_usage`, `UsageInput`, `classify_agent` and `classify_model` had no callers after the relay took over metering, so they are deleted. `nudge_if_unpriced` stays, because the relay's writer still uses it. The harness's TypeScript comments (`run.ts`, `transport.ts`, `run.test.ts`) no longer explain the tier slot by the TS ledger writer (`recordUsage`, `classifyAgent`), which was deleted with `ui/src/server/usage.ts`. They now say what is true: the relay prices the call it routed, books a tier's turn under its base agent (`persona_base`), and gets only `refId` and `taskId` from the harness. The harness's ledger attribution (`LedgerAttribution`, on every `TransportRequest`) now holds only those two refs. Its `agentModel`, `tier` and `source` rode on every request, but nothing in ui, mcp, api, desktop or the apps read them, so they are removed, along with the unused `ledgerOf`. `RunLedger.source` stays on the SDK type, marked deprecated and read by nothing, because apps written before `ctx.harness` still pass `ledger: { source: 'chat' }` to the free `runHarness`. The app runner no longer stamps it: the relay books every call on an app's key under source `app` anyway.
