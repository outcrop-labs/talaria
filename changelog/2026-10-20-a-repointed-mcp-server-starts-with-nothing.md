- **Fixed:** Editing an MCP server's URL kept everything the old host had been trusted with. The org headers, the stored OAuth discovery and every connected account's token stayed on the row, and the next gateway call — or the hourly health pass — sent them to the new host. A URL whose host or port moves now drops all of it: every `mcp_oauth_tokens` row (the org's and each person's), the in-flight OAuth states and reconnect flags, the stored discovery, and the sealed org headers unless the same request sets new ones; the catalog is cleared as before and the route then asks the new host what auth it wants and what tools it has, inline, so the server card and the "drop missing tools" offer never read an empty catalog as "all missing". A `timeoutSecs` change now rolls the server's carriers too — it rides config.yaml, and a running Hermes only reads it at start. Verified: `cargo test -p talaria-mcp` (the host-change rule has a unit test: path, scheme, case and default port are the same host; host, subdomain and port are not), `cargo test -p talaria-routes-fleet`, clippy `-D warnings` on both, `bun run check`. The DB side of the drop has no unit test — the crate's suites are pure (RUST-MIGRATION rule 9).
