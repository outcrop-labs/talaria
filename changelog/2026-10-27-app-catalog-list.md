- **New: the app marketplace reads a list of catalogs the operator fills, instead of one URL that defaulted to Outcrop's registry.** Manage → Apps → Discover gains a **Catalogs** panel — add (name + https URL), rename, change the URL, turn off, move up or down, remove — backed by a new `app_catalogs` table and `/api/admin/apps/catalogs` (GET for anyone with the Apps view; POST, PUT `{id,…}` or `{order}`, and DELETE admin-only and audited as `app.catalog-add|edit|reorder|remove`). Every enabled catalog is read at once through the SSRF guard; each app card names the catalog it came from, a slug two catalogs list is shown from the higher one (the lower one says it was shadowed), and a catalog that cannot be read shows its own error while the rest still list their apps. Adding a catalog reads it once and says how many apps it lists or why it could not be read. **The default is now a migration, not a fallback:** upgrading moves the old `apps_catalog_url` value in as the first catalog, or seeds Outcrop's registry when none was set, and no code ever re-adds it — an operator who removes every catalog gets an empty Discover tab that says no catalog is configured, and install from Git keeps working. `GET /api/admin/apps?catalog=1` now answers `catalog: {apps, catalogs}` (each app tagged `catalog: {id, name}`), and the `catalogUrl` field and `PUT /api/admin/apps {catalogUrl}` are gone (nothing else read them). Catalog URLs are https-only; a dev stack with `TALARIA_APPS_LOCAL_SOURCES=1` may also list `http://` to loopback (the SSRF guard still wants the host in `TALARIA_FETCH_ALLOW_HOSTS`). Verified: Rust tests for URL and name validation, index admission, the merge (list order, catalog tags, one card per slug, shadowed slugs, per-catalog errors, off catalogs not read) and two loopback catalogs read through the guard; an ignored live test of add/duplicate/edit/reorder/remove against a migrated database, ending in an empty list that stays empty; the migration on a fresh database (one Outcrop row) and on an upgrade from rc's schema with a custom `apps_catalog_url` (one row, that URL); and live on a worktree stack (whose database migrated from an older schema to one Outcrop row): every route over curl with minted admin and Apps-view member sessions (a member reads and is refused writes; a non-https or credentialed URL is a 400, a duplicate a 409, a partial order a 400), two loopback catalogs plus a 404 one merged on the Discover tab with a slug shown once and the error on its own row, a reorder moving that slug to the other catalog, an add and a remove through the panel in Playwright, the `app.catalog-*` audit rows, and screenshots of the tab at 1440 and 390 with no sideways scroll.
