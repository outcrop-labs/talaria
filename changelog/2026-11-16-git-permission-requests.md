- **A Developer agent whose GitHub token lacks a permission now asks for it with `request_git_permission`, and an admin approves or denies it in Admin → Git hosts; approval adds the permission to the agent's set on that host.** The workbench verb takes `{repo, host?, permissions: [{name, level}], why, taskId?}`. It refuses only a key or level GitHub's App catalog does not know, a repo the agent is not granted, and a host whose own token decides (a PAT or Forgejo host). There is no cooldown, no cap on open requests, and no key the agent may not ask for. Each permission is filed in `workbench_permission_requests` as `pending`, or `awaiting_github` when the agent's set already carries it and only the installation lacks it. One the set carries and the installation holds is answered as carried, and nothing is filed. A partial unique index keeps one open request per agent, host and permission. Asking again is never refused: it appends the new words and evidence, keeping the newest 4000 characters and the newest 20 raises' evidence, and raises the level when more is asked. One that waited on GitHub goes back to `pending` when the agent's set no longer carries it. The request is a line on the ticket it was asked from and keeps that ticket; a repeat ask from another ticket says there that the decision lands on the first, and the agent's answer names the ticket, or says only `list_repos` will show it when none was named. It is also a ninth approval kind in the census, `git_permission`: an admin's to decide, bounded to the ticket's board, announced when raised, and open while pending or waiting on GitHub. `GET /api/workbench/permission-requests` (admin, by session) lists the open requests, with the agent's words shown only to an admin who may read that board; any other admin sees only that one waits. `PUT {id, action: approve|deny, level, note?}` decides one. `level` is the level the admin was shown and is required to approve: if the agent asked for more since, the answer is a 409, never a grant nobody confirmed. Approve locks the agent's grants on the host (a 409 when it holds none), merges the key at that level into its set from the default when it had none, and writes `workbench.github_permission_grant`, all in one transaction. The request becomes `granted` when the installation that mints the repo's token holds the permission, and `awaiting_github` when it does not. Deny writes `workbench.github_permission_deny`; on a request waiting on GitHub it closes it as `withdrawn`, with a note telling the agent the permission stays in its set. Either way the ticket gets a line with the note, and the agent's managers get a `git_permission_decided` notice (class `work_complete`) that never carries the agent's words. Every holdings refresh grants a request waiting on GitHub once the installation holds it, or withdraws it when an admin took the permission back out of the set first, each with its audit row, line and notice. A grant write that leaves the agent no repo on a host withdraws its open requests there in the same transaction. Admin → Git hosts gains the section: each request with the agent, the permission, whether the installation holds it (and its settings page when not), "the agent says" as plain text, the evidence, the ticket and its column, a note, Approve (its confirmation names every repo the approval applies to) and Deny, or Close for one waiting on GitHub. "Post my note in the ticket thread", checked by default, sends the decider's own message to the ticket's room through the chat door. A Restart button, shown when the ticket is Blocked, moves it with the board's own move. `list_repos` gains `permissionRequests`: every open request however old, and every one decided in the last 30 days. The toolkit, workbench-driving and github skills, `report_problem`'s description, docs/WORKBENCH.md, docs/MCP.md and docs/PERMISSIONS.md send a missing GitHub permission to `request_git_permission` instead of `report_problem` or `report_gap`. Also fixed: the `repo_request` approval linked to Admin → Agents and now links to Admin → Git hosts, and the stall report no longer tells admins to decide admin-only queues in Admin → Agents.
