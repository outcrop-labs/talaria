- **Fixed:** The MCP gateway's relay to a registered upstream now goes out on a client that never follows a redirect and re-checks the address it dials at connect time, and any 3xx from the upstream is answered as a 502 ("upstream answered with a redirect, which the gateway does not follow") instead of being followed. Before, the hop used the first-party client, which followed up to ten redirects outside the SSRF guard — so a compromised upstream could bounce the api onto a cloud metadata address or a loopback port, with the org's API-key headers attached, and have the answer relayed into the model's context. The builtin toolkit and package containers keep the first-party client (loopback and container DNS are what the guard refuses); the relay still streams and never buffers. The gateway also forwards only a body that parsed: every parse failure — an empty body, a bare word, SSE framing, a body a UTF-8 byte-order mark made unparseable — is answered with JSON-RPC `-32700` over HTTP 200, and a leading BOM is stripped before parsing so a well-formed body behind one still works. Before, only a brace-led failure was refused and everything else was forwarded verbatim with the credentials attached and without the tool gate, the spend boundary or the `tools/list` filter running on it. The `tools/list` filter now reads multi-line `data:` frames (an SSE event's data lines are joined before parsing), so a server that splits one message over several lines no longer leaks its unfiltered catalog. The in-process dispatchers (builtin, Workbench, app servers) negotiate the MCP protocol revision on `initialize` the way the not-connected answer already did, instead of echoing whatever the client sent. Verified: `cargo test -p talaria-safe-fetch` (9 passed; a loopback listener answering 302 gets exactly one request and the 302 comes back with its Location); `cargo test -p talaria-routes-fleet --lib mcp_gw_server` (the parse-failure set, the BOM strip, the multi-line SSE filter); `cargo test -p talaria-mcp-jsonrpc` and `-p talaria-mcp --lib not_connected` (a revision nobody speaks, or an empty one, is negotiated down); clippy `-D warnings` on each; `bun run check` (its invariant pass reports three failures, all in files this change does not touch: a hand-unwrapped secretbox in `fleet_defs_id_rotate_key.rs`, an off-board status literal in `mcp/src/index.ts`, and duplicate `too_many_requests`/`agent_brake` bodies in the knowledge and comms route crates).
