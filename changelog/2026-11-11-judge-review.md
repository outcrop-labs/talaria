- **Every pull request now gets a model's review against this repository's rules, run from the protected branch, and the diff judge stops raising what never mattered.** `judge (review)` (`.github/workflows/judge-review.yml`, `scripts/judge-review.mjs`) sends a change to `z-ai/glm-5.3-flash` on OpenRouter — pinned once in the script, overridable with the `JUDGE_REVIEW_MODEL` variable — with a dedicated, spend-capped `JUDGE_OPENROUTER_API_KEY`, never the app's `OPENROUTER_API_KEY`. It reads the trusted branch's rules for the paths touched (AGENTS.md and CONTRIBUTING.md always; the API, UI, Rust-migration or update conventions as relevant), descriptive reference docs labelled as never a finding by themselves, the body and changelog entry, judge-pr's findings, the previous review and its answers, the diff at `-U25`, the full head files, and computed cross-references: the callers of what the diff adds or stops calling, and the importers of changed modules, all inside a 300k-token budget trimmed in a fixed order. Code keeps only findings whose quote is verbatim and unique in the head, in a changed file, near a change; it drops low confidence and caps claim-vs-code, test-gap, docs-drift and performance at minor. Every surviving blocker or major then gets a blind second reading that sees only the file, line, title and quoted lines and must name the triggering input and trace it; a would-be gate finding gets two. At most three confirmed findings become line annotations and the only comment the review creates; unconfirmed ones sit collapsed in an existing comment; minors, the verification gap and the cost are in the job summary.

  It never fails and never approves: a missing key, a fork, a draft, a lane PR, a provider error, a timeout, bad output, the $0.25 per-run ceiling or a crash is a green job with a `not reviewed: <reason>` notice. The job runs every script from the trusted tree (testing, rc or main) and reads the pull request only as git objects; the key is in one step that runs only that tree's reviewer, the comment comes from a job with no checkout, and until the trusted branch has a reviewer a separate keyless `judge (review) bootstrap` job dry-runs the head's copy — never in the job that names the key, because a runner holds every secret its job references from the first step on. `bun run gate:remote` pushes are reviewed too (`offload / judge (review)`) and remote-gate prints the findings without changing its exit; pr-watch lists them under its proof line; `bun run judge` runs judge-pr and the review locally (`--dry-run` needs no key). Report mode is the default and holds nobody. Only once a prospective, person-graded bar passes (150 live reviews, ≥ 80% would-gate precision, ≤ 3% of PRs falsely held) may the owner set `JUDGE_REVIEW_GATE=blockers`, and then pr-watch holds an agent's done (`pr-watch: review`) on an unanswered, doubly confirmed blocker until it is fixed or answered with `judge-review answer <id>: <why>`; a person's merge is never held. `judge-calibrate.yml` scores the reviewer on 22 known pull requests (dev defects, held-out defects, clean ones) and runs a weekly canary.

  `judge (standards)` keeps the exact rules — branch flow, the changelog entry (RELEASING.md and test-only diffs no longer need one, and a roll is exempt), the do-not-touch trees, skill shape, the body's asks, and a new ask for a calibration scorecard when the reviewer changes — and drops commit-subject, claim-misses-surface, cli-suite-not-covered-by-verify, no-test, product-skills and generated-drift/changed: over #669–#725 it raised 59 findings and none was a defect. It no longer dies of ENOBUFS on a roll's CHANGELOG.md diff, judges the PR head sha, reads diffs with `--text --no-textconv --no-ext-diff`, reads a skill at the head rather than the working tree, reports a crash as a warning rather than a finding, prints the `must` report in the failing step, and runs the trusted branch's copy in a read-only job beside a comment job with no checkout.
