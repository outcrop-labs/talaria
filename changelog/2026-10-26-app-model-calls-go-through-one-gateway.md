- **Changed: every model call an app makes goes through the Talaria gateway on the app's own key, and the app host's second gateway is gone.** An app's harness runs (from its `server.ts`, an MCP tool, or a fitness replay of its fixtures) used to reach providers from inside the app host: the host decrypted provider keys, built and sent the request, learned parameter rejections, checked a budget and wrote its own ledger rows. That copy recorded no provider-reported cost, left a reply without usage unmetered, filed the spend under whatever caller name the app passed (so an app could spend under another app's name), checked the budget on one call path of three, read capability probe facts the api had already retired (json-strict below probe revision 1), and filed app spend as `chat` or `gateway`. A harness turn on a fleet agent was metered twice: once by the host, and again at the relay, where the agent's own calls landed as `unattended` because no turn was recorded. A `refId` that was not a uuid, which the SDK doc example passes, dropped the host's ledger row. Now every call the host's runner makes is a POST to `/api/llm/v1/chat/completions` on a per-app key named `app:<slug>`. The api mints the key when the host first asks (the new internal route `POST /api/internal/apps/<slug>/llm-key`), seals it in `app_llm_keys` (rotated by the secret rotation, listed in Admin → Secrets), and revokes it when the app is disabled or uninstalled; the host keeps it in memory and app code never sees it. The relay trusts the key only while that record holds its id, and `POST /api/keys` refuses names starting with `app:`. The host decides which app is calling, not the app: every boundary where it runs app code (`isolateApp`, an MCP tool handler, a replay) marks the app, and a model call outside one is refused. The relay books each call with ledger source `app` under the run's caller stamp, kept inside the app's namespace (`fitness:x` becomes `app:<slug>:fitness:x`, and `app:other:…` becomes `app:<slug>:app:other:…`). It records the provider's cost, estimates a reply without usage, and books the run's ref and ticket only when they are uuids, never at the cost of the row. It enforces the app's budget (`app:<slug>` in Admin → Settings → LLM budgets, summed over every stamp under it) on every call. A model that is a live fleet agent is driven for one turn through the persona door with the turn recorded as `app` spend, so the agent's own calls are its only meter. The relay runs no guard pass of its own for an app's key, because the runner's pass with the harness's own rule set is the one of record. Fitness replays of app harnesses now report the provider's own token counts instead of the chars/4 estimate. Deleted from the app host: the upstream builder and fetcher, the parameter learner (`harness/gateway-params.ts`), the budget check, the gateway stats ring, the ledger writer (`usage.ts`), `completeViaGateway`, `recordGatewayUsage`, `guardCompletion`, `meterPersonaTurn`, `personaProbeTurn` and the direct agent proxy (`proxyChat`). What stays in `llm-gateway.ts` is the model catalog and the routing read the runner resolves models and capability keys with. Verified: `bun run gate` exited 0. That covers check, svelte-check with 0 errors, the full ui suite (2310 tests), and `cargo test` plus clippy `-D warnings` on the eight touched api packages. There are new Rust tests for the key vocabulary, the stamp namespace, the budget family, the persona base, the key record and the stale-key sweep, plus a live-DB test (run against the worktree's Postgres) that an app row keeps a uuid ref, drops a non-uuid one without dropping the row, and that the app's budget sums its stamps and nothing beside them. New ui tests cover the transports against a stubbed relay (signed with the key of the app in scope, refused outside one, a 401 re-asks once, the relay's own sentence on a failure, real usage on a plain completion, the persona turn's hold and refs), the scope at each boundary, the key cache, the replay's stamp, and the probe-revision rule. Exercised on this branch's worktree stack with a mock provider registered as a gateway endpoint: a scratch app's harness run from its server landed one usage row, `app:gwprobe:triage`, source `app`, the run's uuid ref, 111/22 tokens not estimated, and the provider's $0.000321 cost. A non-uuid ref booked the row with no ref; a caller of `app:billing:x` booked `app:gwprobe:app:billing:x`; a streamed call on the app key relayed with `x-talaria-transport: gateway` and booked its row. A replay through `POST /api/app-host/gwprobe/harnesses/gwprobe:triage/cases/…` passed with 111/22 tokens and `estimated: false`, booked as `app:gwprobe:fitness:gwprobe:triage`. A budget of 500 tokens on `app:gwprobe` (665 spent across its stamps) refused the next run with the gateway's budget sentence and no provider call. A harness pinned to a fake fleet agent went through the persona door: the agent's own inner call on its `agent:` key was the turn's only row, booked under the agent with source `app` and the run's ref, and the host wrote none. A key named `app:gwprobe` that the record does not hold got 401, and `POST /api/keys` refused the name. Disabling the app revoked its key (the held copy got 401, and the internal route answered 404). Re-enabling it minted a new key, and the host's next run swapped its stale copy on the relay's 401 and succeeded. Uninstalling revoked the key too.
