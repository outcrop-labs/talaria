- **Changed:** A work session's files come from the API, opening one creates nothing, and the agent is told which file is open. New `GET /api/conversations/{id}/files` (same gate as the conversation, 404 otherwise) answers `{ kind, files }`: every Talaria document and every Google file a chip on the session's messages names, in order of first appearance with `lastTouchedAt` the newest message naming it, then the session's `pinned_files`, then a legacy work session's living document. Artifacts the caller cannot read (the artifact GET's own check) or that were deleted are left out, and the list stops at 100. The derivation is pure, in `talaria_chips::session_files`, beside a Rust port of `parseGoogleFileUrl` (Docs, Sheets, Slides, Drive `/file/d/` and `open?id=`). Google tools now leave a chip naming the file they worked on (`create_google_doc`, the Docs, Sheets and Slides reads and writes, `read_drive_file`; a source pill at the file's canonical URL), and `import_drive_file` leaves a document chip, so the files a session touched in Google are in its list too. `GET /api/conversations/{id}/doc` on a work session never creates: it answers a legacy session's existing document, else 404 "this session has no plan document"; `POST` there is a 409. A work turn no longer triggers the post-turn document rewrite (`plan_meta` is built for plans only). `/api/chat` takes an optional `focus: { kind: 'artifact' | 'google', id, title? }`, and every work turn carries one system line after the work-mode prompt naming the open file (title stripped of control characters and line breaks, capped at 300 UTF-16 units, quoted) or saying nothing is open and to create a file when asked. `WORK_MODE_PROMPT`'s first paragraph now describes the files pane, names `create_document` / `create_sheet` / `create_page` / `create_google_doc`, and says there is no separate plan document; the `hermes:work` harness renders the same focus line the product sends. A queued or auto-resumed work turn carries the same two lines the live one computed (`TurnMeta.work_prompts`); before, a chained work turn ran with the plan prompt, and with none once plans stopped being built for work. Plan sessions are unchanged.
