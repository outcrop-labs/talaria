- **Fixed: a design that a failed hire hands back into New agent no longer replaces what you are typing there, and describing or naming a new design no longer throws the returned one away.** A hire that fails before the agent exists hands its design back into New agent when New agent is empty. To the server, a New agent you have only typed into is empty: a description not yet sent, or a manual form with no name yet, is saved nowhere. So the returned design took the place of what you had typed on the modal's next read: the describe step jumped to the review step, or the form's fields were filled from the returned design. Now the modal keeps what you typed and says the design is back, with **Open it** and **Discard it**. If you carry on and describe the agent or name it, the returned design is set aside. It waits, as it already did behind any open design, and comes back when that one is hired or discarded. The server does this for a describe or a manual start over a returned design that nobody has edited or refined since (`set_aside` in `talaria-agent-design`). It is one Redis script, so the design is never in both places or in neither. Before, a manual start over it was refused as stale, and a describe replaced it. A refine of a returned design now ends its link to the failed hire, as a hand edit already did (#712). The hiring strip's **Retry** of that hire no longer spends the refined design on the old input. Two smaller fixes in the same flow:
  - **Discard design** with a returned design waiting no longer leaves an empty describe step while New agent holds the returned design. The next save used to write the typed form over it.
  - A **Create** clicked right after naming a manual form spends the design that the name's save created. It no longer leaves a copy of it in New agent.
