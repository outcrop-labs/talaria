- **Fixed:** A marketplace package could mount the host into its container. The run-flag allowlist admitted `-v`, `--volume`, `--mount` and `--add-host` by name alone, so a registry entry (or anyone holding `agents.manage`) could declare `-v /:/host` or mount the docker socket and run an image of its choosing as root — host root, every fleet key, the Postgres volume. The gate now checks values, not just names (`check_run_flag`, shared by the install parser and the spawn): a volume may only be a `talaria-mcp-*` named volume with an absolute destination, a publish may only bind `127.0.0.1`, `--mount` and `--add-host` are refused outright, and an admin's fill for a placeholder passes the same rule as the declaration. Every package container now runs as uid 65534 on a read-only root with one tmpfs at `/tmp` (HOME — npx and uv keep their caches there, so a respawn re-downloads; the named cache volumes are gone). oci-http containers get their own `talaria-mcp-<instance>` bridge network, which the api joins on demand when it runs in-image, instead of the api's `*_internal` network beside Postgres, Redis and Qdrant. Installing a package server is an admin's call (403 otherwise); URL-only servers keep `agents.manage`. Verified: `cargo test -p talaria-mcp` (the flag rule has its own test, value by value, including the docker-socket and `/` cases), `cargo test -p talaria-routes-fleet`, clippy `-D warnings` on both, `bun run check`.
