- **Fixed:** An agent could keep replacing the body of a Google Doc it created after its owner had edited it from their own account: the only probe before an immediate replace was Drive's `lastModifyingUser.me`, and the owner is the token holder, so Drive reported the edit as the agent's own. `agent_created_google_docs` now carries `last_agent_write_at`, stamped on every agent write (create, immediate replace or append, and an approved `doc_update`); a full-body replace also holds Drive's `modifiedTime` against that stamp and queues for approval — dropping the agent's standing on the doc — when the revision is later than the agent's own write, by more than a 5-second clock-skew allowance. Appends stay immediate; rows from before the column fall back to the `me` flag alone until the agent's next write stamps them. The decision is the pure `modified_after_agent(modified_time, last_agent_write_ms)` in `talaria-google-docs`, with an RFC 3339 parser beside it. Verified: `cargo test -p talaria-google-docs` (timestamp parsing incl. fractions, offsets, a leap day; a later/earlier/inside-skew revision; unknown on either side is not evidence); clippy `-D warnings` on `talaria-google-docs`, `talaria-google-pending`, `talaria-routes-integrations`; `cd ui && bun run migrations:check` replayed the appended migration against the worktree database and the snapshot matched; `bun run check`.
