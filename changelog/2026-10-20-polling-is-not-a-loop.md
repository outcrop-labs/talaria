- **Changed:** The doom-loop guard counted identical `(tool, arguments)` calls and stopped the turn at five, so an agent polling a build job every thirty seconds was cut off as if it were stuck. The guard now counts a call at its completion, keyed on the tool, its arguments and a hash of what the call produced: the same call with the same answer is the loop, the same call with a changing answer is polling and is never touched. The two thresholds are settings — `chat.loop_warn_at` and `chat.loop_stop_at` in `app_settings`, defaults 3 and 5, read once per turn — so an operator who knows a workflow repeats raises them without a rebuild; a stop set equal to the warn is the stop. Verified: `talaria-chat-persist` unit tests (`doom_loop`: thresholds, settings parsing and fallback, polling exempt, the moment the answer stops moving counts) and clippy clean with `-D warnings`; `bun run check`.
