- **Added:** An hourly MCP health check. Until now a server's status changed only when someone pressed Discover, so a revoked key, a dead host or an OAuth grant the provider stopped refreshing kept reading "ready" while every agent call failed. The `mcp-health` job (talaria-mcp `health.rs`; hourly, leased, first run two minutes after boot) re-asks every enabled external server, and `POST /api/mcp/health` (admin) runs the same pass on demand and returns `{checked, changed, down, recovered, notified, servers}`. Header-auth org servers get `initialize` + `tools/list` with the sealed org headers. This is the same conversation discovery has (it is now one shared function), and no audit row is written. When the tool *name* set changes, the cached catalog is replaced. Assignments whose tool subset names a tool the server no longer offers are recorded in the probe as `staleAssignments: [{agent, missing}]`. Org OAuth servers have their grant refreshed first. A grant that was connected and that the provider then refused to refresh gets the new `reconnect` probe state, and the card offers Reconnect; Discovery (Check now) reports it too, and says the token endpoint did not answer (rather than "not connected yet") when a refresh simply went unanswered. The refusal is recorded where it happens: `oauth_token_for` drops the grant and flags it in the new `mcp_oauth_reconnect` table in the same step (the token row itself is deleted on refusal), so a grant the gateway lost in the middle of an agent call still reads as Reconnect at the next pass, and a fresh sign-in clears the flag. The refresh is now single-flight per grant: it runs under the token row's lock and re-reads the row once it holds it, so the gateway, the health pass and a second pass refreshing one grant at once make one refresh instead of having the loser spend a rotated refresh token, get 400, and delete the winner's fresh grant. Per-user servers get an unauthenticated reachability probe, where a 401 counts as up. Then each person's stored OAuth grant is refreshed, so a refusal surfaces within the hour even when the person's agents are idle. `GET /api/me/mcp` then answers `needsReconnect` and Settings → Connections shows Reconnect; a disconnect clears the flag. Builtin, app and Workbench servers are not probed. An oci-http package server is asked at its container (resolved, and started if it stopped, the same step the gateway's first call takes); a stdio package has no address and is not asked, and its card shows no "Checked" line. Passes in one process run one at a time, each server's conversation gets at most 45 seconds whatever its own timeout, and each verdict is written as it arrives, so one hung server delays only its own line. When a server the last pass saw `ok` is found unreachable, erroring, refusing credentials or needing a reconnect, every admin gets one in-app notification (`mcp_server_down`, routed to the capability-gaps class). It fires once per transition: the pass compares against a new `mcp_servers.health_state` column (what the last *pass* saw), so a person's Check now cannot swallow the transition, and the read-and-write is one locked update, so two overlapping passes cannot both notify. A recovery writes the probe only. While any external server's last probe is not ok, admins see one "N MCP servers need attention" warning in `/api/alerts` that names the servers and links to `/mcp/external`. The agent's MCP tab answers `assignedToolsMissing` per server (computed live against the cached catalog; the tab's copy of the probe leaves out `staleAssignments`, which names every agent on the server) and shows a warning chip with a one-click **Drop missing tools**. That re-posts the assignment without those tools, or asks to remove the assignment when none would remain, because an empty subset grants nothing and a null one would grant every tool. Every server the pass asks shows "Checked <when>" from the probe with a **Check now** action, plus a line when assignments name tools the server no longer offers; the others keep the time on their failure detail. A per-user server the check cannot reach shows unreachable instead of "per-user accounts".
