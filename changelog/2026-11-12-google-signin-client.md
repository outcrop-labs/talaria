- **Google login can run on its own OAuth client, and each Google client records whether it is marked for AI agents.** Google now sorts OAuth clients into agentic and not ("Use this client for an AI-powered agent", under Google Auth Platform → Clients), and says a client used for both should be split: "Keep the existing client for your non-agent features." Admin → Google Workspace now has a second card, **Sign-in client (optional)**. Saved there, or set as `AUTH_GOOGLE_SIGNIN_CLIENT_ID` / `AUTH_GOOGLE_SIGNIN_CLIENT_SECRET`, it is the client Google login starts, exchanges and gates on. Left empty, login uses the existing client, now called the connections client, exactly as before. Every connect flow, every token refresh and the integration gate stay on the connections client, so moving login changes no stored connection. The Workspace domain restriction (`hd`) is always read from the connections client, so a sign-in client can never open login to every Google account: the consent URL carries the connections domain, and the exchange refuses an identity outside it. Login admits any Google account only when a connections client is configured with no domain, as before. Removing the connections client still stops login, sign-in client or not, unless `AUTH_GOOGLE_HD` or a connections record saved without its secret still names a domain; the panel's Remove confirmation says so, and a new warning names a sign-in client left with no domain to take. Each card also asks what Google Cloud shows for the agentic box (Ticked, Unticked, Not said). The answer is stored per client id in `google_client_evidence`, or pinned in env with `AUTH_GOOGLE_CLIENT_AGENTIC` / `AUTH_GOOGLE_SIGNIN_CLIENT_AGENTIC`. It refuses nothing: the panel warns when the sign-in client is declared agentic, and when login is on, has no sign-in client and the connections client is declared agentic. The redirect URIs are listed per client. New routes and parameters: `PUT` and `DELETE /api/admin/google-client?role=signin` (audited as `google.signin_client_config` and `google.signin_client_config_clear`) and `PUT /api/admin/google-client/agentic` (audited as `google.client_evidence`). `talaria setup` templates the sign-in pair commented out, and `talaria reset secrets` now clears both sealed client records. docs/GOOGLE-WORKSPACE.md "Operator setup" explains the roles and which shape to run.
