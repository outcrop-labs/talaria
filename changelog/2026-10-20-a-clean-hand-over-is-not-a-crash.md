- **Fixed:** The durable run plane counted every re-entry of a running row as a driver crash, so three rolling deploys (or three momentary Redis blips) killed a research expedition as "gave up", and a cross-instance stop was only honoured at the end of the in-flight step because the row-side heartbeat guard matched the wrong type. A clean stop now releases the row back to `queued`, a new `runs.crashes` column counts only claims that found the previous driver dead, and `max_attempts` bounds that; one unreachable-Redis renewal beat is tolerated before the drive stops; a refused heartbeat (cancelled, taken, gone) stops the drive within one beat; and a cancel is relayed through a short-lived Redis flag the driving instance polls every five seconds, so a stop pressed anywhere lands in seconds. Two `rag-reindex` / `rag-backfill` runs can no longer start together — a partial unique index `runs_one_live_per_kind` refuses the second insert, the start reads it as "already running", a backfill stands down under a live reindex, and each collection's `rag_points` delete and schema stamp are one transaction after the Qdrant drop. `start_scheduler` refuses to arm when a required job is missing (the docs now say nine), a research search call is bounded at nine minutes and re-entered from its checkpoint up to twice before it counts as a failed angle, the `research_runs` and `plan_drafts` rows are written before their run is enqueued (so the drive can no longer lose the caller's conversation and dials), the plan-draft save fails loudly on zero rows, and `store.answer` carries the question key in its UPDATE predicate.
