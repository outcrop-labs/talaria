- **An agent can open an existing document in your Work pane, and documents it creates now open there too.** Ask "open the launch plan here so we can iterate on it" and the agent calls the new `open_in_pane` toolkit tool (`POST /api/agent/open`). The tool takes a Talaria document, sheet, page or uploaded file, or a link to a Google Doc, Sheet, Slides deck or Drive file, and puts it in the pane beside a Work, Plan or Research session. A file closed earlier in the session comes back the same way. With no file named, the tool lists the session's files. The file opens with your access: one you can read but not edit opens **View only**. The Read/Edit switch, Edit on an empty file, the icon picker, the upload, Pull from Google and Delete are all hidden for a viewer, on the Files page too. A file you cannot read is refused, and nothing is linked. An agent that cannot read the file is told it opened and nothing else. Knowledge-base docs and run transcripts are refused with a sentence saying where they open. Your pane follows the agent only for turns it ran for you, never while you have unsaved edits in another document. A teammate sharing the session gets the new tab without their pane moving. Agent-created documents never opened before, because of two gaps. Hermes names toolkit tools `mcp__talaria__<tool>`, and it wraps each tool's answer in `{"result": …}`, so the tool-events door never recognised a writer. Both are now read through. The create route also links the new document itself, as the edit route already did, because the agent's plugin cuts a long answer to 4000 characters.
