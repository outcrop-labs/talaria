- **An agent can open an existing document in your Work pane, and documents it creates now open there too.** Ask "open the launch plan here so we can iterate on it" and the agent calls the new `open_in_pane` toolkit tool (`POST /api/agent/open`). The tool takes a Talaria document, sheet, page or uploaded file, or a link to a Google Doc, Sheet, Slides deck or Drive file, and puts it in the pane beside a Work, Plan or Research session. A file closed earlier in the session comes back the same way. With no file named, the tool lists the session's files. The file opens with your access: one you can read but not edit opens **View only**. The Read/Edit switch, Edit on an empty file, the icon picker, the upload, Pull from Google and Delete are all hidden for a viewer in the document's own view: the pane, and the document's editor on the Files page. The Files list's row menu and bulk Delete still offer Delete to everyone, and the server refuses a viewer's. A file you cannot read is refused, and nothing is linked. An agent that cannot read the file is told it opened and nothing else. Knowledge-base docs and run transcripts are refused with a sentence saying where they open. Your pane follows the agent only for turns it ran for you, never while you have unsaved edits in another document or in a plan's own document. A turn is for the person whose message it answers. A message with no author counts as the owner's, and a cron turn counts as the person who scheduled it. A teammate sharing the session gets the new tab without their pane moving. Agent-created documents never opened before, because of two gaps. Hermes names toolkit tools `mcp__talaria__<tool>`, and it wraps each tool's answer in `{"result": …}`, so the tool-events door never recognised a writer. Both are now read through. The create route also links the new document itself, as the edit route already did, because the agent's plugin cuts a long answer to 4000 characters. Both routes link it only on a reply the agent is streaming, so a document a cron run or a background job makes or edits no longer opens in the pane of whoever the agent last spoke to. Reading through the envelope also changes what other toolkit calls leave on a Hermes agent's reply, since none of their chips reached it before. A ticket the agent created or moved links on the reply. So do a channel it posted to, a research run it started and a knowledge doc it wrote, and a board-access request leaves its Approve card. A document a call only read never becomes a chip: a `get_document` answer and `search_knowledge` hits that point at documents open nothing, so reading a file does not open it. A listing links nothing per row: `list_tickets` and search hits land no chip for each ticket or page they return.
