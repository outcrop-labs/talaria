- **The api's integration tests build as one test binary instead of 36.** Every file in `api/tests/` was its own test crate, and each one statically linked the whole api. After any api change, `cargo test -p talaria-api` (which the local gate runs for `api/src` and `api/tests` diffs) relinked all 36 and wrote 6.9 GiB. The files are now modules of `api/tests/it/`, so that same build relinks one test binary and writes 0.8 GiB. Run one file's tests with a module filter: `cargo test -p talaria-api --test it runs_run::`. The live suite in `api-integration.yml` still runs module by module, so tests from different files never share the scratch database at once, same as when they were separate binaries.
  Verified: `cargo clippy -p talaria-api --tests -- -D warnings` clean; `cargo test -p talaria-api --test it` passes 89 with 81 ignored, three runs in a row; after touching `api/src/lib.rs`, `cargo test -p talaria-api --no-run` relinked 36 executables (6.9 GiB, 17s) on rc and 2 (0.8 GiB, 3s) on this branch.
