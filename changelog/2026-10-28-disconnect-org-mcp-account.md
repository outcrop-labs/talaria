- **Added: an admin can disconnect the org's OAuth account from an MCP server.** Until now only deleting the server dropped an org connection. The server card's menu now offers **Disconnect org account** to admins (`DELETE /api/mcp/servers/{id}/oauth`, refused server-side to everyone else, a member who holds `agents.manage` included). It drops the sealed org tokens, clears a pending reconnect flag, and is audited as `mcp.oauth_disconnect` with the admin as the actor. The change applies in place, like the connect it undoes: the gateway answers for the server in-house again, the server's carriers re-list it on the gateway's list-changed notice, and nothing restarts. Verified live on a worktree stack with the repo's OAuth 2.1 stub (`scripts/e2e/mcp-stubs.mjs`, DCR and PKCE) and an agent on the pinned `hermes-agent:v0.22.4`, under a scripted mock model: after the org connect, a turn's `shout` reached the stub. A member holding `agents.manage` and the MCP view saw no Disconnect entry in the menu, and the route answered them 403 and kept the token. The admin's click went through the confirm (Playwright screenshots) and answered 200; the token row was gone and the audit row named the admin. Bob's next keepalive got the notice, Hermes re-listed the server, and his next call answered "The workspace's OAuth Org Stub connection isn't set up yet" with nothing reaching the stub. His container's id and start time did not change. `bun run gate` was green; CI is the full compile and test line.
