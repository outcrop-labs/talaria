- **A price that was only guessed now says so, and an admin can override it. Catalog matches that would misprice are withheld.** These are follow-ups to the #682 review.
  - **Fuzzy matches:**
    - Every catalog price records the entry it came from, and whether the model's own id found it (exact) or a stripped tag, date or path segment did (fuzzy).
    - A manual rate now beats a fuzzy match, but not an exact one.
    - The new **Priced by a fuzzy match** list and the cost page's legend show "priced as … (fuzzy match)".
  - **Withheld matches:**
    - A dated snapshot the catalog lacks no longer borrows its alias's price when the catalog prices that alias's listed snapshots differently (`gpt-4o-2024-05-13` costs twice `gpt-4o`).
    - On OpenRouter, an `:online` or `:nitro` id with no catalog entry of its own stays unpriced, with the reason, instead of taking the base model's rate.
    - Another host's model matched only by its last path segment (`accounts/fireworks/models/gpt-oss-120b`) is no longer priced at OpenRouter's rate. It is offered as a suggestion the admin can accept.
  - **Path ids:** a dated path id now tries its own dated last segment before the undated one, so `…/deepseek-r1-0528` reaches `deepseek/deepseek-r1-0528`.
  - **"Included" labels:** the By agent list and a ticket's spend say "included" instead of a bare $0.
  - **Smaller fixes:**
    - The spend tile says how much of the month is estimated from published prices.
    - A manual $0 / $0 is refused in favour of "included".
    - Rows with no model id no longer offer fixes the api refuses.
    - Ticking a model "included" on the endpoint editor confirms before it replaces a manual rate.
    - Price changes are audited with the value they replaced, and retries are audited too.
    - The one-row read after a retry no longer scans the whole window.
