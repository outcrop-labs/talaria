- **Added: agents keep themselves on Hermes' stable releases — each instance checks `nousresearch/hermes-agent:stable` every six hours, tests a new release in a throwaway canary, and moves its agents onto it one at a time in a 02:00–05:00 maintenance window, rolling back by itself if anything fails. No Talaria release is needed for a Hermes release.** Until now every agent ran the Hermes pin compiled into the release (`v0.22.4`), so each Hermes release waited for a Talaria pull request, release and upgrade. Now the check is an anonymous manifest HEAD, which Docker Hub does not count against its pull limit. A new digest is downloaded in the background (through the agents' own download, after any other download finishes) and read with networking off for its own config schema version, the env names its Hermes strips, and its drain tools. Every agent always runs a resolved digest, never `stable`, and its config is stamped with its own image's schema version instead of the compiled one, so a newer Hermes never tries to migrate the read-only config. In the window (the workspace time zone; configurable), or on **Roll now**, the image boots first as a canary with a rendered config and no channels, users, credentials or model to call. Then agents restart onto it one at a time; an agent writing a reply, running a work session, with a conversation message in the last 10 minutes or a model call in the last 5 is passed over and tried again a minute later. Each is checked the same way: healthy, its API server answering the gateway, no config or migration error in its log, its drain tools in place. Any failure stops the rollout: that agent goes back to the last version that worked at once, the new one is marked bad and never tried again, any agent it already reached moves back, and every admin is notified. **Manage → Agent image** (admins) shows the version each agent runs, the channel, the last check and the rollout, with Check now, Roll now, Roll back and Pin. The previous version stays on the server for three days after the new one is good, then images the instance downloaded itself are removed. **To opt out:** Pin a version on the panel, or set `HERMES_IMAGE` in `fleet/.env` as before; a chassis image of your own also turns the channel off. A server that cannot reach Docker Hub keeps its agents where they are and shows the failed check. A server upgrading from an earlier release runs the compiled pin first, then moves to stable in its next window, so pre-pulling the pin before upgrading (`docker pull nousresearch/hermes-agent:v0.22.4@sha256:7a69201726bc64db2072a1371557137c23312d29705cda2b8ea2a0214a50a4cf`) still makes the upgrade quick.
