- **Workbenches set up each job's dev environment, and Talaria declares its own toolchain.** Agents run unprivileged in a stock image, so they were hand-installing rustup and mold into their homes and prefixing every command with PATH exports. The new `prepare_env(jobId)` workbench verb does it from what the repo declares. It installs toolchains through mise (the repo's `mise.toml` / `.tool-versions`, or versions detected from `rust-toolchain.toml`, `.nvmrc`, `package.json`, `go.mod`, `.python-version` and friends), installs the OS packages a repo lists in `.talaria/workbench.toml` via apt as root, and puts mise's shims on the agent's PATH. start_job's instructions and the workbench-driving skill point agents at it. Talaria now ships a root `mise.toml` (rust 1.97.1, bun 1.4.0, node 22, mold 2), held to CI's pins by a new invariant. `talaria setup` warns when `ld.mold` is missing on x86_64 Linux, where the api can't link without it, and the workbench image bakes in build-essential, mold, and mise.
  Verified: clippy `-D warnings` and tests on talaria-workbench-mcp (detection rules, workbench.toml validation, scan parsing); the pin invariant fails on a deliberate drift; ran prepare_env's scripts in the live dogfood agent container against test checkouts (Rust + bun + mold, Go + Python + apt), including the failure path (see PR).
