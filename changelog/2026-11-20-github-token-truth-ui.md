- **The GitHub permissions editor and the git host card now say what an agent's token actually carries, not only what the App's installation holds.** Before, every key in an agent's set showed as held whenever the installation had accepted it, and the host card's green "Installation accepted" chips listed workflows and actions. Neither surface read a minted token, so an agent could look authorized while every token it got lacked the key. In Fleet → agent → Workbench → GitHub permissions, each key now says one of four things. "On the agent's token (acme/widgets, 12 min ago)" means the last token minted for this set carries it. "Granted, not on a token yet" means the set changed since the last token. "Not on the token (acme/widgets, 2 min ago): …" gives the reason: the installation has not accepted it (with the installation's page on GitHub), GitHub refused it (in GitHub's words), GitHub omitted it, or no token was minted (in the door's words). While nothing has been minted, the record answers, labelled "The installation holds it; no token checked yet", and it is never green. Admins get a **Check token** button, with a repo picker when the agent has several repos. It asks for the token the agent's next push gets and says, in plain sentences, why any key is not on it. A failed check shows the server's sentence verbatim, never a blank. When a workspace secret answers git ahead of the App, the editor says "Git at GitHub answers from the workspace secret <name> for this agent; these permissions don't apply to it." On the host card (Admin → Git hosts → GitHub), "Installation accepted" now reads "Installation accepted (the most any token can carry)". A new "Agents' tokens" list shows each agent with its default chip or custom set, what its tokens can carry, and its last token. When the installation accepted keys that no agent's set names, the card says so: "Accepted by the installation, carried by no agent: actions, workflows. An admin grants them per agent (Fleet → agent → Workbench → GitHub permissions)." Nothing here grants or gates anything: grants stay admin-only and per agent per host. Every new field is optional, so against an api without them, both surfaces draw what they drew before (apart from the caption).
