- **Documents no longer show the "Agent refine" notice; version history is where an agent's changes are reviewed, and a stale editor can no longer wipe an agent's edit.** The banner above KB docs and files ("Agent refine tiffany-personal-tiffany updated this 11d ago · no text changes") is gone. It fired on an agent's own creation of a document, on revisions with no text changes, and on old revisions. Its component and its decision helpers are deleted; the one helper something else used (the Muse receipt's line summary) moved to `lib/change-summary`. The **Version history** rail (the ⋯ menu on a KB doc, a space or a file) now lists every revision, agents' included, with the agent's name, a time on every row (Latest included), a **Changes** diff against the version before it, the **Version** itself, and Restore. Files used to restore on a single click with no preview; they now get the same review-then-restore dialog as KB docs. Two jobs the notice did quietly stay. **Read panes still follow the server:** a document or page in read mode refreshes itself when a revision lands, with nothing on screen. **No silent overwrite:** an editor names the version its buffer started from (`baseUpdatedAt` on `PUT /api/kb/docs/{id}` and `PUT /api/artifacts/{id}`), and the route answers 409 with the current document when the body moved under it and the save would replace it. The editor retries without a word when only metadata moved (an icon, a re-file, a promote). When someone else's text is there, it shows one line at that save, never on open: "Not saved: this document changed while you were editing", with **Review in version history** and **Keep mine**. Leaving Edit with an unsaved, refused edit asks before discarding it. Saves from one editor now run one at a time, so two autosaves can no longer land out of order. Saves that name no base keep the old replace: agent tools, restores, and Keep mine.
