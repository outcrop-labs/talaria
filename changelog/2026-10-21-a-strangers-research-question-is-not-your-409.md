- **Fixed:** `POST /api/research`'s duplicate-question check ran over every queued or running run in the org and answered 409 with the other run's id — so a caller learned that someone else was researching the same question, and where. The check is now scoped to the runs the caller may read, through the same viewer rule the list route and `research_role` use (a person: their own, shared and org runs; an agent: its owner's, so a general agent sees org runs only). A stranger's in-flight question is neither detected nor disclosed. Verified: `cargo clippy -p talaria-research -p talaria-routes-workbench --tests -- -D warnings` clean; `bun run check`.
