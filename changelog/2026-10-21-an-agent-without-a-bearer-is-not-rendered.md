- **Fixed:** An agent whose `HERMES_KEY_<SLUG>` line was missing from, or empty in, the fleet `.env` was still rendered as a compose service: compose interpolates a missing variable to "", so the container came up with `API_SERVER_KEY` empty, which is an agent gateway with no key at all, and the render only logged "no HERMES_KEY_… in the fleet .env" as a warning. The render now mints the line where it is missing or empty, the same way it materializes each agent's `TALARIA_AGENT_KEY_<SLUG>` line (a line with a value is kept verbatim: a running container holds that key), and an agent it cannot mint a key for is left out of the compose file entirely, with a warning naming the agent, rather than rendered open. Verified: `cargo test -p talaria-fleet-render` (a missing line is appended, an empty one rewritten in place, a live one untouched, an unmintable slug named and never written empty), clippy `-D warnings` on `talaria-fleet-render`; `bun run check`.
