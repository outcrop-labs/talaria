- **Two people editing one agent's repositories at once no longer silently undo each other: the write is now a compare-and-set, and the one that arrives second is told what changed.** `PUT /api/workbench/repos/{agentId}` replaces an agent's whole grant set and the branch rules of each repo. Until now a second manager working from an older read put back whatever the first had just changed, and it also dropped a repo an approval had granted meanwhile. The PUT now takes `from`: what the editor read, as `{repos, rules}` (the GET's `granted` and `rules`). If the agent holds anything else when the write arrives, the answer is 409 with `current` (what is there now, in the same shape), and nothing is written: no grant, no rule, no audit row, no revoked token. Repos are compared as a set, each with its rules. A repo the read gives no rule for counts as being at the defaults. A rule compares the way the write stores it, so a prefix saved before the `/` trim never looks like a change. The grants and the rules of the repos still granted now land in one transaction under an advisory lock on the agent. Approving a repo request (`add_grant`) takes the same lock, so an editor's read either sees that grant or gets it back in a 409. A write with no `from` is not compared and works exactly as before, so `scripts/rewind-fixture.mjs` and any other old caller keep working. The GET reads `granted` from the same rows as `rules`, so a read always describes one state. The Repositories section of an agent's GitHub access (`AgentRepoGrants`) sends `from` with every add, remove and "Save branch rules". On a 409 it re-reads and shows a toast whose title says what moved, for example "These repositories changed since you read them: acme/docs was added, acme/app was removed and the branch rules of acme/site changed" (with the host name when grants span hosts). The title carries this because a toast clips its body to one line. The body is the permissions editor's "Showing what is set now. Make your change again if it still applies." Pending rule edits were made against the old read, so they are dropped with it, the way the permissions editor drops its stale edits. A single editor sees no change. docs/WORKBENCH.md describes the compare-and-set, and docs/api is regenerated (the PUT lists 409).
