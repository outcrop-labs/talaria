- **Fixed:** Fleet agents now run Hermes' own loop guard, reasoning effort, persona tiers and title switch, configured by the render, instead of Talaria's copies that had drifted from Hermes. Five changes. (1) Each `config.yaml` turns on `tool_loop_guardrails.hard_stop_enabled`. Hermes counts `api_server` as an attended platform, so its hard stops were off on every agent. The guard that talaria-chat-persist ran on the stream is deleted. It matched calls on a display preview and an always-empty result hash, so it stopped legitimate work: five `cargo test` reruns on the pinned arm, or a false "Repeating the same call" chip after three MCP calls on different tickets on the completions arm. The person's own stop and steer, and the work-session thrash brake, are unchanged. (2) A turn's effort pick now travels as `model_options.reasoning_effort` on both persona arms. Hermes' API server ignores a top-level `reasoning_effort`, so every pick and every configured default ran at Hermes' `medium`, and the session arm carried no effort at all. The render writes each model's configured, vouched effort as `agent.reasoning_overrides`. It marks a model with no vouched levels `model_overrides.<provider>.<id>.supports_reasoning: false`, keyed by the provider id the model's routed spec names (`custom` today), so Hermes sends no effort for it instead of filling in `medium`. This is a behaviour change for every fleet model that neither its provider's catalog (in practice OpenRouter-style catalogs that publish `reasoning.supported_efforts`) nor an admin vouches levels for: its cron, channel, harness and session turns stop carrying Hermes' `medium` and run at the provider's own default, the same as Talaria's own chat already did for it. An operator restores effort by declaring the model's levels on the endpoint modal (`model_efforts`): that alone brings back Hermes' `medium`, and a level configured on the agent is rendered for that model. If the render cannot read the catalog or the endpoint roster, it leaves the reasoning block out rather than marking every model unvouched. The persona transports (Rust and the TS twin) no longer send `temperature` or `response_format`, which Hermes never reads. A JSON request to a persona now comes back `contract_dropped`, so the runner relies on its prompt anchor, the way it does on a gateway that strips the parameter. (3) Persona tiers render as `platforms.api_server.extra.model_routes` (`<persona>-<tier>` → the tier's upstream id). Without the route, a tier turn on the completions arm ran the main model and was metered as the tier. (4) `auxiliary.title_generation.model_upgrade_enabled: false` drops Hermes' background title call. Hermes still keeps its free instant title, and nothing in Talaria read the model-written ones. Verified on a worktree stack running the pinned `nousresearch/hermes-agent:v0.22.4@sha256:7a6920…` image, with a recording mock upstream behind Talaria's gateway. Hermes' own loaders in the container read back `hard_stop_enabled=True`, `{effort: high}` for the main model and `low` for the tier, `None` and `supports_reasoning=False` for the unvouched model, and `model_upgrade_enabled=False`. `GET /v1/models` on the env-enabled API server listed `hxr-render-deep → hx-tier`. At the upstream: a direct call with no effort reached the main model at `high`; the tier alias reached `hx-tier` at `low`; `model_options` `medium` arrived as `medium`; a top-level `reasoning_effort`/`temperature`/`response_format` arrived as `high` with neither of the other two. The unvouched model got no `reasoning_effort`, and the same agent re-pointed at a vouched model with no configured level got Hermes' `medium`. Through `/api/chat`, an explicit `low` arrived as `low` on the completions arm and on a pinned session, a `deep` tier turn on the completions arm reached `hx-tier` at `low`, and its ledger row says `hx-tier`. A conversation that made the mock return the same tool call each time was halted by Hermes after five calls ("I stopped retrying because I kept running skills_list 5 times…"). The row landed complete, with no chip and no stopped stamp. Each chat turn made exactly one upstream call, so no title call. (5) A pinned (session-arm) conversation runs its agent's main model when a message picks a tier, because the session route carries no model and Hermes pins a session's model at its first turn. Those turns were booked and priced as the tier. They are now booked as the main model, and the tier's effort is not sent to the main model. Verified on the same stack: on a pinned conversation, a `deep` turn with `low` and a `deep` turn with no pick both reached `hx-main` at its rendered `high` and booked `llm_model = hx-main`; a re-render after these changes wrote byte-identical configs for both agents. `bun run check`, `bun run gate` (svelte-check, vitest 1881, clippy and cargo tests on the seven touched packages), the TS transport suite, and new unit tests for the render, the per-target effort lookup and the session booking. CI is the full compile and test line. Honouring a per-message tier on a pinned session is not done; it needs a design decision.
