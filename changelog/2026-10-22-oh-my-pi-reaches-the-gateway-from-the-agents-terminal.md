- **Fixed:** A Developer Agent's Oh My Pi can authenticate to the Talaria gateway from the agent's own terminal, and per-agent secrets stop colliding with Hermes's names. Before this change, three things stopped omp, and the doctor's `--version` probe could see none of them. Hermes strips `OPENAI_API_KEY`/`OPENAI_BASE_URL` from every command its terminal runs, and `terminal.env_passthrough` cannot put them back, so the workbench key never reached omp. The rendered `apiKey: "$OPENAI_API_KEY"` was sent as that literal text, because omp reads an `apiKey` as a bare env-var name. And Hermes's terminal runs commands from a login-shell snapshot whose PATH Debian's `/etc/profile` resets, so `bun` in `/opt/data/.local/bin` was not found and omp exited 127. Now the key rides `TALARIA_WORKBENCH_API_KEY` (no `OPENAI_*` in the sandbox env), and the render writes `models.yml` naming it, mounted where omp reads it. omp converts a `models.json` into `models.yml` only once, so later renders never reached it. The boot hook links `/usr/local/bin/bun`. `doctor` runs its probes in that same login shell, and after `--version` it makes one model call through omp with every name Hermes strips unset first, so an omp that starts but cannot authenticate reads as broken. It skips that call, and says so, when the agent's jobs run on a coding subscription, or when the steps before it have used most of the 300 s Hermes gives an MCP call. A render leaves an older `models.json` in place, because a container created before it still binds that file. Per-agent secrets: names Talaria stamps or owns (`TALARIA_*`, `LLM_*`, the omp/git/Playwright env) are refused, and so are Hermes runtime settings (`HERMES_*`, `TERMINAL_*`, `GATEWAY_*`, `API_SERVER_*`, `AUXILIARY_*`) the container's process settings (`PATH`, `HOME`, `LD_*`, `PYTHONPATH`, `NODE_OPTIONS`, `BASH_ENV`, `S6_*` …), and the 450 names Hermes v0.22.4 strips. That last set is a snapshot generated from the pinned image, with its refresh command in the file's header. A secret saved under such a name before this change still loads, and the Secrets tab now marks it with the reason. The render lists the remaining secret names in `terminal.env_passthrough`, so they reach `execute_code` as well as the terminal. Setting any per-agent secret also no longer fails with `invalid input syntax for type uuid`: the email in a TEXT column had been cast to uuid since the Rust port. The workbench-driving and subagent-driven-development skills point UI checks at `browser_exec` instead of `npx playwright`. On v0.22.4 that Browser Use CLI tool is the agent's only browser tool, because Hermes enables it by default in place of the `browser_*` tools. The subagent skill drops the `toolsets=` arguments `delegate_task` ignores and no longer claims subagents lack a file tool. The optional workbench image drops its Playwright layer, which the runtime `PLAYWRIGHT_BROWSERS_PATH` hid. Verified on the pinned `nousresearch/hermes-agent:v0.22.4@sha256:7a6920…` in this worktree's stack, with a real gateway endpoint, a Developer Agent rendered and run by Talaria, and commands run through Hermes's own `LocalEnvironment` (the terminal tool's backend) inside the container. **Before:** the container env held `OPENAI_API_KEY` (a `tlk_` key) but Hermes's terminal env did not. omp there exited 127 (`env: 'bun': No such file or directory`). With bun linked by hand it answered `401 invalid API key`, the same 401 it gave under `docker exec` with the key present (the `$` literal). The volume held the `models.yml` omp had migrated at its first run, with `apiKey: $OPENAI_API_KEY`. `doctor` said "runs — omp/18.8.5, auth through the Talaria gateway". **After:** Hermes's terminal env carries `TALARIA_WORKBENCH_API_KEY` and `FIGMA_TOKEN`, and no `OPENAI_*`. `bun` resolves at `/usr/local/bin/bun`. omp 18.12.6 replied `OK`, and the gateway wrote a `usage_events` row on `api:workbench-gateway`. `doctor` reports "reached the Talaria gateway" with reply `OK`. With the old `$OPENAI_API_KEY` line put back in the mounted `models.yml`, it reports "CANNOT REACH THE TALARIA GATEWAY: omp exited 1: 401 invalid API key". `PUT …/secrets` answered 200 for `FIGMA_TOKEN` and 400, with the reason, for each of `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `GITHUB_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TERMINAL_ENV`, `HERMES_HOME`, `TALARIA_WORKBENCH_API_KEY`, `LLM_API_KEY` and `PI_SMOL_MODEL`. The container's `config.yaml` carries `terminal.env_passthrough: [FIGMA_TOKEN]`. Hermes's `execute_code` env builder passes `FIGMA_TOKEN` with that list and drops it without one. The gateway logs "Single-profile install", so the value resolves from the process env. Hermes's own tool list for the agent, computed in the sandbox, offers `browser_exec` and no other browser tool, with the agent on a model that cannot see images. `browser_exec` opened a page served on localhost in the sandbox, read its heading, clicked its button, and `capture_screenshot()` saved a PNG. `doctor` on the gateway plan reached the gateway in 12 s. With the agent given a primary coding account (rows written straight to the database), `doctor` skipped the call and named the subscription, and no usage row was written. A render with an older `models.json` beside `models.yml` left the file there. A row stored before the rule (`TAVILY_API_KEY`) still went into `secrets.env`, stayed out of `env_passthrough`, and came back from the list with `refused`, and the Secrets tab showed the reason under it. `PUT` refused `PATH`, `HOME`, `LD_PRELOAD`, `PYTHONPATH`, `NODE_OPTIONS`, `BASH_ENV`, `S6_KEEP_ENV` and `AGENT_BROWSER_EXECUTABLE_PATH`, and accepted `LINEAR_API_KEY`.
