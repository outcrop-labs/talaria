- **Every LLM call an agent makes is now metered at the gateway relay, one `usage_events` row per upstream call, and attributed to the conversation, channel, run or ticket that drove it — the per-turn ledger rows, the Redis turn register and the relay's skip are gone.** Before, while any Talaria-driven turn was open the relay skipped every call on the agent's key and the flow wrote one row from Hermes' main-loop counters, so auxiliary calls (titles, compression, vision, web_extract, session_search), delegated subagents and any cron that fired mid-turn reached no ledger, and a budget could not see a turn until it ended. Now every agent's config.yaml carries a `providers.talaria` entry on the same gateway URL its specs use (`session_affinity_header: x-talaria-session`, `key_env: LLM_API_KEY`, `discover_models: false`; rendered only while the brain is the gateway), so Hermes stamps its conversation key on every call. The specs keep `provider: custom`, and inside a v0.22.4 container the runtime provider stays `custom` (direct-alias), so anything keyed by it is unchanged. On a turn Talaria drives, Hermes' key is its own `gwk_…` digest of the session's route, so two records join it to the flow: the chat transport records the conversation it drove (`usage_attributions`: the session id it created, or the completions arm's `X-Hermes-Session-Id`, with source, `ref_id`, `task_id`), and the agent's talaria-events plugin reports from inside the turn which conversation its key names (new `pre_llm_call` hook → new `POST /api/agents/affinity`, agent's own credential only → `usage_affinity_keys`). The relay copies the flow onto each row in the insert, and whichever record lands second backfills the rows already booked. A cron fire carries `cron_<job id>` and is booked `unattended` per job; a call with no key is `unattended` under the agent. Rows keep the key (`usage_events.affinity_key`). `gateway_unmetered_keys` now defaults to empty and fleet-brain no longer forces the personas' key onto it; a key an operator lists there is booked nowhere. The cost views' `generations` now count upstream calls rather than turns. Also fixed: LLM budgets never bound. `spend_since` sent its window as a `bigint` to `make_interval`, which takes only `int4`, so every read failed and `check_budget` failed open. Inside the container, `/opt/data/config.yaml` carries the entry. Hermes' own `get_custom_provider_session_affinity_header` returns `x-talaria-session` for the spec's base URL, and `resolve_runtime_provider` answers `custom`/`direct-alias`. Every turn was then booked with the right attribution. A completions chat turn gave two rows (main loop + title), both `chat` with the conversation as `ref_id`. A pinned session turn was attributed the same way. A delegation turn gave four rows: the subagent's call carried the parent's conversation id. A channel reply was booked `channel` with the channel id. A work session gave fifteen rows, each with the ticket as `task_id`, and the ticket's usage rollup priced them. A cron run-now landed as `unattended` under `cron_45fe2d12cf73`. An operator key's forged header was ignored (`gateway`, no key). `/api/cost` per-agent totals include the auxiliary and subagent rows.
