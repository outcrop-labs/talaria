- **Every LLM call an agent makes is now metered at the gateway relay, one `usage_events` row per upstream call, and attributed to the conversation, channel, run or ticket that drove it — the per-turn ledger rows, the Redis turn register and the relay's skip are gone.** Before, while any Talaria-driven turn was open the relay skipped every call on the agent's key and the flow wrote one row from Hermes' main-loop counters, so auxiliary calls (titles, compression, vision, web_extract, session_search), delegated subagents and any cron that fired mid-turn reached no ledger, and a budget could not see a turn until it ended. Now every agent's config.yaml carries a `providers.talaria` entry on the same gateway URL its specs use (`session_affinity_header: x-talaria-session`, `key_env: LLM_API_KEY`, `discover_models: false`; rendered only while the brain is the gateway), so Hermes stamps its conversation key on every call. The specs keep `provider: custom`, and inside a v0.22.4 container the runtime provider stays `custom` (direct-alias), so anything keyed by it is unchanged. On a turn Talaria drives, Hermes' key is its own `gwk_…` digest of the session's route, so two records join it to the flow: the chat transport records the conversation it drove (`usage_attributions`: the session id it created, or the completions arm's `X-Hermes-Session-Id`, with source, `ref_id`, `task_id`), and the agent's talaria-events plugin reports from inside the turn which conversation its key names (new `pre_llm_call` hook → new `POST /api/agents/affinity`, agent's own credential only → `usage_affinity_keys`). The plugin keeps reporting a pair at each turn until the door has answered 2xx, so a report lost to a timeout, an api restart or a full queue is sent again, and its backfill claims the calls booked before it. The relay copies the flow onto each row in the insert, and whichever record lands second backfills the rows already booked. A cron fire carries `cron_<job id>` and is booked `unattended` per job; a call with no key is `unattended` under the agent. Rows keep the key (`usage_events.affinity_key`). `gateway_unmetered_keys` now defaults to empty and fleet-brain no longer forces the personas' key onto it; a migration removes that one entry, which every earlier render wrote, from a stored list, so the fleet-wide key agents fall back to when their own keys cannot be minted is booked again. A key an operator lists there is booked nowhere. An agent rename now carries its attribution records with it. A fleet an operator pointed at a raw upstream (a non-gateway `LLM_BASE_URL`) never reaches the relay, so it now books no agent spend; before, each chat, channel and harness turn wrote one row from Hermes' main-loop counters. The cost views' `generations` now count upstream calls rather than turns. Also fixed: LLM budgets never bound. `spend_since` sent its window as a `bigint` to `make_interval`, which takes only `int4`, so every read failed and `check_budget` failed open. Every configured budget now binds, an operator key's included.
