- **Fixed: an agent design described in New agent now reaches the review step when the server finishes. Before, it said "Designing" until the page was reloaded.** There were two bugs. The design store started each new design's run on the plain object it had just built, not on the store's reactive copy. The modal and the roster's design row read the design straight away, so the run's answer, its error and its elapsed count were written where nothing could see them. The server answered in 20 to 30 seconds while the browser still showed "Designing" six minutes later on the owner's instance, and ten minutes later on another. The run now writes through the store, as a refine already did. Separately, the modal chose its step only once, when it opened, so a design that landed while it was open showed the describe form again rather than the review. It now moves to the review step when the design lands.

  Verified: in headless Chromium, against this branch's own stack (app :5304, the Rust api :5404) and a stand-in model that takes 20 or 60 seconds, the full New agent flow (describe, then Design agent) reached the review step with the drafted name at 20.7 s and 60.9 s. Closing the modal mid-design, then reopening it after the design landed, showed the review step; the roster row already read "Scout is designed and waiting for review". On the code before the fix, the same 20-second run still showed the "Designing" splash after 45 s. A new unit suite runs the design store under Svelte's client transform, which the existing suite did not use. Its four cases (ready, a derived reader moving to ready, the elapsed count and an error, each read while the run is out) fail on the old code and pass with the fix, and the existing store suite still passes. The transport is not the cause: through the real production server (`bun server-entry.ts`) proxying to a stand-in api that holds `POST /api/muse` like the Rust one, a 20-second and a 60-second answer both arrived whole, with status 200, at 20.0 s and 60.0 s.
